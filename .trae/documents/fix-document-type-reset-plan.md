# 修复文档分类被错误更改为"项目"的问题 - 实施计划

## 问题分析
当更改网页内容后，文档分类会被自动重置为"项目"类型，而不是保持用户之前设置的分类。

## 根本原因
问题出在 `useDocumentState.ts` 文件中的 frontmatter 解析逻辑，当解析 frontmatter 时，如果 `type` 字段不存在，就会默认设置为 'project'。

## 实施计划

### [x] 任务 1: 修改 useDocumentState.ts 中的文档类型设置逻辑
- **优先级**: P0
- **依赖**: 无
- **描述**:
  - 修改 `useDocumentState.ts` 文件中的文档类型设置逻辑
  - 当解析 frontmatter 时，如果 `type` 字段不存在，使用之前的文档类型而不是默认值
  - 确保只有在首次加载或明确设置时才使用默认值

- **成功标准**:
  - 文档类型在内容更新后保持不变
  - 只有在首次加载或明确设置时才使用默认值

- **测试要求**:
  - `programmatic` TR-1.1: 修改代码后，当内容更新时，文档类型保持不变
  - `human-judgement` TR-1.2: 手动测试，确认文档类型在编辑内容后不会被重置

- **注意事项**:
  - 确保修改不会影响其他功能
  - 保持代码的可读性和可维护性

### [x] 任务 2: 增强 updateFrontmatter 函数的健壮性
- **优先级**: P1
- **依赖**: 任务 1
- **描述**:
  - 增强 `useMarkdownInteraction.ts` 中的 `updateFrontmatter` 函数
  - 确保 `type` 字段在更新过程中得到保留
  - 增加字段验证，确保文档类型的有效性

- **成功标准**:
  - `updateFrontmatter` 函数在更新其他字段时不会影响 `type` 字段
  - 文档类型在批量更新操作中得到正确处理

- **测试要求**:
  - `programmatic` TR-2.1: 测试 `updateFrontmatter` 函数，确保 `type` 字段在更新其他字段时保持不变
  - `human-judgement` TR-2.2: 手动测试批量更新操作，确认文档类型不会被影响

- **注意事项**:
  - 确保修改不会破坏现有的 frontmatter 更新功能
  - 保持函数的向后兼容性

### [x] 任务 3: 验证修复效果

- **成功标准**:
  - 文档类型在内容更新后保持不变
  - 首次加载时正确使用默认值
  - 手动设置文档类型后正确保存

- **测试要求**:
