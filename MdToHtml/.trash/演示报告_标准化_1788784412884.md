## 项目简介与解决痛点 {layout="grid" columns=2 section-color="chart-2" title-spacing="8" show-divider="true"}

### 产品定位 {card-style="normal" card-color="chart-2"}

**MdToHtml Pro** 是一款 **Windows 本地离线的 Markdown 文档工程系统**：它将遵循自研 CHD 协议（Card-based Hierarchical Document）的 Markdown 文档，解析并渲染为**卡片式网格布局**的交互页面。

- 支持双栏实时编辑、AI 辅助生成、全文搜索
- 支持一键导出独立 HTML 与 Electron 桌面化分发
- 可服务于技术写作、学术笔记、知识管理、课程设计等场景

### 传统 Markdown 工具的四大痛点 {card-style="normal" card-color="chart-2"}

| 痛点 | 现象描述 | MdToHtml Pro 的解法 |
|------|---------|--------------------|
| 平面化结构 | Typora / VS Code 预览均为线性排版，长文缺乏层级与视觉区分 | 自研 **CHD 协议**，文档按 `章节 → 卡片` 两级组织，自动排版为卡片式网格 |
| 导出能力有限 | HTML 导出后丢失动态效果与交互，样式依赖外部 CSS | **HtmlBundler** 将 HTML/CSS 内联为独立单文件，保留网格布局与主题 |
| AI 集成空白 | 主流编辑器无内置 AI，或仅停留在"聊天问答" | **DeepSeek 原生集成**，将原始文稿智能改写为 CHD 结构化文档 |
| 离线优化不足 | 多数编辑器是"浏览器套壳"，冷启动慢、缓存弱 | **四层本地化架构**：SSR + LRU-500 缓存预热 + 惰性编译，首屏仅 280ms |

## 核心亮点详解 {layout="grid" columns=2 section-color="chart-3" title-spacing="8" show-divider="true"}

### CHD 协议：为什么做协议？ {card-style="highlight" card-color="chart-3" badge="亮点 1"}

现有静态生成器排版千篇一律；让 AI 直接输出 HTML 则样式失控、难以维护。CHD 的答案是：**把"二维布局问题"降维为一维的"内容类型标签"序列**——人与 AI 只负责写规范文本，排版交给确定性的规则引擎。

**协议结构（三层刚性约束）：**

```markdown
---
title: 我的技术周报
date: 2026-09-06
tags: [Next.js, 架构]
---
<!-- L0: YAML Frontmatter 文档元信息 -->

## 本周重点 {layout="grid"}
<!-- L1: Section 章节容器，自动排版为自适应列数网格 -->

### 完成：首页首屏优化 {card-style="highlight"}
<!-- L2: Card 卡片单元 -->

- 通过 SSR + 缓存预热将首屏从 1,850ms 降至 280ms
- 首包 JS 由 485KB 裁剪至 142KB

### 下周计划 {card-style="normal"}
...
```

### CHD 协议：特性与数据 {card-style="normal" card-color="chart-3"}

- **4 种卡片样式**：`normal`（标准）/ `highlight`（高亮强调）/ `quote`（引用语录）/ `code`（代码展示）
- **5 种卡片形状**：矩形 / 圆形 / 大圆角 / 浮动徽章 / 箭头
- **智能列数规则**：1~4 张卡片按数量等分布局，5 张及以上自动切换为 3 列网格
- **富文本能力**：内嵌 KaTeX 数学公式（`$ LaTeX $`）、GFM 表格、代码块高亮

**数据说话**：解析器为手写 **DFA 状态机**（非正则堆叠），O(n) 线性复杂度。52 行小文档 2.1ms → **0.3ms**，5,632 行超大型文档 89.0ms → **12.1ms**，整体提速 7.0×~7.4×。

### 双栏实时编辑 + 增量解析 {card-style="highlight" card-color="chart-3" badge="亮点 2"}

编辑器采用 **CodeMirror 6**（模块化、包体小、离线性能优），左侧源码、右侧 CHD 实时预览，支持双向同步滚动；编辑体验的核心是 **"分片缓存增量解析"**：只重算被改动的内容分片，而非整篇重解析。

| 编辑动作 | 无缓存全量解析 | 分片缓存增量解析 | 提升 |
|---------|--------------|----------------|------|
| 修改 1 行文字 | 42ms | **0.8ms** | **52.5×** |
| 插入 5 行内容 | 42ms | 1.5ms | 28.0× |
| 删除 1 个卡片 | 42ms | 2.1ms | 20.0× |

> 输入 → CHD 解析 → DOM 更新 → 预览渲染 **全链路响应 10.0ms → 1.8ms（↓82%）**，200~5,000 行文档编辑帧率稳定在 55~60fps。

### AI 原生集成：能力设计 {card-style="highlight" card-color="chart-3" badge="亮点 3"}

AI 不是外挂聊天框，而是深度嵌入内容生产的**"排版助手"**：粘贴一段自由文本或上传文档，系统自动理解并改写成符合 CHD 协议的卡片式 Markdown。

| 能力维度 | 具体设计 |
|---------|---------|
| 输入格式 | `.txt` / `.md` / `.docx`（docx 经 mammoth 提取正文） |
| 双 Prompt 模板 | 默认模板（通用文档）与学术模板（论文/文献导向） |
| 双模型 | Flash（快速）/ Pro（深度），可在设置面板切换 |
| 三级 Token 预算 | Minimal 200~400 / Medium 800~1,500 / Full 2,000~5,000，先估算再生成 |
| 输出方式 | DeepSeek API + **SSE 流式输出**，逐字渲染，首 Token 仅 ~1.2s |
| 容错机制 | 网络错误指数退避重试 3 次（1.2s → 2.4s → 4.8s），重试后成功率 99% |
| 结果管理 | 生成结果多版本临时文件管理，支持实时预览 / 下载 / 保存为正式文档 |

### 离线优先 + 文档全生命周期管理 {card-style="highlight" card-color="chart-3" badge="亮点 4"}

系统面向 **"数据不出本机"** 设计：无云服务、无后端依赖，本地文件系统 + SWR 本地缓存构成数据闭环。同时把文件管理做到"管家级"：

- **导入**：手动编写、文件拖拽上传、文件选择器多格式导入
- **组织**：文档列表 + 收藏 + 置顶 + 排序 + 容量可视化进度条
- **全文搜索**：Fuse.js 模糊搜索（~8KB），标题与正文均可命中
- **删除保护**：删除进回收站而非直接清除，支持恢复 / 清空
- **缓存加速**：LRU-500 缓存 + 启动时异步后台扫描预热

### HtmlBundler 一键导出 {card-style="highlight" card-color="chart-3" badge="亮点 6"}

渲染引擎负责"屏幕上看"，HtmlBundler 负责"带走用"。一键导出后得到 **CSS 已内联的独立静态 HTML 单文件**，不依赖 Node、不依赖外链样式，可双击打开、可 U 盘分发、可部署到任意静态托管。

| 文档规模 | 导出产物大小 | 导出耗时 | 瓶颈环节 |
|---------|------------|---------|---------|
| 小型（52 行） | 18KB | 35ms | HTML 模板构建 |
| 中型（423 行） | 57KB | **92ms** | CSS 提取 + 内联 |
| 大型（1,847 行） | 156KB | 210ms | 大量卡片 DOM 构建 |
| 超大型（5,632 行） | 420KB | 580ms | DOM + CSS + 资源内联 |

> 导出快的关键：**解析结果以 DOM 片段形式缓存复用**，导出阶段零重复解析——同规格下比 Typora + Pandoc（230ms）快约 2.5 倍。

### 无限级撤销 / 重做 + 自动保存 {card-style="highlight" card-color="chart-3" badge="亮点 7"}

编辑最怕"误操作无法挽回"和"断电内容丢失"。系统把操作历史做成**操作栈**（撤销快照式实现升级为命令式实现），配合定时自动保存与退出确认，构建三层保护：

- **无限级撤销/重做**：从单字符输入到 Block 级插入、500 行全选替换均可回溯
- **自动保存**：默认 3,000ms 防抖自动落盘，大型文档单次保存 62ms 且不阻塞 UI
- **会话恢复**：页面刷新/意外退出后可恢复最近编辑现场（配合临时文件体系）

|---------|---------|----------|
| 普通文字输入（30 字符） | <1ms | 3ms |
| Block 级操作（插入卡片） | 3ms | 28ms |
| 全选替换（500 行） | 18ms | 85ms |

### Electron 桌面便携化 {card-style="highlight" card-color="chart-3" badge="亮点 8"}

产品不只停留在浏览器，更交付为 **Windows 原生桌面软件**：构建时将 Next.js 生产服务器内嵌进 Electron 主进程，单进程即可运行，无需用户安装 Node.js 环境。

- **启动体验**：独立加载窗口 + 端口探测（`port+1` / `/status` 端点 + stdout 联动），先给用户可感知的启动反馈，再平滑切入主界面
- **打包形态**：`electron-builder` 产出 **Portable 免安装版 .exe**，双击即用
- **体积优势**：安装包 **18MB**，仅为 Typora（85MB）的 1/5、VS Code（180MB）的 1/10
- **安全与交付**：内置代码签名策略调整与安全性审计，适配企业/学校等受控环境分发
