## 1. 协议概述

CHD (Card-based Hierarchical Document) 是一套专为降低 AI 理解成本并提升人类写作结构化程度而设计的文档工程协议。

### 核心哲学 (Core Philosophy) [v1.6 Update]
- **最小闭环 (Minimum Viable Loop)**: 在初期阶段，为了保证系统的绝对稳定性和 AI 生成的确定性，我们严格限制布局和样式的自由度。
- **结构优先**: 在有限的自由下，最大化机器可理解性。
- **刚性层级**: 严格限制文档层级深度，禁止无限嵌套。
- **显式语义**: 通过格式显式声明内容类型，而非依赖 AI 猜测。
- **矩形主导**: 严禁生成异形卡片（如圆形、切角等）。即使渲染引擎支持，协议层面也暂时禁止 AI 使用。

## 2. 文档结构定义 (L0-L3)

CHD 协议定义了严格的三级刚性结构，禁止四级及更深层级。

### L0: 文档根节点 (Document)
文档必须以 YAML Frontmatter 开头，定义元数据。

```yaml
---
title: "文档主标题"          # 必须，对应 L1 概念
subtitle: "副标题"           # 可选
tags: ["标签1", "标签2"]     # 可选
version: "1.6"               # 协议版本
---
```

> **变更注意 (v1.3)**: `highlights` 字段已废弃。请在正文第一个 Section 使用 `stat` 卡片组来展示核心亮点。

### L1: 章节节点 (Section)
使用二级标题 (`##`) 定义章节。章节是文档的逻辑分割单位。

**约束规则：**
- 必须使用 `## ` 开头。
- 标题文本应简洁，作为该逻辑块的核心总结。
- 章节下不能直接包含正文文本，必须包含 L2 卡片。
- 渲染时，章节标题下方会自动生成分割线。

### L2: 卡片节点 (Card)
使用三级标题 (`###`) 定义卡片。卡片是内容的最小语义单元。

**约束规则：**
- 必须使用 `### ` 开头。
- 标题即卡片名称。
- 卡片包含具体的内容块（文本、代码、列表、图表）。
- **禁止**在卡片内使用四级标题 (`####`)。
- 一个卡片对应一个独立的语义点（Concept, Example, Metric 等）。

### 结构示意图
```
[Document L0]
  ├── [Metadata]
  ├── [Section L1] "## 研究背景"
  │     ├── [Card L2] "### 传统方法局限" (Text)
  │     └── [Card L2] "### 核心洞察" (Text)
  ├── [Section L1] "## 实验结果"
  │     ├── [Card L2] "### 准确率对比" (Chart/Metric)
  │     └── [Card L2] "### 性能提升" (Data)
```

## 3. 扩展语法 DSL

为了支持更丰富的布局和语义，CHD 支持在标题后使用扩展属性语法 `{key="value"}`。

### 3.1 布局控制 (Layout)

> **v1.6 协议锁定**: 虽然渲染引擎已支持 Timeline, Hub, Ring 等多种布局，但在当前协议版本中，**仅允许使用 Grid (并列) 布局**。其他布局关键字保留但暂时禁用。

**智能布局 (Smart Layout) [v1.4 新增]：**
CHD 渲染引擎内置了智能布局算法，当 Section (`##`) 未显式指定 `layout` 或 `columns` 时，会自动根据卡片数量计算最佳列数，实现“两头发力”的优化体验。

- **3 张卡片**：自动设置为 **3 列** (col-span=4)。
- **4 张卡片**：自动设置为 **4 列** (col-span=3)。
- **5 张卡片**：自动设置为 **3 列** (3+2 布局)，确保两行排列平衡。
- **6 张卡片**：自动设置为 **3 列** (3+3 布局)。

**显式布局覆盖：**
若需强制特定布局，可使用 `columns` 属性：

```markdown
## 方法设计 {columns=2}   <-- 强制两列
## 实验结果 {columns=3}   <-- 强制三列
```

### 3.2 卡片样式与形态 (Card Style & Shape)

> **v1.6 协议锁定**: 仅支持标准矩形卡片。多边形、悬浮、环形等样式暂时禁用。

应用于 Card (`###`)，定义卡片的视觉呈现语义和尺寸。

```markdown
### 核心性能 {card-style="highlight", col-span=2}
### 用户评价 {card-style="quote", row-span=2}
### 移动端预览 {card-style="normal", width="narrow"}
```

**支持的样式类型 (`card-style`)：**
为了降低 AI 决策维度，样式已精简为以下 4 种：
- `normal`: 默认文本卡片 (Standard)
- `highlight`: 高亮强调
- `quote`: 引用/评价
- `code`: 纯代码展示

**已废弃/禁用样式：**
- `stat`, `summary`, `orange`, `emphasis`: 已废弃。
- `floating`, `cut`, `arrow`: 虽然引擎支持，但协议**禁止** AI 生成。

**支持的尺寸属性：**
- `col-span`: 跨列数 (Grid 布局下生效，如 `col-span=2`)
- `row-span`: 跨行数 (Grid 布局下生效，如 `row-span=2`)
- `width`: 宽度提示 (`wide` | `narrow` | `full`)

### 3.3 文本排版 (Typography) [v1.2 新增]
应用于 Card (`###`)，控制卡片内文本的对齐与大小。

```markdown
### 居中标题 {title-align="center", content-align="left"}
### 大号文本 {title-size="text-3xl", content-size="text-lg"}
```

**支持的排版属性：**
- `title-align`: 标题对齐方式 (`left` | `center` | `right`)，默认为 `center`。
- `content-align`: 内容对齐方式 (`left` | `center` | `right`)，默认为 `left`。
- `title-size`: 标题字号 (基于 Tailwind 标尺，如 `text-xl`, `text-2xl`...)。
- `content-size`: 内容字号 (基于 Tailwind 标尺，如 `text-sm`, `text-base`...)。

### 3.4 数据表格 (Data Tables) [v1.3 新增]
为了确保数据展示的规范性和可读性，表格必须遵循以下规范：

1.  **语法规范**：必须使用标准 Markdown 表格语法。
2.  **卡片容器**：包含表格的卡片**禁止**使用 `card-style="stat"`。推荐使用 `normal` 或 `highlight`。
3.  **宽度适配**：
    - 列数 < 4：可使用 `col-span=1`。
    - 列数 ≥ 4：建议使用 `col-span=2` 或 `col-span=3` (Wide Card) 以避免横向滚动。
4.  **对齐方式**：表头与内容应根据数据类型（文本左对齐，数字右对齐）在 Markdown 源码中指定对齐。

```markdown
### 实验数据对比 {card-style="normal", col-span=2}
| 模型 | 准确率 | 召回率 | F1-Score |
| :--- | :---: | :---: | :------: |
| Baseline | 85.2% | 78.4% | 0.81 |
| Ours | **92.1%** | **88.6%** | **0.90** |
```

## 4. 禁止规则 (Strict Constraints)

为了保证 AI 解析的确定性，以下行为被严格禁止：

1.  **禁止四级标题**：`####` 及更深层级标题是非法的。如果需要更细粒度，请拆分为新的卡片或使用列表。
2.  **禁止孤儿文本**：`## Section` 下方必须紧跟 `### Card`，不允许在 `##` 和 `###` 之间直接书写正文。**所有内容必须包裹在 Card 内。**
3.  **禁止混合层级**：文档必须严格遵循 L0 -> L1 -> L2 的层级顺序。
4.  **禁止隐式结构**：不要使用粗体或字号大小来模拟标题，所有结构必须通过 `##` / `###` 显式声明。
5.  **禁止 HTML 实体**：Markdown 输入中禁止使用 `&gt;`、`&lt;`、`&amp;` 等 HTML 实体字符，必须使用原始符号 (`>`, `<`, `&`)。渲染端已内置自动解码，但输入端应保持纯净。
6.  **禁止紧凑加粗**：中文语境下，加粗文本 `**...**` 若与普通文本紧密相连（尤其是包含英文字符时），极易导致解析器边界识别错误。必须在加粗内容前后保留**一个空格**。
    - **错误**：`MPHm实现**堵塞度↓36%**与**QoS↑21%**的双重优化`
    - **正确**：`MPHm实现 **堵塞度↓36%** 与 **QoS↑21%** 的双重优化`
7.  **禁止冗余分隔符**：`## Section` 之间禁止手动添加 `---` 分隔线。渲染引擎会自动处理章节间距，手动添加分隔线会破坏语义树结构。
8.  **禁止复杂 Stat 卡片**：`card-style="stat"` 仅限于展示核心指标数字或短语，**严禁包含表格、代码块或长列表**。若需展示表格，必须使用 `normal` 或 `highlight` 样式。
9.  **禁止空属性值**：属性定义中禁止出现空值（如 `card-color=`），所有声明的属性必须有明确的 value。
10. **禁止非标样式值**：`card-style` 必须使用协议定义的值（如 `normal`, `highlight`, `quote`, `code`）。不支持的样式值将被忽略并回退到默认样式。

### 4.1 核心决议 (Core Resolutions)

**[2026-02-24] 二级标题样式一致性决议**
同一个二级标题 (`## Section`) 下的所有卡片，**必须**采用相同的颜色 (`section-color`) 和相同的卡片样式 (`card-style`)。
- **强制性**：无论后续协议如何扩展，这条决议永久生效。
- **目的**：极度降低 AI 的决策维度。AI 只需要为 Section 决策一次样式，Section 下的所有 Card 自动继承。
- **三级标题**：AI 不再需要考虑三级标题 (`### Card`) 的样式，三级标题只能控制自己文本内容的文本样式（如加粗、斜体）。

## 5. 最佳实践与标准结构 (Standard Structure)

基于成熟项目的验证，我们推荐以下文档结构作为标准模板（Template）：

### 5.1 标准开头 (Opening)
文档应以 **项目概述** 或 **核心摘要** 作为第一个 Section。
- **布局**：推荐使用单卡片全宽布局。
- **卡片样式**：使用 `highlight` 样式。
- **属性配置**：`{card-style="highlight", col-span=4, content-align="center", title-size="text-2xl"}`
- **目的**：作为文档的 Hero Banner，一句话阐述核心价值或定位。

### 5.2 核心内容区 (Body)
- **Grid 布局**：推荐使用 `columns=3` 或 `columns=4`。
- **卡片数量约束**：建议每个 Section 下的卡片数量控制在 **3-4 个**。
    - **禁止 5 个卡片**：在 4 列布局下，5 个卡片会导致第二行只有一个孤儿卡片，严重破坏版面平衡。
    - **解决方案**：若内容超过 4 点，请拆分为两个 Section（如 "优势 Part 1" & "优势 Part 2"）或精简为 4 点。
- **样式搭配**：使用 `normal` 作为基础，配合 1-2 个 `highlight` 卡片突出重点。
