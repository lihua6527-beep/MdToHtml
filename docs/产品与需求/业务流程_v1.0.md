## 1. 总体架构：双螺旋协同

DocMind 由两个核心子项目构成，互为支撑：

1.  **Markdown 转换项目 (DocMind Core)**：
    - 负责：前端交互、CHD 协议校验、AST 生成、最终渲染。
    - 角色：应用场景提供者、数据生产者。
2.  **数据蒸馏项目 (DocMind AI)**：
    - 负责：训练任务特化小模型（Structure Understanding Model）。
    - 角色：核心智能能力提供者。

## 2. 端到端业务流程

```mermaid
flowchart TD
    subgraph User Input [用户输入层]
        UI[前端表单/编辑器] -->|实时引导| Draft[草稿文本]
        Draft -->|提交| Validator[CHD 协议校验器]
    end

    subgraph AI Processing [智能处理层]
        Validator -->|合格| RuleEngine[规则引擎 (RegEx)]
        Validator -->|模糊/复杂| SmallModel[任务特化小模型 (<50MB)]
        
        RuleEngine --> AST[初步 AST]
        SmallModel -->|语义标注/布局建议| AST
    end

    subgraph Core Engine [核心引擎层]
        AST --> Transformer[AST 转换器]
        Transformer -->|注入元数据| FinalAST[标准化 AST]
        FinalAST --> Renderer[React/Next.js 渲染器]
    end

    subgraph Output [输出层]
        Renderer --> WebPage[精美网页]
        WebPage -->|用户反馈| DataLake[训练数据湖]
    end

    DataLake -.->|微调| SmallModel
```

### 流程详解

1.  **输入 (Input)**：
    - 用户在前端通过“表单模式”或“引导模式”输入内容。
    - 系统实时进行语法检查，确保输入基本符合 CHD 规范。

2.  **智能解析 (AI Processing)**：
    - **规则路径**：对于标准结构，直接使用正则解析，速度最快。
    - **模型路径**：对于自由文本粘贴或复杂语义判断（如“这段话是数据还是引用？”），调用端侧小模型进行推理，输出带有语义标签（Tags）和布局建议（Layout Hints）的 AST 节点。

3.  **AST 构建 (AST Construction)**：
    - 生成符合 CHD 定义的 JSON AST 树。
    - 节点包含：`type` (Section/Card), `content`, `metadata` (style, layout)。

4.  **渲染 (Rendering)**：
    - 渲染引擎遍历 AST。
    - `Section` 节点映射为布局容器（Grid/Flex）。
    - `Card` 节点根据 `style` 属性映射为具体的 React 组件（StatCard, CodeCard, TextCard）。

```json
{
  "type": "document",
  "metadata": {
    "title": "项目分析",
    "highlights": ["高性能", "低成本"]
  },
  "children": [
    {
      "type": "section",
      "title": "性能指标",
      "layout": "grid-3",
      "children": [
        {
          "type": "card",
          "title": "QPS",
          "style": "stat",
          "content": "1000+"
        }
      ]
    }
  ]
}
```

## 4. 部署架构

- **前端**：Next.js / React (承载编辑器、渲染引擎和小模型运行时)。
- **模型运行时**：ONNX Runtime Web / TensorFlow.js (在浏览器端运行蒸馏模型)。
- **后端**：静态托管 (Vercel/Netlify) 或轻量级 API (仅用于数据同步，不负责渲染)。

## 5. 异常处理机制

- **降级策略**：如果小模型加载失败或超时，自动回退到纯规则解析模式，保证基本可用性。
- **错误边界**：渲染引擎对每个 Card 进行错误边界包裹，单个卡片渲染失败不影响整页显示。
