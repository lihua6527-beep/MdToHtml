## 1. 核心设计理念

**“将约束内化为交互，而非事后惩罚。”**

传统的 Markdown 编辑器让用户面对空白屏幕写作，然后由渲染器处理格式错误。DocMind 颠覆这一流程，通过前端交互设计，引导用户在写作过程中自然产出符合 CHD 协议的规范文档。

---

## 2. 演进路线图

### 第一阶段：表单优先 (Form-First) —— 当前 MVP
在 AI 模型尚未成熟且用户习惯未建立时，采用“填表”模式强制规范输入。

- **交互逻辑**：
  - 用户不再面对一个大的 Markdown 编辑框。
  - 界面被拆分为明确的表单字段：
    - `文档标题` (Input)
    - `亮点 (Highlights)` (List Input x 3-5)
    - `章节 (Section)` (Dynamic List)
      - `章节标题` (Input)
      - `卡片 (Card)` (Dynamic List)
        - `卡片标题` (Input)
        - `内容` (Textarea/RichText)
- **价值**：
  - **数据纯净**：100% 保证产出符合 CHD 结构的 JSON/Markdown 数据。
  - **零门槛**：用户无需学习 Markdown 语法，只需填空。
  - **训练燃料**：用户填写的表单数据将直接成为训练“任务特化小模型”的黄金数据集。

### 第二阶段：自由模式 + 实时引导 (Free-Form + Guidance)
当用户熟悉结构后，提供更自由的编辑体验，但保留“护栏”。

- **实时语法提示**：
  - 类似拼写检查，实时检测 CHD 违规（如使用了 ####）。
  - 下划线提示：“建议将此处拆分为新的卡片”。
- **结构化辅助**：
  - 输入 `/` 呼出命令菜单，快速插入标准卡片模板（如“三栏对比”、“数据统计”）。
  - 侧边栏大纲导航，实时显示文档结构健康度。

### 第三阶段：智能修正 (AI-Correction)
AI 模型介入，处理非标准输入。

- **场景**：用户粘贴一段自由文本。
- **AI 行为**：
  - **自动分割**：识别文本中的逻辑断点，自动拆分为 Section 和 Card。
  - **语义归类**：自动判断内容是“引用”、“数据”还是“代码”，并应用对应的 Card Style。
  - **用户确认**：AI 仅做预填充，最终由用户在表单界面确认和微调。

## 3. 关键交互特性

### 1. 实时预览 (Live Preview)
- **机制**：屏幕右侧实时渲染最终网页效果。
- **目的**：提供正向反馈。当用户看到填写的 `highlights` 变成了精美的顶部横幅时，会更有动力完善内容。

### 2. 智能占位符与提示
- **Highlights**：“请用10字以内的短语概括核心价值”
- **Section**：“本章节的核心逻辑总结”
- **Card**：“一个独立的观点或数据点”

### 3. 加载与反馈
- **Loading 状态**：所有涉及 AI 处理或数据加载的操作，UI 必须显示 Loading 状态，杜绝白屏。
- **错误处理**：若解析失败，提供具体的修改建议（如“第3章节缺少卡片”），而非通用错误码。

---

## 4. 技术实现细节

- **状态管理**：使用 React/Vue 的状态管理维护一棵实时的 AST 树。
- **序列化**：前端负责将表单状态序列化为标准 CHD Markdown 文本，供后端或存储使用。
- **验证器**：前端内置轻量级验证逻辑（Linter），在提交前拦截结构性错误。
