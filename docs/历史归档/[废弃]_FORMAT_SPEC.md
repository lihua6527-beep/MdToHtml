# FORMAT_SPEC: 智能布局 Markdown 规范 (v3.0)

> **版本**: 3.0.0 (Hierarchy & Container Edition)
> **生效日期**: 2026-02-02
> **核心理念**: **"H2 综述 -> H3 容器 -> H4 卡片"** 分层架构，拒绝扁平化堆叠。

---

## 1. 文档结构规范 (Document Structure)

所有文档必须严格遵循以下**三层嵌套结构**，以确保清晰的视觉层级和内容分组。

### 1.1 分层定义 (The Hierarchy)

| 层级         | Markdown 语法 | 角色定义                   | 视觉呈现                           | 内容要求                                                                    |
| :----------- | :------------ | :------------------------- | :--------------------------------- | :-------------------------------------------------------------------------- |
| **L1** | `## Title`  | **模块 (Module)**    | 全宽标题 + 分割线                  | 必须紧接一段**综述段落 (Summary)**，定性描述该模块。                  |
| **L2** | `### Group` | **容器 (Container)** | **大型矩形分组框**           | 定义子领域（如"后端服务"）。**H3 本身不承载细节，只作为 H4 的容器。** |
| **L3** | `#### Item` | **卡片 (Card)**      | **独立交互卡片 (CyberCard)** | 承载具体信息点。支持横长、竖长等多种形态。                                  |

### 1.2 结构示例 (Example)

```markdown
# 系统架构设计说明书

## 1. 核心亮点 (Highlights)
本系统采用先进的前后端分离架构，具备高并发、高可用特性。（<-- H2 综述必不可少）

### 性能优势 (H3 容器：横向排列)
#### 秒级响应
基于 Next.js SSR，首屏加载 < 1s。
#### 高并发
支持 10k+ QPS。

---

## 2. 详细设计 (Detailed Design)
详细设计涵盖前端交互与后端微服务两个维度。（<-- H2 综述）

### 前端交互层 (H3 容器：纵向堆叠)
#### 动态路由 (H4 卡片)
...
#### 状态管理 (H4 卡片)
...

### 后端服务层 (H3 容器)
#### 用户鉴权 (H4 卡片)
...
```

---

## 2. 智能布局与组件映射 (Smart Layout & Components)

### 2.1 布局映射规则 (Mapping Rules)

1. **H2 (Level 1)**: 触发模块分割，渲染大标题和综述段落。
2. **H3 (Level 2)**: 触发 **Layout Group (分组容器)**。
   * **Horizontal Group**: 第一组 H3（通常是 Highlights）。
   * **Vertical Group**: 后续所有 H3 默认为纵向堆叠容器。
3. **H4 (Level 3)**: 触发 **CyberCard (实体卡片)**，渲染在所属 H3 容器内部。

### 2.2 降级策略 (Graceful Degradation)

若文档结构不完整（如缺失 H4），系统将执行自动降级：

* **Rule**: 如果 H3 下没有 H4 子标题，则 **H3 直接退化为 Card**。
* **Result**: 视觉上保持矩形卡片样式，但失去外层容器包裹，直接罗列在 H2 下。

---

## 3. 多样化卡片形态 (Card Shapes)

为丰富视觉体验，支持多种比例的卡片形态。**请在 H4 标题中添加后缀标识**（可选）：

| 形态               | 标识后缀   | 尺寸 (Tailwind)               | 适用场景                                       |
| :----------------- | :--------- | :---------------------------- | :--------------------------------------------- |
| **Standard** | (无)       | `w-full` / `h-auto`       | 通用信息，自适应内容。                         |
| **Wide**     | `(横向)` | `col-span-2`                | 宽屏图表、代码块、时间轴。                     |
| **Tall**     | `(竖向)` | **`w-64` / `h-96`** | **手机界面截图、移动端预览、人物画像**。 |

> **示例**: `#### 移动端首页 (竖向)` -> 渲染为瘦长的手机状卡片。

---

## 4. 渲染约束 (Rendering Constraints)

### 4.1 AI 生成约束

1. **H2 必带综述**: 严禁 H2 标题后直接接 H3，必须有一段铺垫文字。
2. **H3 必带 H4**: 尽量避免 H3 "光杆司令"，应拆分为多个 H4 卡片以利用容器布局。
3. **字数限制**: 单个 H4 卡片内容建议不超过 **150 字**，过长请拆分。

### 4.2 本地渲染约束

1. **矩形化**: 所有容器和卡片必须是规整的矩形（Rounded Rect），拒绝不规则形状。
2. **边界处理**: 容器应具备 `overflow-hidden` 或自动换行能力，防止内容溢出。
