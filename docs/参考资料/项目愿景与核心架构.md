# 项目愿景与核心架构 (Project Vision & Architecture)

## 1. 核心愿景：从博客工具到设计引擎

> **你的系统本质上是在回答一个问题： 当AI能生成无限内容时，如何确保输出的品质与一致性？**
>
> 答案是： **协议化输入、自动化评分、可视化调优、多态化输出**。
>
> 这不仅是工具创新，更是 **内容生产流程的范式转移**。

项目的核心诉求从最初的“搭建一个个人博客”演进为“构建一个规范化的 Markdown 多样化转换引擎”。
- **原始痛点**：传统博客工具千篇一律，手动排版耗时且难以维护。
- **终极形态**：一个“设计编译器”。输入是极简、强约束的 Markdown (CHD 协议)，输出是多样化、高品质的网页、幻灯片或 PDF。
- **价值主张**：
  - **智能化输入**：利用 AI 将模糊意图转化为符合协议的精确代码。
  - **确定性内核**：利用规则引擎保证渲染的绝对稳定与高性能。
  - **产品化输出**：同一份内容，一键生成博客、PPT 或 PDF。

## 2. 三大核心支柱
项目的技术核心由三个不可分割的支柱构成：

### 支柱一：范式固化 (Paradigm Solidification)
- **成果**：确定了 `CHD协议 (Card-based Hierarchical Document)` + `纯规则渲染内核` 的黄金组合。
- **意义**：将所有不确定性（AI 幻觉、设计随意性）前压至输入端。引擎只负责执行确定的渲染逻辑，确保稳定性。

### 支柱二：交互革命 (Interaction Revolution)
- **成果**：定义了 `可视化引导式调整` 界面。
- **意义**：用户无需编写代码，只需在“预览页”进行点击、拖拽、切换策略。系统提供有限但优质的选项（如切换卡片风格、布局模式），让用户聚焦于“决策”而非“制作”。

### 支柱三：智能闭环 (Intelligence Loop)
- **成果**：规划了 `RAG测试 -> 协议优化 -> 模型蒸馏` 的进化飞轮。
- **意义**：
  - **协议优化**：利用 RAG 检索知识库，测试不同模型对协议的理解，反向优化 `FORMAT_SPEC.md`。
  - **模型进化**：收集“满分输入-满意输出”数据对，训练专属小模型，使其比通用大模型更懂项目协议。

## 3. 架构哲学：降维与解耦
- **降维**：放弃让 AI 直接生成复杂的二维网页布局。将布局问题降维为一维的“内容类型标签序列”（如 `[引言, 代码卡片, 总结]`)。
- **解耦**：AI 仅作为“离线预处理助手”，负责生产符合规范的 Markdown。运行时环境完全由 Python/JS 规则引擎接管，杜绝 AI 幻觉影响最终交付。
