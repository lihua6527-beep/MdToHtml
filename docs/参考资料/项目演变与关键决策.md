# 项目演变与关键决策 (Project History & Key Decisions)

## 1. 演变四幕剧 (The Four Acts)
本项目从一个简单的个人需求，演进为具备深度的工程系统，经历了四个关键阶段。

### 第一幕：痛点与定义 (Origin)
- **背景**：需要一个低成本、零运维的个人技术博客。
- **问题**：现有的静态生成器（Hexo/Hugo）排版千篇一律，无法满足对“内容多样性呈现”的追求。
- **目标**：构建一个能自动将 Markdown 转化为高品质、多风格网页的工具。

### 第二幕：AI 陷阱 (The AI Trap)
- **尝试**：最初试图构建全流程 AI 系统，让大模型直接读取内容并生成 HTML/CSS 布局。
- **失败**：发现 AI 输出极不稳定，样式难以统一，且调试成本极高（“黑箱”问题）。
- **反思**：不能将系统的核心建立在不确定的概率模型上。

### 第三幕：降维与解耦 (Decoupling)
- **关键决策**：
  1.  **降维**：将二维布局问题简化为一维的“内容类型标签”序列。
  2.  **解耦**：将 AI 移出运行时。AI 仅负责在离线阶段生成符合规范的 Markdown，核心渲染完全由确定性的规则引擎接管。
- **结果**：系统内核变得 100% 稳定、可调试、高性能。

### 第四幕：通用引擎 (Abstraction)
- **升维**：项目超越了“博客”的范畴，成为一个通用的“结构化内容交付引擎”。
- **扩展**：新增了 PPT/PDF 导出能力，支持从技术文档到演示文稿的无缝转换。

## 2. 关键架构决策
| 决策点 | 放弃方案 | 采纳方案 | 理由 |
| :--- | :--- | :--- | :--- |
| **核心驱动** | 端到端 AI 生成 | CHD 协议 + 规则引擎 | 保证稳定性与可控性，消除 AI 幻觉。 |
| **输入格式** | 自然语言 / 随意 MD | 强约束 CHD Markdown | 建立人机协作的唯一标准语言，降低解析复杂度。 |
| **交互模式** | 聊天式修改 | 可视化引导式调整 | 赋予用户直接控制权，聚焦于“选择”而非“描述”。 |
| **输出形态** | 单一网页 | 网页 / PPT / PDF | 复用渲染资产，最大化内容的交付价值。 |

## 3. 面试/答辩叙事策略
- **核心逻辑**：痛点 -> AI 尝试失败 -> 架构重构（解耦/降维）-> 最终工程化方案。
- **重点强调**：
  - **工程思维**：展示如何通过“协议”来管理不确定性。
  - **系统闭环**：不仅有工具，还有数据反馈和模型进化的闭环设计。
  - **实际价值**：解决了内容创作者“排版难”的真实问题，且具备极高的扩展性。
