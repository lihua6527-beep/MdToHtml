# 静态网页资产接入与首页整合方案
更新时间：2026-02-27  
适用范围：`个人博客项目/前端`（Next.js Static Export / `output: "export"`）

## 1. 背景与任务重述
现阶段个人博客的内容生产方式发生变化：后续将由工具把「标准化 Markdown」批量转换为「静态网页（HTML/CSS/JS）」。

本项目不再负责“网页怎么生成”，只需要：
1. 做一个扩展性良好的首页（可持续扩展多个内容区块/集合）。
2. 支持从固定文件夹读取“项目/论文”的静态网页资产（至少包含：列表展示 + 访问能力）。
3. 将这些资产整合到首页与集合页（Projects/Papers）中。

## 3. 现状与目标的差距（Gap）
### 3.1 当前系统的“内容来源”不是“固定资产文件夹”
- Projects 依赖 Markdown + frontmatter（`src/content/projects`）。
- Papers 依赖 TS 硬编码数组（`src/data/papers.ts`），并且论文列表页还包含“为演示虚拟列表而扩增 1000 条”的逻辑（见 [papers/page.tsx](file:///c:/Users/86171/Desktop/个人博客项目/前端/src/app/papers/page.tsx#L51-L61)），不适合真实资产管理。

### 3.2 当前系统无法“自动接入批量生成的静态 HTML”
你未来交付的是一批 HTML 页面，但当前：
- 没有约定“静态网页资产固定目录结构”
- 没有约定“每个页面的元信息（标题/日期/标签/摘要/封面等）从哪里来”
- 首页与列表页的聚合逻辑是“读取 Markdown 或写死数组”，不是“扫描资产文件夹”

### 3.3 路由层面的潜在冲突
现有路由：
- `/projects/[id]`、`/papers/[id]` 是 Next 页面

未来如果直接放入静态 HTML 并希望也走 `/projects/<slug>` 这种“干净 URL”，需要决定：
- 是“直接访问静态文件路径”（如 `/static_pages/projects/<slug>.html`）
- 还是“保留 `/projects/<slug>`，由 Next 页面包一层显示静态 HTML”

## 4. 目标系统的定义（你现在真正需要的能力）
将内容体系从“源码内容（md/ts）驱动”切换到“资产目录（html+meta）驱动”。

核心能力拆解：
1. 固定资产目录：一个约定好的文件夹，批量丢入 HTML 即可被系统识别。
2. 元数据驱动：列表展示、首页聚合、排序筛选都基于元数据，而非解析 HTML。
3. 访问策略明确：用户点击条目后，能稳定打开对应静态页面（本地导出+Nginx 均可用）。
4. 可扩展集合：除 Projects/Papers 外，未来可以新增 Notes/Talks/Reports 等集合，不需要重写首页结构。

## 5. 推荐的资产目录规范（Fixed Folder Contract）
为兼容 Windows、Nginx、静态导出与批量生成工具，建议使用英文目录名。

### 5.1 目录位置（推荐）
放在 Next 会被原样拷贝到 `out/` 的位置最省事：
- 推荐路径：`前端/public/static_pages/`

原因：
- `public/` 会进入静态导出产物
- 资产可以完全脱离 Next 的编译链路，降低耦合

### 5.2 目录结构（推荐 v1）
```text
前端/public/static_pages/
  projects/
    <slug>.html
    <slug>.meta.json
  papers/
    <slug>.html
    <slug>.meta.json
  _shared/
    covers/
      <any>.png|jpg|webp
```

说明：
- `<slug>`：建议只用 `[a-z0-9-]`，避免中文路径的编码/解码风险。
- `.meta.json`：列表/首页需要的元信息统一从这里读取。
- HTML 文件名与 meta 文件名一一对应，便于工具批量生成。

### 5.3 元数据格式（`.meta.json`）
建议统一字段（可选字段允许缺省）：
```json
{
  "id": "distributed-iot-monitor",
  "type": "project",
  "title": "分布式 IoT 监控平台",
  "summary": "一句话概括，用于卡片列表与首页摘要。",
  "date": "2026-02-01",
  "tags": ["iot", "mqtt", "distributed"],
  "cover": "/static_pages/_shared/covers/distributed-iot-monitor.png",
  "source": {
    "generator": "markdown-to-static-tool",
    "version": "1.2.0"
  }
}
```

约束建议：
- `type`：`project | paper`（后续可扩展）
- `date`：统一用 `YYYY-MM-DD`，方便排序与过滤
- `cover`：用站点绝对路径（以 `/` 开头），静态服务器可直接访问

## 6. 访问与展示策略（Static Export 友好）
这里给出两种可行策略，推荐使用 B。

### 6.1 策略 A：直接访问静态文件（最简单，URL 不够干净）
- 列表页的跳转链接直接指向：
  - `/static_pages/projects/<slug>.html`
  - `/static_pages/papers/<slug>.html`
- 优点：实现最简单，纯静态文件访问稳定
- 缺点：URL 带 `.html`；不经过 Next 路由层，难以复用站点导航/主题/TOC 等 UI

### 6.2 策略 B：Next 详情页“包一层壳”，内部展示静态 HTML（推荐）
目标：
- 用户访问 `/projects/<slug>` 或 `/papers/<slug>`
- 页面框架（Navbar/Theme/布局）仍由 Next 控制
- 正文内容来自 `public/static_pages/...` 的 HTML 文件

推荐展示方式：
- 使用 `<iframe>` 内嵌静态 HTML（避免把 HTML 当字符串注入造成 XSS/样式污染）

优点：
- URL 干净、站点体验一致
- HTML 的脚本/CSS 隔离更好（不污染 Next 页面）

缺点：
- 需要对 iframe 的高度、自适应与锚点体验做少量适配

## 7. 首页扩展性设计（建议的“数据驱动”模型）
首页不再拼“projects + papers 两份数据”，而是拼“多个集合的条目”。

建议定义统一条目模型（概念层）：
```text
ContentItem:
  id / type / title / summary / date / tags / cover / href
```

首页的可扩展区块（概念层）：
```text
HomeSection:
  key / title / subtitle / query(过滤规则) / layout(网格策略)
```

这样未来新增集合：
- 只需要新增一个 `type` 与对应的资产目录
- 首页新增一个 section 配置即可，无需修改渲染逻辑

## 8. 实施步骤（原子化拆分）
以下步骤以“最小代价接入大量静态 HTML”为第一优先级，并兼容后续扩展。

### 8.1 约定与准备（不改动 UI）
1. 确定固定资产目录：`前端/public/static_pages/{projects,papers}`
2. 确定元数据文件规范：`<slug>.meta.json`（字段与约束如 5.3）
3. 约定 slug 规则：默认只允许 `a-z0-9-`；中文标题放在 `title`
4. 明确访问策略：优先采用“策略 B（Next 包壳 + iframe）”

### 8.2 资产扫描与索引（构建期执行）
5. 新增一个“资产读取”模块：在构建期用 Node `fs` 扫描 `public/static_pages/**.meta.json`
6. 输出统一的条目列表（内存中即可，或构建期生成 JSON 数据文件）
7. 补齐必要字段：`href` 按策略 B 生成为 `/projects/<slug>` 或 `/papers/<slug>`
8. 排序策略：默认按 `date` 倒序；无 date 的条目放末尾或使用文件时间兜底

### 8.3 改造列表页（Projects/Papers）
9. Projects 列表改为“读资产索引”而非读 Markdown
10. Papers 列表改为“读资产索引”而非写死数组
11. 删除/禁用论文列表页的“扩增 1000 条演示逻辑”，改为真实数据分页/虚拟列表（按真实数量）

### 8.4 改造详情页（访问静态 HTML）
12. `/projects/[id]` 改为：读取对应 meta，渲染统一头部信息 + iframe 正文
13. `/papers/[id]` 改为：同上
14. `generateStaticParams` 改为：从资产索引生成（避免漏导出）

### 8.5 改造首页（整合所有静态资产）
15. 首页统一数据源切换为“资产索引”
16. 首页区块支持按 type/tags/date 过滤：如“最新动态”“精选项目”“论文笔记”
17. 首页卡片跳转统一使用 `href`

### 8.6 构建与部署链路校验
18. 确保 `next build`/静态导出后：`out/static_pages/**` 存在且可访问
19. Nginx/静态服务器配置确保能访问 `.html` 静态文件
20. 回归测试：随机抽查 20 个条目链接，确保 404 为 0

## 9. 验收标准（Definition of Done）
- 批量放入 `public/static_pages/projects/*.html + *.meta.json` 后：
  - `/projects` 能自动展示所有条目（标题/日期/标签/摘要）
  - 点击任意条目能打开对应静态 HTML（不依赖手写路由）
- 批量放入 `public/static_pages/papers/*.html + *.meta.json` 后：
  - `/papers` 同样可用
- 首页能展示聚合内容（至少“最新动态”从全部集合中取 Top N）
- 全站静态导出后，在 Nginx 纯静态部署下可访问（无 Node 服务依赖）

## 10. 风险与边界
- HTML 脚本与样式隔离：推荐 iframe，避免注入到 Next DOM
- 中文 slug 风险：强烈建议 slug 只用英文与短横线；中文只用于 `title`
- 元数据缺失：需要明确兜底策略（至少 title/date/href 可用）
- 静态页面相对路径：生成工具应尽量使用绝对资源路径或与站点目录对齐，避免资源 404
