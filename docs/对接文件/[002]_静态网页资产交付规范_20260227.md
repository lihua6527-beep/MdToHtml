# 静态网页资产交付规范（Interface Standard）

> **给上游生成工具的说明书**：  
> 本文档定义了“静态网页生成工具”向“个人博客系统”提交内容时的标准格式与数据要求。为了让生成的网页能被博客首页自动收录、分类展示并正确访问，请严格遵循以下交付规范。

## 1. 核心原则
- **复用原始 Markdown**：博客系统利用已有的 Markdown Frontmatter（文件头信息）作为元数据来源，无需额外生成 JSON 文件。
- **成对交付**：每一个网页资产必须由 `HTML 文件` + `原始 Markdown 文件` 组成一对原子，缺一不可。
- **纯静态特性**：交付的 HTML 必须是纯静态的（无服务端渲染依赖），资源路径（CSS/JS/Image）应为相对路径或公共 CDN 路径。

## 2. 交付目录结构
请将生成的资产按以下结构整理，推荐直接输出到博客项目的 `前端/public/static_pages/` 目录下。

```bash
前端/public/static_pages/
├── projects/                  # 项目类网页
│   ├── my-awesome-project.html       # [必选] 网页本体（用于展示）
│   └── my-awesome-project.md         # [必选] 原始文档（用于提取标题/简介/标签）
├── papers/                    # 论文/笔记类网页
│   ├── attention-is-all-you-need.html
│   └── attention-is-all-you-need.md
└── ...
```

## 3. 详细数据规范

### 3.1 网页本体 (`.html`)
- **文件名 (Slug)**：
  - 必须使用 **纯英文、数字、短横线(-)** 组合。
  - **严禁使用中文**、空格或特殊符号（避免 URL 编码问题）。
  - 示例：`distributed-system-v1.html` (√), `分布式系统.html` (×)
- **内容要求**：
  - 必须是完整的 HTML Document (`<!DOCTYPE html>...</html>`)。
  - 内部资源（图片/脚本）引用建议使用相对路径（如 `./assets/img.png`）或绝对路径（如果资源已托管）。
  - **自适应**：建议支持响应式布局（Mobile/Desktop），因为会被嵌入到博客的 iframe 中展示。

### 3.2 原始文档 (`.md`)
这是博客系统“认识”这个网页的关键。文件名必须与 HTML 完全一致，仅后缀不同。

**标准 Frontmatter (YAML 头)：**
```markdown
---
title: "分布式物联网监控平台"      # [必填] 标题，支持中文
brief: "基于边缘计算的高性能..."   # [必填] 简介，用于列表页卡片展示（建议 50-100 字）
date: "2024-03-15"              # [必填] 发布日期，格式 YYYY-MM-DD
tags: ["IoT", "Vue3", "Edge"]   # [必填] 标签数组，用于分类筛选
cover: "/images/iot-cover.jpg"  # [可选] 封面图路径，若无则使用默认占位图
author: "Trae"                  # [可选] 作者名
type: "project"                 # [可选] 显式指定类型：project | paper
---

这里是 Markdown 正文内容（博客系统主要读取上面的 YAML 头信息，正文内容仅作备用或搜索索引）...
```

### 3.3 示例：一个完整的交付包

**文件 1：`deep-learning-note.html`**
```html
<!DOCTYPE html>
<html>
<head>
    <title>深度学习笔记</title>
    <style>body { font-family: sans-serif; padding: 20px; }</style>
</head>
<body>
    <h1>深度学习核心概念</h1>
    <p>这里是正文内容...</p>
</body>

```

**文件 2：`deep-learning-note.md`**
```markdown

# 深度学习核心概念
...
```

## 4. 为什么需要“HTML + Markdown”？
虽然 HTML 是最终展示的内容，但解析 HTML 获取结构化数据（如标题、日期、标签）非常不可靠且低效。
Markdown 的 Frontmatter 是天然的元数据载体。
**优势**：
1.  **无需额外开发**：上游工具本身就是 Markdown 转换器，保留原始输入文件零成本。
2.  **单一事实来源**：标题和标签在 Markdown 中定义一次，HTML 生成和博客索引都使用同一份数据。
3.  **便于维护**：如果需要修改标题或标签，直接改 Markdown 文件即可，博客系统会自动更新索引。

## 5. 常见问题 (FAQ)

**Q: 我的 Markdown 没有 Frontmatter 怎么办？**
A: 请在转换前手动添加或让工具自动补充。没有 Frontmatter，博客系统无法知道这篇文章的标题和发布时间，也就无法在首页展示。

**Q: 图片资源放在哪里？**
A: 建议将 HTML 及其引用的图片一起放在一个子文件夹中，例如：
`public/static_pages/projects/my-project/index.html`
`public/static_pages/projects/my-project/index.md`
`public/static_pages/projects/my-project/assets/image.png`
这样 HTML 内部引用图片只需写 `<img src="./assets/image.png">` 即可，博客系统能完美支持这种结构。

**Q: 首页如何展示这些内容？**
A: 博客构建脚本会自动扫描 `public/static_pages` 下的所有 `.md` 文件，解析其 Frontmatter，将其聚合成一个列表，按 `date` 倒序排列，生成首页的“最新动态”和“项目列表”。用户点击卡片后，会跳转到对应的 `.html` 页面。
