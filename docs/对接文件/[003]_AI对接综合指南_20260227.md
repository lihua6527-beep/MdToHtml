# 静态网页资产交付与对接规范 (Static Assets Delivery Standard)
更新时间：2026-02-27
**对接方**：个人博客系统 (Personal Blog Project)
**输出方**：MdToHtml 工具 (本系统)

---

## 1. 概述 (Overview)

本规范定义了 **MdToHtml 工具** 向 **个人博客项目** 交付静态网页资产的标准。
我们（MdToHtml）负责将结构化的 Markdown 转换为高保真的静态 HTML 页面。
你们（个人博客项目）作为**容器**，负责接收这些资产，通过文件系统扫描建立索引，并将其集成到博客的 Projects/Papers 板块中。

---

## 2. 交付物定义 (Deliverables)

我们交付的核心资产是 **“静态 HTML + 元信息 JSON”** 的成对文件。

### 2.1 交付清单
对于每一个内容条目（如一篇论文笔记或项目介绍），我们将提供：

1.  **静态网页文件 (`.html`)**
    *   **形式**：纯静态 HTML5 文档，无 React/Vue 运行时依赖。
    *   **体积**：单文件通常 < 50KB (Gzip 前，不含图片)，极度轻量。
    *   **技术栈**：原生 DOM + CSS Grid + Tailwind (内联/原子化)。
    *   **兼容性**：专为 `<iframe>` 嵌入设计，支持响应式布局 (Mobile/Desktop)。
    *   **样式**：内置 CHD 协议的莫兰迪配色与网格布局，自带暗色模式适配能力。

2.  **元信息文件 (`.json`)**
    *   **作用**：作为博客系统的**索引数据源**。博客系统应读取此 JSON 来获取标题、日期、标签、摘要、类型等信息。
    *   **特点**：字段稳定、无需解析 Markdown/HTML，构建索引更快且更可靠。

### 2.2 不交付内容 (Out of Scope)
为降低对接复杂度与避免路径/资源问题，本阶段明确不交付/不承诺以下能力：
*   **不交付 Markdown 源码**（博客系统不需要解析 CHD Markdown）。
*   **不处理图片与资源路径**：HTML 中不应依赖本地图片/自定义 assets 目录；若确有图片需求，统一由下游以外部 URL 或后续版本协议扩展解决。

---

## 3. 交付目录结构 (Directory Structure)

建议博客系统预留一个接收目录（如 `public/static_pages/`）来接收我们的输出。**目录内采用扁平结构**：HTML 与 JSON 混合存放，通过文件名一一对应。

```text
前端/public/static_pages/
├── 卷积神经网络研究综述.html        # [交付物] 页面正文 (支持中文文件名)
├── 卷积神经网络研究综述.json        # [交付物] 元信息
├── distributed-monitor.html
├── distributed-monitor.json
└── ...
```

**命名规范**：
*   **允许中文文件名**：为了保持与原 Markdown 标题的一致性，交付的文件名（Slug）可能包含中文。
*   HTML 与 JSON 通过**基名完全一致**建立关联：`<slug>.html` ↔ `<slug>.json`。
*   **风险提示与处理**：
    *   在文件系统层面（Node.js `fs`），直接使用 UTF-8 字符串即可读取，通常无问题。
    *   在 Web 服务与 URL 路由层面，中文路径必须经过 URL 编码。下游系统在生成链接时应使用 `encodeURIComponent(slug)`，在接收路由参数时应使用 `decodeURIComponent(slug)`。

## 4. 元数据协议 (Metadata Protocol)

博客系统**必须**解析与 HTML 同名的 JSON 文件来构建列表页/首页聚合。以下是我们输出的标准字段：

### 4.1 JSON 示例

```json
{
  "id": "卷积神经网络研究综述",
  "type": "project",
  "title": "卷积神经网络研究综述",
  "brief": "深入探讨CNN的核心架构与最新进展……",
  "date": "2026-02-27",
  "tags": ["AI", "Deep Learning"],
  "chdVersion": "2.4",
  "htmlFile": "卷积神经网络研究综述.html"
}
```

### 4.2 字段说明
*   **id**: 必需。推荐等于文件基名 `<slug>`（可能含中文），作为唯一主键。
*   **type**: 必需。下游用于分流：`project | paper`（后续可扩展）。
*   **title**: 必需。列表页的大标题（可中文）。
*   **brief**: 必需。列表页摘要，建议 60-100 字。
*   **date**: 必需。排序字段，格式 `YYYY-MM-DD`。
*   **tags**: 必需。用于筛选/检索。
*   **chdVersion**: 可选。记录内容遵循的 CHD 协议版本（方便后续兼容）。
*   **htmlFile**: 必需。HTML 文件名（通常就是 `<slug>.html`，冗余但便于校验）。

## 5. 文件对应与分流策略 (Matching & Routing)

下游拿到一个“扁平混合目录”后，应按文件后缀分流，并通过文件基名进行配对。

### 5.1 配对规则 (Pairing)
*   配对键：文件基名 `<slug>`（不含扩展名）。
*   必须同时存在：`<slug>.html` 与 `<slug>.json`。
*   如果只存在其中一个：该条目视为不完整，应忽略或记录为告警。

### 5.2 分流策略 (Routing)
建议下游索引流程：
1.  扫描目录得到所有 `*.json`。
2.  读取 JSON，按 `type` 分到 `Projects/Papers`（或未来其他集合）。
3.  用 `htmlFile` 或 `<id>.html` 生成最终访问地址：
    *   如果下游使用 iframe 壳页面：`/projects/<id>` 或 `/papers/<id>`（壳页面内部 iframe 指向 `/<basePath>/<htmlFile>`）。
    *   如果下游直接暴露静态文件：`/<basePath>/<htmlFile>`。

### 5.3 对应示例 (Example)
*   `distributed-monitor.json` 的 `id` 为 `distributed-monitor`，则：
    *   对应 HTML：`distributed-monitor.html`
    *   详情页壳路由（下游自定）：`/projects/distributed-monitor`
    *   iframe 指向（下游自定 basePath）：`/static_pages/distributed-monitor.html`

## 6. 技术问答 (FAQ)

**Q: 输出的 HTML 依赖外部 CSS/JS 吗？**
A: 默认不要求下游额外引入运行时。样式尽量内联/自包含；如遇到数学公式渲染依赖，优先由 HTML 自包含解决。下游只需把 HTML 当作静态页面展示。

**Q: 网页体积多大？**
A: 纯文本内容的 HTML 通常在 **20KB - 50KB** 之间。非常轻量，加载速度极快。

**Q: 博客系统需要安装 Markdown 渲染器吗？**
A: **不需要**。下游只读取 JSON 取元信息，并展示 HTML 即可。
