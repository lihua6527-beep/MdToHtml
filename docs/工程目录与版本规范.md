## 二、统一构建管线（产物只落两个位置）

```
开发预览   npm run dev                → 开发态 .next/
Web 构建   npm run build              → 生产态 .next/（唯一 Web 产物目录）
桌面打包   npm run build:electron     → release/（唯一打包产物目录）
一键清理   npm run clean              → 删除全部可再生产物（scripts/clean-artifacts.js）
```

产物命名规则：`MdToHtml Pro-Portable-<package.json 的 version>.exe`

---

## 三、版本与归档规划

1. **版本号唯一来源**：`MdToHtml/package.json` 的 `version` 字段；页面展示号与其保持一致。
2. **git 标签**：发布/重大清理后打对应 tag（现有 `v1.0`、`backup-before-card-style-upgrade`）。
3. **release 目录只保留最新一次打包结果**：历史 exe 不堆积在仓库内，统一移到工作区外的 `MdToHmtl_release_backup/`。
4. **演示/交付前必须重新打包**：`npm run build && npm run build:electron`，保证 exe 包含最新源码（例：2026-07-18 的旧 exe 落后于 07-26 源码，已于清理时归档）。
5. **未提交源码状态**：2026-07-25/26 存在未提交的 AI 内联编辑等功能改动（`git status` 可见），重新打包前应先行提交或确认包含范围。

## 四、node_modules 瘦身（整工程 ≤ 500MB 目标）

现状：清理后 `MdToHtml` ≈ 1,389 MB，其中 `node_modules` ≈ 920 MB，是超过 500MB 目标的唯一大头。

可选步骤（按需执行）：
1. 备份现有 `node_modules` → 执行 `npm ci` 全新安装（去除历史残留包）。
2. `npm dedupe` 消除重复版本。
3. 若仍超限：使用生产 profile `npm ci --omit=dev` 运行演示；需要重新构建/打包时再临时 `npm ci` 恢复。
4. 用 `npm ls --depth=0` 核对是否残留已不在 `package.json` 中的历史依赖。

---

## 五、铁律（防止问题复发）

1. 禁止在任何子目录新建 `dist`/`dist_build`/`dist_build_v2`/`release_v2`/`out` 这类非标准产物目录；构建结果只允许出现在 `.next/` 与 `release/`。
2. 禁止提交 `test-results/`、`playwright-report/`、`coverage/`、`.swc/`、`temp/` 等可再生产物（已加入根 .gitignore）。
3. 大体积 `.zip`/`.exe` 一律不进 git；历史备份放工作区外目录。
4. 目录结构变化后，同步更新 `PROJECT_SYSTEM_INDEX.md` 与本文档。
