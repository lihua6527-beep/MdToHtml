# 开发日志原子化管理规范 (Atomic Development Log SOP)

本文档定义了 `dev-log-manager` Skill 的工作流逻辑，旨在彻底杜绝“覆盖写入”导致的数据丢失问题，确立标准化的开发记录维护机制。

## 1. 核心原则 (Core Principles)

1.  **原子性 (Atomicity)**: 
    - 每天或每个功能点必须生成一个**独立文件**。
    - 禁止全量修改或覆盖旧的日志文件。
2.  **追加模式 (Append-Only)**: 
    - 对当天的日志文件，严禁使用 `Write` 工具进行全量覆盖。
    - 必须使用 `SearchReplace` 或追加工具进行增量写入。
3.  **不可变历史 (Immutable History)**: 
    - 过去日期的日志文件一旦生成，即视为**不可变**。
    - "合并"操作仅是将旧文件归档，而非修改它们的内容。

## 2. 目录结构 (Directory Structure)

- **根目录**: `docs/开发记录/`
- **每日日志**: `docs/开发记录/历史记录/YYYY-MM-DD_[FeatureName].md`
- **索引文件**: `docs/开发记录/开发记录索引.md`
- **归档目录**: `docs/开发记录/归档/` (可选，用于存放合并后的汇总)

## 3. 操作流程 (Workflows)

### 3.1 创建/更新今日日志 (Create/Update Daily Log)

**触发场景**: 用户指令 "写日志"、"记录开发"、"更新日志"。

**执行步骤**:
1.  **确定文件名**:
    - 格式: `YYYY-MM-DD_[FeatureName].md`
    - 示例: `2026-02-27_评分系统重构.md`
2.  **检查文件是否存在**:
    - **不存在**: 使用 `Write` 工具创建新文件，写入一级标题 `# YYYY-MM-DD [Feature] 开发记录`。
    - **已存在**: 读取文件内容 -> 使用 `SearchReplace` 在文件末尾**追加**新章节 (Level 2 `##` 或 Level 3 `###` 标题)。
    - **警告**: 严禁读取旧内容后拼接新内容再全量 `Write`，这极易导致中间内容丢失。
3.  **更新索引**:
    - 读取 `docs/开发记录/开发记录索引.md`。
    - 若无今日链接，则追加: `- [YYYY-MM-DD [Feature]](./历史记录/YYYY-MM-DD_[FeatureName].md)`。

### 3.2 合并/归档记录 (Merge/Archive Logs)

**触发场景**: 用户指令 "合并记录"、"归档日志"。

**执行步骤**:
1.  **识别目标**: 扫描 `docs/开发记录/历史记录/` 下的所有文件。
2.  **过滤**: **排除** 今天的日志文件 (Today's Log)。今日日志仍处于活跃状态，不应被归档。
3.  **执行合并**:
    - 根据需求生成汇总文件 (如 `2026-02_汇总.md`) 放入 `归档/` 目录。
    - **保留** 原有的历史文件 (除非用户明确要求删除)，确保数据安全。

## 4. AI 行为准则 (Safety Instructions)

- **NO OVERWRITE**: 永远不要覆盖写。永远。
- **VERIFY**: 每次写入后，必须读取文件确认内容完整性。
- **ISOLATION**: 不同的功能开发应尽可能使用不同的日志文件后缀，避免并发修改冲突。
