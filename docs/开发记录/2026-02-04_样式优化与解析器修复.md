## 1. 项目进度分析
当前项目已完成核心渲染引擎的构建（Next.js + Tailwind CSS），实现了 Markdown 到 CHD（Card-based Hierarchical Document）的动态转换。

### 已达成目标
- [x] **CHD 协议支持**: 支持 L0 (文档), L1 (章节), L2 (卡片) 三级结构。
- [x] **Grid 布局修复**: 解决了 Tailwind 动态类名导致的 Grid 失效问题，实现了从左往右的自然流式布局。
- [x] **莫兰迪配色体系**: 全局应用了低饱和度的莫兰迪色系，视觉风格统一。
- [x] **智能尺寸算法**: 根据卡片文本量自动计算 `col-span`，避免了由于内容差异导致的布局破碎。
- [x] **核心亮点重构**: 将 YAML Frontmatter 中的 `highlights` 升级为独立的 Grid 卡片展示区，支持“大标题+描述”的视觉范式。

### 存在的差距
- **静态导出**: 目前依赖 `npm run dev` 启动服务，尚未配置 `next build && next export` 生成纯静态 HTML 文件。
- **样式多样性**: 虽然核心亮点区视觉效果优秀，但正文区域（L2 卡片）的样式过于依赖 Markdown 中的 `card-style` 属性。由于现有文档（如 `例子1.md`）中大量使用了重复的 `style="highlight"` 或 `style="normal"`，导致视觉体验趋于单调。

## 2. 样式差异分析
**现象**: “核心亮点”区域显示效果特别优秀，而后续卡片显示风格非常单一。

**原因分析**:
1.  **实现机制不同**:
    - **核心亮点 (Highlights)**: 在 `CHDRenderer.tsx` 中使用了**定制化的 React 组件**。它不依赖 Markdown 的通用解析，而是专门提取了“标题”和“描述”，应用了居中对齐、特殊字体大小和特定的 Grid 布局。这种“硬编码”的优化保证了其视觉上限。
    - **后续卡片 (Standard Cards)**: 使用通用的 `Card.tsx` 组件。该组件虽然支持多种 `style` 变体（如 `normal`, `highlight`, `stat`），但其最终渲染效果完全取决于 Markdown 文档中是否正确使用了这些变体。
2.  **数据源限制**:
    - 检查 `例子1.md` 发现，大部分卡片被标记为 `card-style="highlight"` 或 `card-style="summary"`。
    - `Card.tsx` 中 `highlight` 和 `normal` 的样式定义虽然经过了优化（统一了阴影和圆角），但本质上都是“白底/灰底 + 文字”，缺乏像“核心亮点”那样的结构化视觉冲击（如居中大标题、图标装饰等）。

**改进建议**:
- **自动样式注入**: 在解析器中增加逻辑，如果卡片没有指定样式，可以根据其内容特征（如是否包含数字、代码块）自动分配 `stat` 或 `code` 样式。
- **丰富 Card 组件**: 将“核心亮点”的“居中大标题”设计模式下沉到通用 `Card` 组件的某个变体中（如新增 `style="hero"`）。

## 3. 解析器遗漏分析 (Parser Review)
当前 `CHDRenderer.tsx` 的解析逻辑主要基于正则表达式 `split`。

### 潜在风险与遗漏
1.  **嵌套结构脆弱性**: 使用 `split(/^### /m)` 分割卡片。如果卡片内容内部（如代码块中）恰好包含 `### `，解析器会将其错误地识别为新卡片。
    - *建议*: 引入更健壮的 AST（抽象语法树）解析，或限制分割仅匹配行首。
2.  **属性解析限制**: `parseAttributes` 函数仅支持 `{key="value"}` 格式。如果用户使用了单引号或无引号（`{key=value}`），可能会解析失败。
3.  **HTML 注入**: 虽然使用了 `ReactMarkdown` 进行渲染，但未显式配置 `rehype-sanitize`，如果 Markdown 内容包含恶意 HTML 脚本，可能存在 XSS 风险（但在本地预览环境下风险较低）。
4.  **图片与多媒体**: 目前尚未专门测试图片（Images）和表格（Tables）在 Grid 卡片中的响应式表现。
