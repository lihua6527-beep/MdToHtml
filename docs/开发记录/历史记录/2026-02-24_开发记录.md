# 2026-02-24 开发记录：编辑器重构尝试与回滚

## 1. 工作摘要
本日主要尝试了基于 `BottomToolbar` 和 `SideToolbar` 的编辑器 UI 重构，旨在提供更丰富的卡片布局、样式和主题控制。然而，在实施过程中遇到了严重的组件耦合、类型错误以及 UI 交互过于复杂的问题，最终决定回滚至 Master 分支，并重新制定“UI 原型优先”的开发策略。

## 2. 失败尝试详情
### 2.1 尝试内容
- **底部工具栏 (BottomToolbar)**：尝试集成主题切换、分区间距控制（Slider -> 固定选项）、布局模式选择（Grid/List/Gallery）。
- **侧边工具栏 (SideToolbar)**：尝试实现针对单个卡片的精细化控制（颜色、宽窄、位置）。
- **状态管理**：引入了复杂的本地状态同步机制（`useEffect` + `frontmatter`），试图解决实时预览的延迟问题。

### 2.2 遇到的问题
1.  **类型系统崩溃**：由于过度扩展 `ThemeConfig` 和 `CHDBlock` 接口，导致多处类型定义冲突（如 `currentSection.cards` 的 `undefined` 问题）。
2.  **UI 交互拥挤**：在有限的底部空间内塞入过多控件（滑块、按钮组、多级菜单），导致操作体验极差，且在小屏幕下出现遮挡。
3.  **代码复杂度失控**：组件内部逻辑过于复杂，混合了 DOM 操作、状态管理和业务逻辑，违反了单一职责原则。

### 2.3 决策：回滚
- **操作**：执行 `git checkout .` 和 `git clean -fd`，放弃所有未提交更改，回退至 `master` 分支。
- **原因**：与其在错误的基础上修补，不如清理包袱，重新出发。当前的架构无法优雅地支持如此复杂的实时编辑需求。

## 3. 反思与改进策略
- **UI 先行**：不再直接在 React 组件中“硬写”逻辑，而是先使用静态 HTML/CSS 原型（`prototype.html`）验证交互设计的合理性。
- **分层实现**：
    1.  **视觉层**：先确立所有控制元素（主题、布局、卡片）的视觉表现和排列。
    2.  **逻辑层**：确认后端逻辑（Markdown/Frontmatter 解析）能否支持这些视觉控制。
    3.  **集成**：最后再进行 React 组件化和状态绑定。
