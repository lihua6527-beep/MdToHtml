# 2026-02-24 开发记录汇总

## 1. 底部工具栏与布局策略重构
*(源文件: 2026-02-24_底部工具栏与布局策略重构.md)*

### 1.1 核心变更 (Core Changes)
- **交互重构**: 将编辑器交互从悬浮式 Dock (Floating Dock) 彻底迁移至底部固定工具栏 (Fixed Bottom Toolbar)。
- **布局引擎升级**: 引入策略模式 (Strategy Pattern) 重构布局渲染逻辑，解耦 `Section.tsx`。
- **视觉对齐**: 实现 `cut` (缺角), `arrow` (箭头), `floating` (琥珀色徽章) 等卡片样式，对齐原型设计。

### 1.2 详细改动 (Detailed Modifications)
#### 底部工具栏 (BottomToolbar)
- **文件**: `src/components/CHD/BottomToolbar.tsx`
- **功能**:
  - 实现了 Theme/Layout/Card 三段式 Tab 结构。
  - 实现了基于选区的自动 Tab 切换逻辑 (选中 Section -> Layout Tab, 选中 Card -> Card Tab)。
  - 集成了 `useMarkdownInteraction` 钩子，直接操作 Markdown 源码。

#### 布局策略 (Layout Strategies)
- **文件**: `src/components/CHD/LayoutStrategies.tsx`
- **新增布局**:
  - **Hub (环绕)**: 核心卡片居中，卫星卡片环绕，强制圆形样式。
  - **Ring (环形)**: SVG 分段环形图，支持点击交互与文本覆盖。
  - **Carousel (3D轮播)**: 基于 CSS 3D Transform 的旋转木马效果，支持拖拽旋转。
  - **Timeline (时间轴)**: 左右交替分布的时间轴视图。
- **架构优势**: 新增布局无需修改 `Section` 组件逻辑，只需注册新策略。

#### 卡片样式 (Card Styles)
- **文件**: `src/components/CHD/Card.tsx`, `src/lib/shapes.ts`
- **实现**:
  - 使用 CSS `clip-path` 实现多边形裁剪。
  - 移除了旧版悬浮编辑菜单代码 (约 300 行)，消除技术债。
  - 修复了 GBK/UTF-8 混杂导致的中文乱码问题。

### 1.3 验证结果 (Verification)
- **功能**: 底部工具栏正确响应点击，Markdown 源码实时更新。
- **视觉**: 环形、轮播等复杂布局渲染正常，无错位。
- **代码**: 移除了冗余代码，消除了控制台关于 `key` 和 `nesting` 的警告。

### 1.4 意义与反思 (Significance & Reflection) [2026-02-25 补充]
- **大一统的前奏**: 今天的重构为后续的「编辑器大一统」奠定了坚实基础。通过将交互下沉到底部，我们成功释放了内容区域的空间。
- **平台化**: 引入策略模式不仅仅是为了支持更多布局，更是为了构建一个可扩展的「插件平台」。未来的开发者（或 AI）只需关注具体的渲染策略，而无需关心状态同步和数据流转。

## 3. 编辑器重构尝试与回滚
*(源文件: 2026-02-24_开发记录.md)*

### 3.1 工作摘要
本日主要尝试了基于 `BottomToolbar` 和 `SideToolbar` 的编辑器 UI 重构，旨在提供更丰富的卡片布局、样式和主题控制。然而，在实施过程中遇到了严重的组件耦合、类型错误以及 UI 交互过于复杂的问题，最终决定回滚至 Master 分支，并重新制定“UI 原型优先”的开发策略。

### 3.2 失败尝试详情
#### 尝试内容
- **底部工具栏 (BottomToolbar)**：尝试集成主题切换、分区间距控制（Slider -> 固定选项）、布局模式选择（Grid/List/Gallery）。
- **侧边工具栏 (SideToolbar)**：尝试实现针对单个卡片的精细化控制（颜色、宽窄、位置）。
- **状态管理**：引入了复杂的本地状态同步机制（`useEffect` + `frontmatter`），试图解决实时预览的延迟问题。

#### 遇到的问题
1.  **类型系统崩溃**：由于过度扩展 `ThemeConfig` 和 `CHDBlock` 接口，导致多处类型定义冲突（如 `currentSection.cards` 的 `undefined` 问题）。
2.  **UI 交互拥挤**：在有限的底部空间内塞入过多控件（滑块、按钮组、多级菜单），导致操作体验极差，且在小屏幕下出现遮挡。
3.  **代码复杂度失控**：组件内部逻辑过于复杂，混合了 DOM 操作、状态管理和业务逻辑，违反了单一职责原则。

#### 决策：回滚
- **操作**：执行 `git checkout .` 和 `git clean -fd`，放弃所有未提交更改，回退至 `master` 分支。
- **原因**：与其在错误的基础上修补，不如清理包袱，重新出发。当前的架构无法优雅地支持如此复杂的实时编辑需求。

### 3.3 反思与改进策略
- **UI 先行**：不再直接在 React 组件中“硬写”逻辑，而是先使用静态 HTML/CSS 原型（`prototype.html`）验证交互设计的合理性。
- **分层实现**：
    1.  **视觉层**：先确立所有控制元素（主题、布局、卡片）的视觉表现和排列。
    2.  **逻辑层**：确认后端逻辑（Markdown/Frontmatter 解析）能否支持这些视觉控制。
    3.  **集成**：最后再进行 React 组件化和状态绑定。
