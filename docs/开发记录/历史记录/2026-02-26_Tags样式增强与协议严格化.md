# Tags 样式增强与协议严格化

## 1. Tags 样式增强 (Tags Styling)
针对用户提出的 "高级渲染" 与 "多样化图标" 需求，我们对 Tags 系统进行了重构：

### 1.1 核心特性
- **5种高级风格**:
  - `glass`: 磨砂玻璃效果 (默认)，高斯模糊 + 半透明背景。
  - `tech`: 科技风，细边框 + 终端字体。
  - `gradient`: 渐变色背景，活力风格。
  - `outline`: 极简描边风格。
  - `pop`: 波普艺术风格，高对比度阴影。
- **智能图标映射 (Smart Icon Mapping)**:
  - 引入 `lucide-react` 图标库。
  - 实现 `getSmartIcon` 算法，根据 Tag 文本内容自动匹配语义化图标：
    - AI/模型 -> `Brain`
    - 数据/Data -> `Database`
    - 性能/优化 -> `Zap`
    - 更多映射规则已内置。
- **Frontmatter 独占渲染**:
  - 严格遵循 CHD v2.3 协议，**仅** 在文档顶部的 Frontmatter 区域渲染 Tags。
  - Card 内部的 Tags 字段不再渲染，避免视觉干扰。

### 1.2 主题集成
- 在 **BottomToolbar** 的主题面板 (Theme Panel) 右侧新增了 **Tag Style Selector**。
- 支持实时点击切换 Tags 样式，并自动同步至 Frontmatter 的 `tag-style` 字段。
- 实现了样式状态的持久化存储。

## 2. CHD 协议严格化 (Strict Enforcement)
针对文档中出现的 "代码样式滥用" (Code Style Abuse) 问题，我们在渲染层实施了严格拦截。

### 2.1 问题背景
用户反馈文档中大量普通文本被错误地使用了 Inline Code 样式 (如 ``重点文字``)，导致视觉混乱且不符合 CHD 语义协议。

### 2.2 强制清洗逻辑
在 `Card.tsx` 的 Markdown 渲染器中增加了拦截逻辑：

1. **允许列表 (Allowlist)**:
   - **Block Code**: 代码块 (` ``` `) 始终允许。
   - **箭头/顺序**: `->`, `=>`, `→` 等符号允许。
   - **引用标注**: `[1]`, `[Ref]` 等格式允许。
   - **纯代码特征**: 包含 `(){}=` 等符号，或驼峰/下划线命名，且 **不含中文** 的文本。

2. **降级策略 (Fallback Strategy)**:
   - 任何 **包含中文** 或 **长句** 的 Inline Code，将被强制降级为 **Bold (加粗)** 样式。
   - 即使 Markdown 源码写的是 ``中文测试``，渲染结果也会变成 **中文测试** (无灰色背景，无等宽字体)。

### 2.3 预期效果
- 彻底消除非代码内容的视觉干扰。
- 强制用户仅在展示真实代码或特定符号时使用 Code 样式。
