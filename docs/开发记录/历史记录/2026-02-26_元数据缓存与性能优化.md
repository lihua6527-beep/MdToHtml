# 开发记录 - 2026-02-26: 元数据缓存与性能优化

## 1. 核心变更摘要
本日重点解决了随着文档数量增长导致的启动缓慢与状态不一致问题。引入了**元数据缓存系统 (Metadata Cache System)**，将文件系统的全量扫描复杂度从 O(N) 降低为 O(1)，并彻底修复了文档状态在“已完成”与“未完成”之间跳变的 Bug。

## 2. 详细变更内容

### 2.1 引入 MetadataCacheManager
- **目标**: 解决 `getAllPosts` 每次全量扫描文件系统的性能瓶颈。
- **实现**:
  - 创建单例 `MetadataCacheManager`。
  - 维护 `.metadata_cache.json` 文件，存储 Top 500 (默认容量) 最近访问文档的元数据。
  - **增量更新**: 仅当文件 mtime 发生变化时才读取文件内容解析 Frontmatter。
  - **自动清理**: 超出容量限制的文件自动移入 `.trash` 目录（需配合配置开启，目前仅做标记移除）。
  - **接口封装**: 提供 `getAll()` (O(1)) 和 `getPost(slug)` 接口。

### 2.2 状态同步与一致性修复
- **痛点**: 用户报告“已完成文档点进去被强制重置为未完成”。
- **根因**: 前端组件 `InteractivePost` 存在冗余的状态解析逻辑，且包含自动重置为 `incomplete` 的副作用代码。
- **修复**:
  - **后端收束**: 移除前端所有从 Markdown 内容解析状态的逻辑，完全信任后端传递的 `initialStatus` (来自缓存)。
  - **副作用移除**: 删除自动重置状态的 `useEffect`。
  - **API 对接**: 重构 `src/lib/posts.ts` 和 `api/save/route.ts`，确保所有读写操作均同步更新缓存。

### 2.3 交互体验优化 (Optimistic UI)
- **痛点**: 状态切换按钮点击后有延迟，且快速点击会导致状态回跳闪烁。
- **优化**:
  - **乐观更新**: 点击按钮瞬间立即更新 UI 状态，无需等待后端响应。
  - **Loading 反馈**: 引入 `Loader2` 转圈动画，在写入过程中禁用按钮，明确告知用户“正在保存”。
  - **过渡动画**: 为状态切换添加了平滑的视觉过渡。

## 3. 涉及文件
- `src/lib/cache-manager.ts` (New): 缓存管理器核心实现。
- `src/lib/posts.ts`: 接入缓存管理器。
- `src/app/api/save/route.ts`: 保存时同步更新缓存。
- `src/components/InteractivePost.tsx`: 移除冗余逻辑，添加乐观更新与动画。
- `src/app/[slug]/page.tsx`: 透传 `initialStatus`。
