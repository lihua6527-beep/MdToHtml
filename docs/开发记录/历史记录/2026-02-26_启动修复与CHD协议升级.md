# 2026-02-26 启动修复与 CHD 协议升级

## 1. 核心修复

### 1.1 启动脚本修复 (Smart Port & Browser Open)
- **问题**: `start.bat` 导致一次启动两个网页，且经常出现 404 错误。
- **原因**:
    - **双重启动**: `setup-port.js` 中的浏览器打开逻辑没有去抖动，且可能被多次触发。
    - **竞态条件**: 浏览器打开时服务器尚未完全就绪（`next dev` 启动较慢）。
- **解决方案**:
    - **引入 `wait-on`**: 使用 `wait-on` 库等待端口（如 3000）完全就绪后再打开浏览器。
    - **添加 `browserOpened` 标志**: 在 `setup-port.js` 中增加全局标志位，确保浏览器只被打开一次。
    - **移除硬编码延迟**: 删除了不可靠的 `setTimeout`，改为基于端口监听的事件驱动。
- **文件**: `scripts/setup-port.js`

### 1.2 路由路径修复 (404 Error)
- **问题**: 访问 `localhost:3000/editor/[中文路径]` 出现 404。
- **原因**: Next.js 的动态路由目录结构与链接不匹配。原目录为 `src/app/[slug]`，但链接指向 `/editor/[slug]`。
- **解决方案**:
    - **目录迁移**: 将 `src/app/[slug]` 移动至 `src/app/editor/[slug]`。
    - **PowerShell 兼容**: 使用 `Move-Item -LiteralPath` 解决了 Windows 下处理特殊字符（如 `[`）路径的问题。
- **文件**: `src/app/editor/[slug]/page.tsx`

### 2.1 协议合并与 SSOT
- **动作**: 将 `portable_ml_package/resources/CHD_protocol.md` 的核心约束合并至 `docs/核心规划/5_CHD协议与AI生成指南.md`。
- **目标**: 确立 `5_CHD协议与AI生成指南.md` 为单一真理来源 (SSOT)。

### 2.2 新增严格约束
- **代码样式 (`card-style="code"`)**:
    - **严格限制**: 仅限于展示代码块、配置文件或命令行。
    - **禁止滥用**: 严禁将普通文本设置为 `code` 样式以获取高亮。
- **视觉一致性 (Visual Consistency)**:
    - **Section 内部统一**: 同一个 `## Section` 下的卡片样式应保持一致（如全 `normal` 或全 `highlight`）。
    - **页脚例外**: 允许文档结尾（总结、引用）使用不同样式。
- **内容原子化 (Content Atomicity)**:
    - **One Card, One Point**: 禁止单体巨石卡片，强制拆分长内容以适配 Grid 布局。
