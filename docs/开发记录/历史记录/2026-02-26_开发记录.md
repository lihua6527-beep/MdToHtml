## 1. 启动修复与 CHD 协议升级
*(源文件: 2026-02-26_启动修复与CHD协议升级.md)*

### 1.1 核心修复
#### 启动脚本修复 (Smart Port & Browser Open)
- **问题**: `start.bat` 导致一次启动两个网页，且经常出现 404 错误。
- **原因**:
    - **双重启动**: `setup-port.js` 中的浏览器打开逻辑没有去抖动，且可能被多次触发。
    - **竞态条件**: 浏览器打开时服务器尚未完全就绪（`next dev` 启动较慢）。
- **解决方案**:
    - **引入 `wait-on`**: 使用 `wait-on` 库等待端口（如 3000）完全就绪后再打开浏览器。
    - **添加 `browserOpened` 标志**: 在 `setup-port.js` 中增加全局标志位，确保浏览器只被打开一次。
    - **移除硬编码延迟**: 删除了不可靠的 `setTimeout`，改为基于端口监听的事件驱动。
- **文件**: `scripts/setup-port.js`

#### 路由路径修复 (404 Error)
- **问题**: 访问 `localhost:3000/editor/[中文路径]` 出现 404。
- **原因**: Next.js 的动态路由目录结构与链接不匹配。原目录为 `src/app/[slug]`，但链接指向 `/editor/[slug]`。
- **解决方案**:
    - **目录迁移**: 将 `src/app/[slug]` 移动至 `src/app/editor/[slug]`。
    - **PowerShell 兼容**: 使用 `Move-Item -LiteralPath` 解决了 Windows 下处理特殊字符（如 `[`）路径的问题。
- **文件**: `src/app/editor/[slug]/page.tsx`

### 1.2 协议升级 (CHD Protocol v2.2)
#### 协议合并与 SSOT
- **动作**: 将 `portable_ml_package/resources/CHD_protocol.md` 的核心约束合并至 `docs/核心规划/5_CHD协议与AI生成指南.md`。
- **目标**: 确立 `5_CHD协议与AI生成指南.md` 为单一真理来源 (SSOT)。

#### 新增严格约束
- **代码样式 (`card-style="code"`)**:
    - **严格限制**: 仅限于展示代码块、配置文件或命令行。
    - **禁止滥用**: 严禁将普通文本设置为 `code` 样式以获取高亮。
- **视觉一致性 (Visual Consistency)**:
    - **Section 内部统一**: 同一个 `## Section` 下的卡片样式应保持一致（如全 `normal` 或全 `highlight`）。
    - **页脚例外**: 允许文档结尾（总结、引用）使用不同样式。
- **内容原子化 (Content Atomicity)**:
    - **One Card, One Point**: 禁止单体巨石卡片，强制拆分长内容以适配 Grid 布局。

## 2. 元数据缓存与性能优化
*(源文件: 2026-02-26_元数据缓存与性能优化.md)*

### 2.1 核心变更摘要
本日重点解决了随着文档数量增长导致的启动缓慢与状态不一致问题。引入了**元数据缓存系统 (Metadata Cache System)**，将文件系统的全量扫描复杂度从 O(N) 降低为 O(1)，并彻底修复了文档状态在“已完成”与“未完成”之间跳变的 Bug。

### 2.2 详细变更内容
#### 引入 MetadataCacheManager
- **目标**: 解决 `getAllPosts` 每次全量扫描文件系统的性能瓶颈。
- **实现**:
  - 创建单例 `MetadataCacheManager`。
  - 维护 `.metadata_cache.json` 文件，存储 Top 500 (默认容量) 最近访问文档的元数据。
  - **增量更新**: 仅当文件 mtime 发生变化时才读取文件内容解析 Frontmatter。
  - **自动清理**: 超出容量限制的文件自动移入 `.trash` 目录（需配合配置开启，目前仅做标记移除）。
  - **接口封装**: 提供 `getAll()` (O(1)) 和 `getPost(slug)` 接口。

#### 状态同步与一致性修复
- **痛点**: 用户报告“已完成文档点进去被强制重置为未完成”。
- **根因**: 前端组件 `InteractivePost` 存在冗余的状态解析逻辑，且包含自动重置为 `incomplete` 的副作用代码。
- **修复**:
  - **后端收束**: 移除前端所有从 Markdown 内容解析状态的逻辑，完全信任后端传递的 `initialStatus` (来自缓存)。
  - **副作用移除**: 删除自动重置状态的 `useEffect`。
  - **API 对接**: 重构 `src/lib/posts.ts` 和 `api/save/route.ts`，确保所有读写操作均同步更新缓存。

#### 交互体验优化 (Optimistic UI)
- **痛点**: 状态切换按钮点击后有延迟，且快速点击会导致状态回跳闪烁。
- **优化**:
  - **乐观更新**: 点击按钮瞬间立即更新 UI 状态，无需等待后端响应。
  - **Loading 反馈**: 引入 `Loader2` 转圈动画，在写入过程中禁用按钮，明确告知用户“正在保存”。
  - **过渡动画**: 为状态切换添加了平滑的视觉过渡。

### 2.3 涉及文件
- `src/lib/cache-manager.ts` (New): 缓存管理器核心实现。
- `src/lib/posts.ts`: 接入缓存管理器。
- `src/app/api/save/route.ts`: 保存时同步更新缓存。
- `src/components/InteractivePost.tsx`: 移除冗余逻辑，添加乐观更新与动画。
- `src/app/[slug]/page.tsx`: 透传 `initialStatus`。

### 2.4 后续计划
- 验证缓存文件在不同机器间的迁移兼容性。
- 进一步完善 `.trash` 清理策略的可视化管理。

## 3. Tags 样式增强与协议严格化
*(源文件: 2026-02-26_Tags样式增强与协议严格化.md)*

### 3.1 Tags 样式增强 (Tags Styling)
针对用户提出的 "高级渲染" 与 "多样化图标" 需求，我们对 Tags 系统进行了重构：

#### 核心特性
- **5种高级风格**:
  - `glass`: 磨砂玻璃效果 (默认)，高斯模糊 + 半透明背景。
  - `tech`: 科技风，细边框 + 终端字体。
  - `gradient`: 渐变色背景，活力风格。
  - `outline`: 极简描边风格。
  - `pop`: 波普艺术风格，高对比度阴影。
- **智能图标映射 (Smart Icon Mapping)**:
  - 引入 `lucide-react` 图标库。
  - 实现 `getSmartIcon` 算法，根据 Tag 文本内容自动匹配语义化图标：
    - AI/模型 -> `Brain`
    - 数据/Data -> `Database`
    - 性能/优化 -> `Zap`
    - 更多映射规则已内置。
- **Frontmatter 独占渲染**:
  - 严格遵循 CHD v2.3 协议，**仅** 在文档顶部的 Frontmatter 区域渲染 Tags。
  - Card 内部的 Tags 字段不再渲染，避免视觉干扰。

#### 主题集成
- 在 **BottomToolbar** 的主题面板 (Theme Panel) 右侧新增了 **Tag Style Selector**。
- 支持实时点击切换 Tags 样式，并自动同步至 Frontmatter 的 `tag-style` 字段。
- 实现了样式状态的持久化存储。

### 3.2 CHD 协议严格化 (Strict Enforcement)
针对文档中出现的 "代码样式滥用" (Code Style Abuse) 问题，我们在渲染层实施了严格拦截。

#### 问题背景
用户反馈文档中大量普通文本被错误地使用了 Inline Code 样式 (如 ``重点文字``)，导致视觉混乱且不符合 CHD 语义协议。

#### 强制清洗逻辑
在 `Card.tsx` 的 Markdown 渲染器中增加了拦截逻辑：

1. **允许列表 (Allowlist)**:
   - **Block Code**: 代码块 (` ``` `) 始终允许。
   - **箭头/顺序**: `->`, `=>`, `→` 等符号允许。
   - **引用标注**: `[1]`, `[Ref]` 等格式允许。
   - **纯代码特征**: 包含 `(){}=` 等符号，或驼峰/下划线命名，且 **不含中文** 的文本。

2. **降级策略 (Fallback Strategy)**:
   - 任何 **包含中文** 或 **长句** 的 Inline Code，将被强制降级为 **Bold (加粗)** 样式。
   - 即使 Markdown 源码写的是 ``中文测试``，渲染结果也会变成 **中文测试** (无灰色背景，无等宽字体)。

#### 预期效果
- 彻底消除非代码内容的视觉干扰。
- 强制用户仅在展示真实代码或特定符号时使用 Code 样式。

### 3.3 文件变更
- `src/components/CHD/Card.tsx`: 新增 `ReactMarkdown` 的 `code` 组件拦截逻辑。
- `src/components/CHD/TagRenderer.tsx`: 新增 Tags 渲染组件及样式库。
- `src/components/CHD/CHDRenderer.tsx`: 集成 `TagRenderer`。
- `src/components/CHD/BottomToolbar.tsx`: 集成 Tag 样式选择器。

*(源文件: 2026-02-26_回收站与批量管理功能实现.md)*

### 4.1 概述
响应用户需求，增强了文件管理的安全性与便捷性。新增了回收站机制，防止误删文档；实现了批量删除功能，提升了管理效率；并在设置面板中直观展示回收站路径。

### 4.2 核心变更 (Core Changes)
#### 回收站机制 (Recycle Bin)
- **路径管理**: 扩展 `PathManager` 类，引入 `recycleDir`。默认路径为项目根目录下的 `recycle/` 文件夹，支持通过 `config.json` 自定义。

- **缓存同步**: 删除操作同步更新 `MetadataCache`，确保列表状态即时刷新。

#### 批量管理功能 (Batch Management)
- **API 升级**: `/api/delete` 接口升级支持 `slugs` 数组参数，实现原子化的批量处理。
- **交互设计**:

- **状态反馈**: 批量操作完成后自动刷新列表并退出选择模式。

#### 设置面板增强 (Settings Panel)
- **路径可视化**: 在“文件路径”设置面板中新增红色高亮的“回收站路径”显示卡片，明确告知用户删除文件的去向。

### 4.3 技术细节
- **原子性**: 批量删除操作在服务端串行处理，确保文件系统操作的稳定性。
- **兼容性**: API 保持对旧版单文件删除请求的兼容。
- **前端状态**: 使用 `Set` 数据结构管理选中项，优化渲染性能。

## 6. 渲染引擎修复与保存逻辑优化
*(源文件: 2026-02-26_渲染引擎修复与保存逻辑优化.md)*

### 6.1 变更背景
本日在系统审计与用户反馈中发现以下关键问题，影响了编辑器的可用性与渲染的准确性：
1. **属性文本泄漏**: 分区标题（Section Title）在渲染时未彻底清洗 `{key=value}` 属性字符串，导致配置代码直接暴露在界面上。
2. **分割线逻辑混乱**: 分割线（Divider）仅在首个分区后显示，且逻辑绑定在 Section 组件内部，无法实现“每两个分区之间显示分割线”的预期效果。
3. **保存交互断层**: 用户手动保存后仍停留在编辑模式，缺乏明确的反馈与状态切换，不符合“保存即预览”的直觉。
4. **编译错误**: 引入新图标时缺少依赖导入。

### 6.2 详细变更内容
#### 渲染引擎修正 (Rendering Engine Fixes)
- **文件**: `src/components/CHD/Section.tsx`, `src/components/CHD/CHDRenderer.tsx`
- **属性清洗**: 在 `Section.tsx` 渲染层增加了强制清洗逻辑 `title.replace('## ', '').replace(/\{.*?\}/g, '').trim()`，确保标题纯净。
- **分割线重构**:
  - **移出**: 将分割线渲染逻辑从 `Section` 组件内部移出。
  - **上提**: 在 `CHDRenderer.tsx` 的主渲染循环中实现分割线逻辑。
  - **规则**: `index < sections.length - 1`，确保仅在分区之间渲染，且严格遵循前一个分区的 `show-divider` 属性。

#### 交互逻辑优化 (Interaction Optimization)
- **文件**: `src/components/InteractivePost.tsx`
- **保存即退出**: 更新 `handleSave` 方法。
  - **旧逻辑**: 仅执行保存请求，保持 `isEditing = true`。
  - **新逻辑**: 保存成功后立即执行 `setIsEditing(false)`，自动切换回预览模式。
- **视觉反馈**: 配合之前的 `saveSuccess` 状态，现在用户点击保存后会看到“成功对勾”并自动退出编辑器，体验更加流畅。

#### 代码质量修复 (Code Quality)
- **文件**: `src/app/editor/page.tsx`
- **依赖修复**: 补全了 `clsx` 工具库和 `Check` 图标的导入，解决了 `npx tsc` 编译报错。

### 6.3 验证结果
- **渲染**: 分区标题不再显示 `{...}`；多个分区之间（如第2-3、3-4之间）正确显示了分割线。
- **交互**: Ctrl+S 或点击保存按钮后，编辑器正确关闭，页面刷新为最新预览状态。
- **构建**: 通过 TypeScript 静态类型检查。

## 9. 自动保存逻辑与启动优化
*(源文件: 2026-02-26_自动保存逻辑与启动优化.md)*

### 9.1 变更摘要
本次更新主要修复了编辑器保存逻辑与启动体验问题，确保符合用户预期与操作习惯。

### 9.2 编辑器保存逻辑优化
- **痛点**: 自动保存 (Auto-save) 触发时会意外关闭编辑器，导致用户输入中断。
- **修复**: 重构 `InteractivePost.tsx` 中的保存逻辑。
  - **手动保存**: 点击保存按钮时，显式传递 `shouldCloseEditor=true`，保存后退出编辑模式。
  - **自动保存**: 无论是定时器触发还是状态变更触发，传递 `shouldCloseEditor=false`，仅执行静默保存，保持编辑器开启。
- **涉及文件**: `src/components/InteractivePost.tsx`

### 9.3 启动体验优化
- **痛点**: `start.bat` 启动后会打开两个浏览器窗口，且有时无法正确唤起。
- **修复**: 优化 `scripts/setup-port.js`。
  - **防止多开**: 移除冗余的打开逻辑，使用平台特定的稳健命令（Windows 下使用 `start "" "url"`）。
  - **单一实例**: 确保服务就绪后只唤起一个浏览器窗口。
- **涉及文件**: `scripts/setup-port.js`

### 9.4 全局布局配置升级
- **痛点**: 
  - 分区间距和分割线开关曾是局部属性，需逐个分区调整，效率低下且不统一。

## 11. 回收站与容量管理
*(源文件: 2026-02-26_回收站与容量管理.md)*

### 11.1 核心变更摘要
本日完成了 **全栈回收站系统 (Recycle Bin System)** 的开发，实现了文档的软删除、恢复、永久删除及容量限制管理。通过引入智能容量警告与一键清理机制，解决了存储空间受限时的用户体验问题。同时优化了恢复逻辑，确保恢复后的文档能立即被用户感知。

### 11.2 详细变更内容
#### 全栈回收站架构
- **后端 (`TrashManager`)**:
  - **单例模式**: 统一管理 `.trash` 目录操作。
  - **元数据持久化**: 删除时保留原文件名与时间戳（通过文件名后缀 `_deleted_TIMESTAMP`）。
  - **冲突解决**: 恢复时若存在同名文件，自动追加 `_restored_TIMESTAMP` 后缀。
  - **时间戳重置**: 恢复文件时，使用 `fs.utimesSync` 强制将文件的 `mtime` 和 `atime` 重置为当前时间，确保文档在“按导入时间排序”的列表中置顶，方便用户查找。

#### 前端交互 (RecycleBin UI)
- **入口集成**: 在文档列表底部集成回收站入口，支持展开/收起。
- **拖拽交互 (Drag & Drop)**:
  - **删除**: 支持从文档列表拖拽文件到回收站图标进行删除。
  - **恢复**: 支持从回收站列表拖拽文件回文档区域进行恢复。
- **列表刷新**: 恢复操作完成后，触发 `router.refresh()` 自动刷新文档列表，无需手动重载。
- **自动同步**: 在 `DocumentList` 组件中引入了 `useEffect` 监听 `initialPosts` 变化，确保服务端刷新后的数据能即时更新到客户端状态中，彻底解决“恢复后需手动刷新”的问题。

#### 智能容量管理
- **独立容量池**: 回收站拥有独立的 500 个文件容量限制（不占用主文档区配额）。
- **容量警告 (`CapacityWarningDialog`)**:
  - 当回收站或文档区达到上限时，拦截操作并弹出警告。
  - **一键清理**: 提供“删除最早文件”的快捷操作，自动识别并清理最旧的文件以释放空间。

## 12. 恢复逻辑与刷新机制修复
*(源文件: 2026-02-26_恢复逻辑与刷新机制修复.md)*

### 12.1 问题背景
用户反馈在 Windows 环境下，从回收站恢复文件后：
1.  **列表未刷新**: 文件数量未变（如 17 -> 16），需手动刷新页面。
2.  **排序错误**: 恢复的文件未出现在列表顶部，而是回到了原来的位置。

### 12.2 核心修复 (Core Fixes)
#### 强制元数据更新 (Windows Tunneling Fix)
- **原因**: Windows 文件系统存在 "Tunneling" 机制，文件被删除后短时间内重建同名文件会保留原文件的创建时间 (CreationTime)，导致按“导入时间”排序失效。
- **修复**: 在 `TrashManager.ts` 中引入 PowerShell 命令，强制将恢复文件的 `CreationTime` 更新为当前时间。
- **策略**: 采用 `Copy` + `Delete` 替代 `Rename` 操作，确保生成全新的文件 inode (在非 Windows 系统上)，并配合 `fs.utimesSync` 更新 `mtime`/`atime`。

#### 多级缓存同步 (Cache Synchronization)
- **服务端**: 在 `restore` API 成功后，立即调用 `MetadataCacheManager.scanAndSync()`，强制服务端缓存重构建，确保 `/api/files` 返回最新数据。
- **客户端**: 在 `DocumentList.tsx` 中实施 **双重刷新策略 (Double Refresh Strategy)**：
  1.  `router.refresh()`: 触发 React Server Components 更新。
  2.  `fetch('/api/files')`: 客户端立即发起异步请求并手动更新 `posts` 状态。
  3.  **时机绑定**: 将刷新逻辑绑定至 `RecycleBin` 的 `onClose` 事件，确保用户关闭回收站时列表绝对是最新的。

### 12.3 验证结果
- **测试脚本**: 编写 `scripts/verify-refresh.js` 模拟完整生命周期（创建->删除->恢复->检查）。
- **表现**: 恢复操作耗时 <300ms，列表立即刷新，且恢复的文件稳居列表顶部。

### 12.4 涉及文件
- `src/lib/trash-manager.ts`: 增加 PowerShell 时间戳修复。
- `src/app/api/trash/restore/route.ts`: 增加 `MetadataCacheManager` 同步。
- `src/components/DocumentList.tsx`: 增加客户端主动刷新逻辑。
