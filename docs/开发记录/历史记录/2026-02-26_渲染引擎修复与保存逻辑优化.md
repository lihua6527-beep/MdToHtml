# 2026-02-26 渲染引擎修复与保存逻辑优化

## 1. 变更背景
本日在系统审计与用户反馈中发现以下关键问题，影响了编辑器的可用性与渲染的准确性：
1. **属性文本泄漏**: 分区标题（Section Title）在渲染时未彻底清洗 `{key=value}` 属性字符串，导致配置代码直接暴露在界面上。
2. **分割线逻辑混乱**: 分割线（Divider）仅在首个分区后显示，且逻辑绑定在 Section 组件内部，无法实现“每两个分区之间显示分割线”的预期效果。
3. **保存交互断层**: 用户手动保存后仍停留在编辑模式，缺乏明确的反馈与状态切换，不符合“保存即预览”的直觉。
4. **编译错误**: 引入新图标时缺少依赖导入。

## 2. 详细变更内容

### 2.1 渲染引擎修正 (Rendering Engine Fixes)
- **文件**: `src/components/CHD/Section.tsx`, `src/components/CHD/CHDRenderer.tsx`
- **属性清洗**: 在 `Section.tsx` 渲染层增加了强制清洗逻辑 `title.replace('## ', '').replace(/\{.*?\}/g, '').trim()`，确保标题纯净。
- **分割线重构**:
  - **移出**: 将分割线渲染逻辑从 `Section` 组件内部移出。
  - **上提**: 在 `CHDRenderer.tsx` 的主渲染循环中实现分割线逻辑。
  - **规则**: `index < sections.length - 1`，确保仅在分区之间渲染，且严格遵循前一个分区的 `show-divider` 属性。

### 2.2 交互逻辑优化 (Interaction Optimization)
- **文件**: `src/components/InteractivePost.tsx`
- **保存即退出**: 更新 `handleSave` 方法。
  - **旧逻辑**: 仅执行保存请求，保持 `isEditing = true`。
  - **新逻辑**: 保存成功后立即执行 `setIsEditing(false)`，自动切换回预览模式。
- **视觉反馈**: 配合之前的 `saveSuccess` 状态，现在用户点击保存后会看到“成功对勾”并自动退出编辑器，体验更加流畅。

### 2.3 代码质量修复 (Code Quality)
- **文件**: `src/app/editor/page.tsx`
- **依赖修复**: 补全了 `clsx` 工具库和 `Check` 图标的导入，解决了 `npx tsc` 编译报错。

## 3. 验证结果
- **渲染**: 分区标题不再显示 `{...}`；多个分区之间（如第2-3、3-4之间）正确显示了分割线。
- **交互**: Ctrl+S 或点击保存按钮后，编辑器正确关闭，页面刷新为最新预览状态。
- **构建**: 通过 TypeScript 静态类型检查。
