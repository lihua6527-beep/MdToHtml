# 2026-02-26 开发记录：状态锁定与交互优化

## 1. 概览
今日主要完成了文档状态逻辑的简化与锁定，以及一系列交互与导航的优化。重点解决了用户对于文档状态管理的痛点，并清理了主页面冗余功能。

## 2. 核心变更

### 2.1 文档状态逻辑简化 (Status Logic Simplification)
- **简化状态**: 废弃了 `pending`, `modified`, `done` 的复杂流转，简化为 `incomplete` (未完成) 和 `completed` (已完成)。
- **状态锁定**: 移除了“编辑自动触发未完成”的逻辑。已完成的文档在修改内容时保持“已完成”状态，必须由用户主动点击切换。
- **持久化交互**: 将状态切换按钮移出编辑模式限制，常驻显示在顶部工具栏。点击按钮立即触发 `saveFile` 并更新 Frontmatter，无需进入编辑模式即可标记文档状态。

### 2.2 交互与导航优化 (UX Improvements)
- **回退机制**: 在编辑器顶部增加 `<ArrowLeft />` 按钮，支持一键返回主页。
- **主页精简**: 移除了 `DocumentList` 底部的“进入编辑器”按钮，强化“基于现有文档工作”的流程。
- **全局设置**: 将设置入口从右上角移至左下角，并实现上拉菜单交互，提升了设置功能的发现性和易用性。
- **布局优化**: 优化了 `BottomToolbar` 左侧 Tab 栏的垂直布局与分割线。

## 3. 文档更新
- **已完成功能清单**: 更新了上述所有完成项。
- **待扩展功能池**: 清理了已完成项，并将“所见即所得编辑器”独立为专项计划。
- **新计划书**: 创建 `docs/计划书/Markdown编辑器革新计划.md`，详细规划了未来的编辑器重构路线。
