# 2026-02-27 文件管理修复与 SWR 优化 开发记录

## 背景
- 文档列表“容量显示”与回收站“恢复”在 API 响应结构升级后出现失效
- 目标是在不引入高风险架构改造的前提下，先完成低风险高回报的规范化与一致性修复

## 完成内容
- 统一类型与常量
  - 抽离并统一 `FileItem` / `TrashItem` / `ApiResponse<T>` 等类型到 [file-system.ts](file:///c:/Users/86171/Desktop/MdToHmtl/MdToHtml/src/types/file-system.ts)
  - 抽离并集中管理容量与路径相关常量到 [constants.ts](file:///c:/Users/86171/Desktop/MdToHmtl/MdToHtml/src/lib/constants.ts)
- 修复：容量显示失效
  - 统一按 `ApiResponse<T>` 解析容量接口返回值
  - `DocumentList` 改为通过 `useCapacity()` 同步容量设置与展示，避免手写 fetch 造成的不一致
- 修复：回收站恢复失效
  - 修正 restore 路由对 `TrashManager` 的调用方式，恢复接口返回 `ApiResponse`
  - restore 成功后触发 `MetadataCacheManager.scanAndSync()`，保证列表能立即发现恢复文件
- 方案 A：前端数据流 SWR 化
  - 新增 `useFiles/useCapacity/useTrash` 三个 Hook，统一缓存策略与刷新方式
  - 回收站恢复/删除后通过 `mutate('/api/files')` 与 `mutate('/api/config/capacity')` 触发联动刷新，消除“恢复后列表不更新/容量不变”的体验问题
