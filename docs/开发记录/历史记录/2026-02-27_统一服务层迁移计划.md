# 统一服务层迁移计划

## 目标
- 解耦 API 调用与 React Hooks 及组件。
- 集中错误处理与类型定义。
- 提高可测试性与可维护性。
- 从文件系统操作开始渐进式迁移。

## 架构
- **服务层**: `src/services/`
  - `core/ApiClient.ts`: 基于 `fetch` 的基础 HTTP 客户端封装。
  - `FileService.ts`: 文件操作（列表、删除、上传）。
  - `TrashService.ts`: 回收站操作（列表、恢复、清空）。
  - `ConfigService.ts`: 配置与容量操作。
- **Hooks 层**: `src/hooks/`
  - 更新 `useFileSystem.ts` 使用服务层而非原生 `fetch`。

## 实施步骤
1.  **创建服务结构**:
    -   创建 `src/services/core/ApiClient.ts`。
    -   创建 `src/services/FileService.ts`。
    -   创建 `src/services/TrashService.ts`。
    -   创建 `src/services/ConfigService.ts`。

2.  **重构 Hooks**:
    -   更新 `src/hooks/useFileSystem.ts` 中的 `useFiles` 使用 `FileService`。
    -   更新 `src/hooks/useFileSystem.ts` 中的 `useTrash` 使用 `TrashService`。
    -   更新 `src/hooks/useFileSystem.ts` 中的 `useCapacity` 使用 `ConfigService`。

3.  **验证**:
    -   验证文件列表、删除、回收站列表、恢复及容量显示。
    -   运行 `npx tsc --noEmit` 确保类型安全。
    -   运行 `npm run lint` 检查代码风格问题。

## 回滚计划
-   撤销对 `src/hooks/useFileSystem.ts` 的更改。
-   删除 `src/services` 目录。
