## 12. 前端架构范式演进分析

### 12.1 背景：为什么早期架构显得“凌乱”？
- 组件内部充斥着大量的 `fetch` 调用。
- 状态更新依赖手动刷新（`window.location.reload()` 或 `router.refresh()`）。
- 错误处理分散在各个 `try-catch` 块中。

### 12.2 演进：为什么分层架构（Service + SWR）能提升稳定性与效率？
- **关注点分离**: UI 层负责渲染，服务层负责通信，状态层负责缓存。
- **统一的副作用管理**: 统一处理错误、请求拦截等。
- **状态自动同步**: 从命令式转向声明式，自动触发更新。

### 12.3 架构范式总结：从“脚本式”到“系统化”
- **数据获取**: 从组件内直接 `fetch` 到封装 `Service` + `useSWR`
- **状态同步**: 从手动刷新到自动变异/响应式流
- **错误处理**: 从 `console.error` 到统一拦截器/Toast/Error Boundary
- **类型安全**: 从 `any` 到严格 TypeScript 接口定义
- **复用性**: 从复制粘贴到组合式 Hooks/高阶组件
