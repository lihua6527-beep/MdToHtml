## 2. 容量显示更新修复

### 2.1 问题描述
用户反馈容量显示的更新没有自动触发，需要手动更新后才能恢复一致。

### 2.2 问题分析
经过代码分析，发现问题出在 `SettingsPanel.tsx` 中的 `handleUpdateCapacity` 函数：
- 该函数调用的是 `ConfigService.updateConfig` 方法
- 而 `ConfigService.updateConfig` 不会更新容量缓存
- 导致容量显示不会自动更新

### 2.3 解决方案
修改 `SettingsPanel.tsx` 中的 `handleUpdateCapacity` 函数，将其改为调用 `ConfigService.updateCapacityLimit` 方法：

```typescript
// 修改前
const handleUpdateCapacity = async (limit: number) => {
  const success = await ConfigService.updateConfig({ capacityLimit: limit });
  if (success) {
    fetchInfo(); // Refresh config display
    notifyPathsUpdated(); // Refresh document list
  } else {
    alert('设置失败');
  }
};

// 修改后
const handleUpdateCapacity = async (limit: number) => {
  const success = await ConfigService.updateCapacityLimit(limit);
  if (success) {
    fetchInfo(); // Refresh config display
    notifyPathsUpdated(); // Refresh document list
  } else {
    alert('设置失败');
  }
};
```

### 2.4 修复效果
- `ConfigService.updateCapacityLimit` 会调用 `mutate(QUERY_KEYS.CAPACITY)` 来更新容量缓存
- 同时，`handleUpdateCapacity` 函数仍然会调用 `notifyPathsUpdated()` 来触发 `app-paths-updated` 事件
- 这会让 `DocumentList` 组件调用 `refreshCapacity()` 来刷新容量显示

### 2.5 验证结果
- 启动开发服务器，运行在 http://localhost:3001
- 打开预览，确认没有错误
- 测试容量更新功能，确认容量显示能够自动更新

### 2.6 技术细节
- **修改文件**：`src/components/SettingsPanel.tsx`
- **修改函数**：`handleUpdateCapacity`
- **涉及服务**：`ConfigService.updateCapacityLimit`
- **缓存更新**：使用 SWR 的 `mutate` 方法更新容量缓存
- **事件触发**：通过 `app-paths-updated` 事件触发文档列表和容量显示的刷新
