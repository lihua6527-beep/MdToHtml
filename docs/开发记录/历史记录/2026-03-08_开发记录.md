## 修复文档分类被错误更改为"项目"的问题

### 问题描述
当更改网页内容后，文档分类会被自动重置为"项目"类型，而不是保持用户之前设置的分类。

### 根本原因
经过分析代码，发现问题出在 `useDocumentState.ts` 文件中的 frontmatter 解析逻辑。当解析 frontmatter 时，如果 `type` 字段不存在，就会默认设置为 'project'。

### 修复过程

#### 1. 修改 useDocumentState.ts 中的文档类型设置逻辑
- **修改文件**: `MdToHtml/src/hooks/useDocumentState.ts`
- **修改位置**: 第160行和第204行
- **修改内容**: 将 `documentType.current = frontmatter.current.type || 'project';` 改为条件判断，只有当 frontmatter 中存在 type 字段时才更新文档类型，否则保持之前的类型。

#### 2. 增强 updateFrontmatter 函数的健壮性
- **修改文件**: `MdToHtml/src/hooks/useMarkdownInteraction.ts`
- **修改内容**:
  - 保存现有的 type 字段值
  - 在创建新 frontmatter 时保留现有的 type 字段
  - 在更新 frontmatter 时跳过 type 字段，除非明确要更新它

### 验证结果
通过创建测试文件模拟各种场景，验证了修复效果：

1. **内容更新场景**: 修改文档内容后，文档类型保持不变
2. **无 type 字段场景**: 当 frontmatter 中没有 type 字段时，保持之前的文档类型
3. **frontmatter 解析失败场景**: 当 frontmatter 格式错误时，保持之前的文档类型

测试结果显示，文档类型在所有场景下都能正确保持，不会被重置为"项目"。

### 技术细节

#### 修复原理
- **核心问题**: 之前的代码在每次解析 frontmatter 时，如果 `type` 字段不存在，就会默认设置为 'project'。
- **修复方案**: 修改解析逻辑，只有当 frontmatter 中明确存在 `type` 字段时才更新文档类型，否则保持之前的类型。
- **额外增强**: 确保 `updateFrontmatter` 函数在更新其他字段时不会影响 `type` 字段。

#### 影响范围
- 修复仅影响文档类型的处理逻辑，不会影响其他功能
- 保持了向后兼容性，确保现有文档的行为不变
- 增强了代码的健壮性，减少了意外的文档类型变更

### 修复成果
通过这次修复，用户在编辑文档内容时，文档分类将不再被意外重置为"项目"类型，而是保持用户之前设置的分类，从而提高了用户体验。
