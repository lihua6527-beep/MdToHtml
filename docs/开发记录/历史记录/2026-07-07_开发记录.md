# 2026-07-07 开发记录

## 一、构建错误修复

### 修复的5处类型错误

1. **jest.setup.ts** — `global.mockToast` 隐式 `any` 类型导致编译失败
   - 添加 `declare global { var mockToast: (() => void) | undefined; }` 全局类型声明
   - 同时修复 `TextEncoder`/`TextDecoder` 的 `global` 赋值类型问题

2. **clear-export/route.ts** — strict mode 下 try 块内不允许函数声明
   - `function deleteExportFiles(dir: string) { ... }` → `const deleteExportFiles = (dir: string) => { ... };`

3. **Card.tsx** — 对象字面量重复键 `network` 和 `settings`
   - 第111行和第220行同时定义了 `network`，第120行和第221行同时定义了 `settings`
   - 删除末尾重复条目（第220-221行）

4. **InteractivePost.tsx** — `CHDBlock` 类型无 `blockIndex` 属性
   - `.find(block => ...)` → `.findIndex(block => ...)`，直接获取数组索引而非对象属性

5. **next.config.js** — `output: 'export'` 被注释导致静态构建不生成 `out` 目录
   - 根据 `NEXT_EXPORT` 环境变量动态启用 `output: isExport ? 'export' : undefined`

### ENOTDIR 路径冲突修复

`src/app/api/app-info/route.ts` 和 `src/app/api/app-info/chd-protocol/route.ts` 共享路径前缀，Next.js 静态导出时先创建文件 `out/api/app-info`，然后试图在同一路径下创建子目录，导致 `ENOTDIR` 错误。

**解决方案**：重构为 `/api/app`、`/api/app/chd-protocol`、`/api/app/chd-protocol/icons`
- 删除 `app-info/` 目录
- 新建 `app/` 目录（含 `route.ts` 和 `chd-protocol/` 子目录）
- 更新 `query-keys.ts`、`SettingsPanel.tsx`、`PathSettingsPanel.tsx` 中的前端引用

## 二、启动脚本修复

### start.bat 闪退根因

`setup-port.js` 中 `wait-on` 失败后走 try-catch 分支只注册了 `setTimeout(openBrowser, 1500)`，但 Node 事件循环无活跃句柄直接退出 → CMD 窗口关闭。

**修复**（`setup-port.js` 完全重写）：
- 移除 `wait-on` 依赖 → 改为原生 `http.get` 轮询 `/api/files`（每秒一次，最多60秒）
- 端口范围 3000-3100（并行扫描）
- 传入 `BROWSER=none` 环境变量阻止 Next.js 重复打开浏览器
- `server.on('close')` 回调中显式调用 `process.exit()` 确保 CMD 不闪退

### build_static.bat 中文乱码

批处理文件中的 UTF-8 中文在 Windows CMD（默认 GBK 代码页）中显示为乱码且被解析为命令。

**修复**：全英文重写，移除所有中文字符和 `chcp 65001` 代码页切换。

## 三、代码一致性重构（屎山代码清理）

### P0-1: lineIndex vs blockIndex 命名统一

`CHDRenderer.tsx` 的回调参数命名为 `lineIndex`，但其他所有文件（`Section.tsx`、`LayoutStrategies.tsx`、`useDocumentState.ts`、`useMarkdownInteraction.ts`）都使用 `blockIndex`。同一值被赋予两个语义，导致理解混乱。

**修复**：
- `CHDRenderer.tsx` 接口定义：`lineIndex` → `blockIndex`（6处）
- `InteractivePost.tsx` 回调参数名：`lineIndex` → `blockIndex`（3处）

### P0-2: Card.tsx 图标映射 130 行重复代码

Card.tsx 的 `getIconComponentSync()` 函数内嵌了一个 130 行的 `iconMap` 对象（使用 `require('lucide-react').Xxx`），与 `lib/icon-manager.ts` 中的 `ICON_CONFIG` 是镜像副本，需要双倍维护。

**修复**：
1. 删除 Card.tsx 中的内联 `getIconComponentSync` 函数定义（140行 → 1行注释）
2. 改为从 `lib/icon-manager` 导入 `getIconComponentSync`（已有导入，只需删除局部覆盖）
3. `lib/icon-manager.ts` 实现真正的同步获取（含缓存）——从之前的 `return null` 改为 `require('lucide-react')` + `componentCache` Map
4. 补充 icon-manager 中缺失的 30+ 图标定义
