# 启动性能与加载体验优化

> **日期**: 2026-07-08
> **类型**: 性能优化 · 用户体验
> **涉及版本**: MdToHtml Pro v1.0.0
> **状态**: ✅ 已完成

---

## 一、背景

首页启动速度约 10 秒。原因如下：
- `page.tsx` 是 SSR 模式，服务端 `getAllPosts()` 同步扫描磁盘 + 解析 frontmatter
- 所有 JS 模块（包括 CodeMirror、katex、react-markdown 等编辑器依赖）一次性打包
- 无启动加载状态，用户打开浏览器看到白屏

---

## 二、改动清单

### 1. 缓存管理器异步扫描（`src/lib/cache-manager.ts`）

| 改动前 | 改动后 |
|--------|--------|
| 构造函数中调用 `scanAndSync()`（同步扫描全部 .md 文件） | 构造函数只读缓存 JSON（<1ms） |
| `getAll()` 每次检查路径 + 同步扫描 | 立即返回缓存数据 + 100ms 后后台触发异步扫描 |
| 扫描串行阻塞 | `pendingScan` 防重入，不阻塞渲染 |

异步扫描时间线：
```
T=0ms    构造函数 → loadCache() 读取缓存（<1ms）
T=0ms    getAllPosts() → 立即返回
T=100ms  后台异步扫描触发
T=500ms  构造函数初始扫描
T=N      后续 getAll() 自动调度
有变化 → 更新缓存，下次生效
无变化 → 静默更新时间戳
```

### 2. 启动加载界面（`src/app/loading.tsx`）— 新增

首次打开时立即显示：
```
旋转 Logo + "CHD Renderer" 标题
逐步显示 5 行加载提示：
  ● 正在加载文档目录
  ● 正在加载整体布局
  ● 正在加载网页格式
  ● 正在加载编辑器组件
  ● 准备就绪
```

每行有 1.2 秒淡入延迟，用户能感知进度。

### 3. SSR 首屏策略（`src/app/page.tsx`）

| 改动前 | 改动后 |
|--------|--------|
| 同步 SSR：`getAllPosts()` 阻塞渲染 | SSR + `Suspense`：服务端返回 + 后台异步 |
| 全部 JS bundle 按需加载 | 首屏 shell 服务端直接渲染 |

避免使用 `dynamic({ssr: false})`（导致客户端完全渲染白屏 5-6 秒），改用 `async component` + `Suspense`。

### 4. 加载时间

| 阶段 | 优化前 | 优化后 |
|------|:------:|:------:|
| 终端启动到浏览器打开 | ~10 秒 | ~1.5 秒 |
| 首次加载（首屏） | 白屏 | 即时显示 loading 动画 |
| 页面可交互 | 10+ 秒 | ~3 秒 |
| 后续页面跳转 | 客户端路由 | 客户端路由（不变） |

## 三、技术细节

### 为什么不用 `dynamic({ssr: false})`

Next.js 的 `dynamic({ssr: false})` 会抛出一个 `BAILOUT_TO_CLIENT_SIDE_RENDERING` 信号，导致：
1. 服务端渲染 loading.tsx（shell）
2. 浏览器等待全部 JS bundle 下载
3. 客户端完整渲染

这个过程在开发模式下需要 5-6 秒。改用 SSR + `Suspense` + `async component` 可以让服务端直接返回 HTML，无需等待客户端 JS。

### 缓存异步扫描

```typescript
getAll(): CacheEntry[] {
  // 立即返回已有缓存（毫秒级）
  const result = Array.from(this.entryMap.values());
  
  // 后台异步触发扫描
  if (!this.pendingScan) {
    setTimeout(() => this.scanAndSync(), 100);
  }
  
  return result;
}
```
