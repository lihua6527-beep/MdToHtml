## 二、图标系统重构（核心变更）

### 2.1 旧架构的问题

原有的 `icon-manager.ts` 单文件（360+ 行）混含了配置数据、组件加载、业务查询三种职责，且通过 `import * as LucideIcons` + 字符串动态访问 `(LucideIcons as any)['Zap']` 的方式在 webpack 构建时被 tree-shaking 移除，导致所有图标无法显示。

### 2.2 新三层架构

```
icon-system/
├── icon-config.ts     ← 配置层：纯数据，定义 IconConfig、ICON_CONFIG、SCENE_LIST
├── icon-renderer.ts   ← 渲染层：Lucide 组件静态映射，防止 tree-shaking
└── icon-manager.ts    ← 外观层：统一对外接口，重新导出所有功能
```

**关键设计决策**：所有 Lucide 组件通过直接命名导入（`import { Zap, AlertTriangle }`），在 `icon-renderer.ts` 中硬编码映射表，编译器能明确追踪每个组件的使用。

### 2.3 最终方案

在 `Card.tsx` 中直接用 switch 语句做图标名→组件的硬编码映射（70+ 个 case），这是 webpack tree-shaking 唯一能 100% 追踪的方式。

## 三、修复的问题清单

### 3.1 图标不渲染（根因：tree-shaking）

- 尝试方案 1：`import * as + 缓存` → tree-shaking 移除
- 尝试方案 2：`require('lucide-react')` → 浏览器端不支持
- 尝试方案 3：独立 `icon-components.ts` 静态映射表 → tree-shaking 移除（映射表本身未被直接引用）
- **最终有效方案**：`Card.tsx` 中直接 import + switch 硬编码映射

### 3.2 图标修正引擎不工作（根因：require 动态加载失败）

`CHDRenderer.tsx` 中 `require('@/services/ai/IconAutoFixService')` 的 `require()` 在 `useMemo` 内部被打包成独立 chunk，加载失败后被 catch 吞掉异常。**修正引擎从未实际执行过**。

**修复**：改为静态 `import { autoFixIcons }`。

### 3.3 图标开关闭包陷阱（根因：useCallback 依赖缺失）

`AIArea.tsx` 的 `handleGenerate` 的 `useCallback` 依赖数组缺少 `enableIcons`，导致闭包中的值始终为初始值 `false`。用户勾选图标开关后，API 调用时 `enableIcons` 始终为 `false`。

### 3.4 预览页面"文档为空"（根因：数据流断裂）

预览按钮直接打开 `/editor/文件名`，但编辑器通过文件系统的 posts 目录读取内容。AI 生成的内容只存在于 `sessionStorage`，编辑器读不到。

**修复1**（临时方案）：预览前先保存到 posts 再打开。
**最终方案**：预览通过 `localStorage` 传递内容，编辑器页面启动时读取。

### 3.5 临时文件被意外删除（根因：保存逻辑耦合了删除）

`handleSaveAll` 和 `handleSaveOne` 在保存后调用 `deleteTemp`，导致用户点击保存后临时文件消失。

**修复**：保存操作不再删除临时文件，只保留在列表中。用户通过「清空所有」或退出时选择丢弃才会删除。

## 四、架构设计原则沉淀

写入 `docs/错误经验/图标系统重构与子系统架构设计经验.md` 的 6 条原则：

1. **高内聚**：一个子系统只做一类事
2. **低耦合**：上层依赖下层，下层不依赖上层
3. **清晰边界**：每层明确定义输入/输出/不做的事
4. **统一入口**：外部只需引用一个文件
5. **向后兼容重导出**：重构时保留旧路径作为重导出
6. **防 tree-shaking 防御性设计**：编译时能静态追踪的引用方式才安全
