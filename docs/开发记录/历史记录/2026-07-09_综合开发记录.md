## ② 首页加载性能优化

### 背景
首页加载存在 2-3 秒白屏，主要是三个层次的问题叠加。

### 解决方案（三层渐进式）

| 层次 | 问题 | 解决方案 | 涉及文件 |
|:----|:-----|:--------|:--------|
| Suspense | fallback={null} 导致白屏 | 替换为 `<PageLoading />` 旋转加载 | `page.tsx` |
| CSS loading | CSSOM 未就绪时 CSS 动画不生效 | SVG `<animateTransform>` 替代 CSS `@keyframes` | `layout.tsx` |
| Lazy compilation | 首次访问需实时编译 | 预热首页路由（先 `httpGet` 再开浏览器） | `setup-port.js` |

### 关键发现
CSS 动画依赖 CSSOM，CSSOM 依赖外部 CSS 文件加载完成；而 SVG `<animateTransform>` 嵌入在 HTML 中，在 HTML 解析阶段即可启动。这个认知差异是问题的根本原因。

### 产出文档
- `docs/经验总结/首页加载白屏与首屏加载优化经验.md` — 详细的性能优化知识沉淀

## ③ 图标系统重构 + AI 图标修复

### 背景
原有 `icon-manager.ts` 使用 `import * as LucideIcons` + 字符串动态索引的方式，被 webpack tree-shaking 移除所有图标，导致图标无法显示。

### 重构架构

```
icon-system/
├── icon-config.ts     ← 配置层：纯数据
├── icon-renderer.ts   ← 渲染层：Lucide 硬编码映射（防 tree-shaking）
└── icon-manager.ts    ← 门面层：统一对外接口
```

### 修复的 Bug

| Bug | 原因 | 修复 |
|:----|:-----|:-----|
| 图标不渲染 | `import * as` + 字符串索引被 tree-shaking | `Card.tsx` 改用 `import { Zap }` + `switch` 硬编码映射 |
| 图标自动修复功能不生效 | `require()` 在 `useMemo` 内导致动态 chunk 加载失败 | 改为静态 `import { autoFixIcons }` |
| 图标开关闭包陷阱 | `handleGenerate` 的 `useCallback` 依赖数组缺 `enableIcons` | 补全依赖 |
| 预览页"文档为空" | 临时文件没保存到服务端 | 新增 temp file 保存链路 |

### 架构原则（产出文档）
`docs/经验总结/图标系统重构与系统架构设计经验.md` 记录了 6 条架构原则：
1. **单一职责** — 一个模块只有一件事
2. **单向依赖** — 上层依赖下层，下层不依赖上层
3. **明确边界** — 每个模块有清晰的创建/查询/修改职责
4. **统一出口** — 外部只通过一个文件访问
5. **当前模块为锚点** — 重构时以当前模块路径为锚点
6. **对 tree-shaking 友好的代码** — 运行时能被静态追踪的引用才安全

## ④ 临时文件预览与保存系统

### 背景
AI 生成的内容需要预览后才能正式保存，预览时需要通过服务端传递文件内容，旧方案用的 `sessionStorage` 经常丢失。

### 实现

| 组件 | 文件 | 功能 |
|:----|:----|:-----|
| TempFileManager | `src/services/ai/TempFileManager.ts` | 临时文件 CRUD 管理 |
| API 组 | `/api/save-temp` `/api/load-temp` `/api/confirm-save` | 服务端临时文件持久化 |
| 预览路由 | `preview/[slug]/page.tsx` + `PreviewClient.tsx` | 预览页同时支持正式文件和临时文件 |
| AIArea 集成 | `AIArea.tsx` 预览按钮 | 生成 → save-temp → 打开预览 |

### 关键设计
- 临时文件与正式文件共用同一个预览路由，通过 `__temp__` 前缀区分
- `confirmSave` 操作将临时文件转为正式文件并清理临时文件
- 保存操作不删除临时文件（用户可能在列表中对同一个文件多次操作）

## ⑤ AI 配置面板全链路实现 💡 **本日最复杂模块**

### 背景
原本的 AI 配置面板只是一个占位符，输入框是 disabled 的，提示用户手动编辑 `.env.local`。需要实现完整的 UI 配置面板 + 惰性覆盖热加载。

### 技术选型讨论（2 轮）

| 轮次 | 方案 | 结论 |
|:----|:-----|:----:|
| 第一轮 | 每次 AI 请求动态从 `.env.local` 读取 | → 否决（99% 场景无意义 I/O） |
| **第二轮** | **惰性覆盖模式（Lazy Override）** | → **通过 🏆** |
| | 默认走 process.env（零 I/O），修改时设 overrideValue + 写入文件 | |

### 惰性覆盖设计

```
未修改路径（99%）：ApiKeyManager.get() → process.env.DEEPSEEK_API_KEY → 零 I/O
已修改路径（1%）：  ApiKeyManager.get() → overrideValue → 零 I/O（仅保存时写 1 次文件）
重启后：           process.env 自动加载已持久化的新 Key
```
