| stage 结构 | `- stage:` → 内层 `name/displayName/steps` | `- name: … / displayName: … / steps: …`（扁平，`stages[i].steps` 直接可见） |
| 步骤数量 | 2 阶段 / 7 步骤（含独立"环境自检""安装依赖"步骤） | 2 阶段 / **2 步骤**（每个阶段 1 个 `shell@1`，命令串在 `run` 内） |
| 失败传播 | 无保障（任一步失败可能不红） | `run` 首行 `set -e`，任一命令失败即步骤失败 |
| 变量层 | `variables: { MDTOHTML_DIR: 'MdToHtml' }` | **移除**（路径内联为 `MdToHtml`），减少未知字段的校验风险 |
| 校验 | — | js-yaml 解析通过：`stages[0].steps` 存在且为数组、无 `stage:` 包裹层、无 `variables` |

**仍未验证**：step 条目本身（`step: shell@1` + `inputs.run`）是否被 Gitee 接受；stage 层是否需要 `stage:` 键；`pull_request` 触发键名（当前不含）。
**待办**：在页面保存/运行后把结果或报错贴回，据此再做一轮校正（命令部分不变）。

## Gitee 流水线 schema 定稿 + 自检（2026-09-14 第五批）

**触发**：页面报 `[插件类型不存在] 位置: stages[0].steps[0].step - 不支持的插件类型: shell@1`，同时用户贴出页面自带的 Maven 模板 → 从此确定 Gitee 流水线的真实 schema。

### 一、schema 定稿（全部由「页面模板 + 页面报错」实测，非推测）

| 层级 | 结论 |
|------|------|
| 文件 | `.workflow/<流水线名>.yml`，**文件名 = 流水线名**；页面创建流水线时会自动生成（内容为默认模板，如 Maven 版） |
| 顶层必填 | `version: "1.0"`、`name`、`displayName`、`triggers`、`stages` |
| 顶层可带 | `notify: []`、`strategy: { blocking: true }` |
| 触发 | `triggers.push.branches.prefix: [...]`（**前缀匹配**，非 `include`） |
| stage | **扁平**：`name` / `displayName` / `strategy: naturally` / `trigger: auto` / `steps` |
| step | **插件 id** `<动作>@<工具>`：`ut@maven`、`build@maven`、`publish@general_artifacts`、`publish@release_artifacts`、`deploy@agent`；本流水线用 **`build@nodejs`** |
| step 字段 | `step` / `name` / `displayName` / `nodeVersion` / **`commands:` 列表** / `checkpoints: {}` / `settings: []` / `caches: []` / `notify: []` / `strategy(resource.cpu/memory)` |
| ❌ 不存在的写法 | ① `shell@1`（插件类型不存在）② `stages[i].stage.steps` 嵌套（报 `配置结构错误`）③ `inputs: { run: … }`（Gitee 用 `commands`） |

## 报错获取通道 + 本地 pre-push 门禁（2026-09-14 第六批）

**背景**：用户提问「怎么收到报错」→ 落地**三层报错获取通道**，其中"本地拦截层"已完成实现与实测。

### 一、新增文件

| 文件 | 作用 |
|------|------|
| `.githooks/pre-push` | 推送前运行 `cd MdToHtml && npm run verify`（= Gitee「门禁」阶段 / GitHub build job 的等价命令）；失败则**阻断推送**并打印 `❌ 门禁未通过（EXITCODE=…）`；未找到 npm 时优雅跳过（CI 仍会检查） |
| `scripts/install-git-hooks.bat` | 一键启用：`git config core.hooksPath .githooks` |
| `.gitattributes` | 强制 `.githooks/*` 与 `*.sh` 使用 **LF**（本机 `core.autocrlf=true`，否则钩子被转成 CRLF 会导致 `bad interpreter`） |

### 二、实测（2026-09-14）

| 检查 | 方法 | 结果 |
|------|------|------|
| 语法 | `sh -n .githooks/pre-push` | ✅ 退出码 0 |
| npm 可见性 | Git Bash `command -v npm` | ✅ `/d/software/npm` |
| 成功路径 | 替身 npm（exit 0）模拟 git 调用 | ✅ 输出 `✅ 本地门禁通过`，退出码 **0** |
| 失败路径 | 替身 npm（exit 1）模拟 git 调用 | ✅ 输出 `❌ 门禁未通过（EXITCODE=1），已阻断本次推送`，退出码 **1** |
| 安装状态 | `git config core.hooksPath` | ✅ `.githooks`（本机已生效） |
| 索引权限位 | `git ls-files -s .githooks/pre-push` | ✅ `100755`（可执行） |
