# AI 服务层配置与容错增强计划

> **创建日期**: 2026-07-10 | **优先级**: P2 | **状态**: 计划中

---

## 一、背景与问题

通过系统审计发现 AI 服务层存在 3 个主要问题：

### 1.1 API Key 配置无校验

当前 `SettingsPanel.tsx` 中的 AI 配置面板仅显示 DEEPSEEK_API_KEY 的状态，但：
- 没有前端格式校验（DeepSeek API Key 以 `sk-` 开头，长度约 32 字符）
- 用户输入格式错误的 Key 时，直到调用 AI 请求时才会收到通用错误
- 首次使用时没有友好引导（"请先配置 API Key"）

### 1.2 错误处理缺乏用户友好提示

`AIService.ts` 虽然有退避重试机制，但重试耗尽后：
- 仅抛出通用 JavaScript Error
- 没有针对不同 HTTP 状态码的中文错误提示
- 401（Key 无效）/ 403（权限不足）/ 429（限流）/ 500（服务端错误）全部显示同一错误信息

### 1.3 Prompt 硬编码

`PromptEngine.ts` 中两个 Prompt 模板（默认版/学术版）约 400 行直接硬编码在代码中：
- 修改 Prompt 需要重启整个应用
- 无法快速切换或实验不同 Prompt 版本
- 用户无自定义 Prompt 的能力

## 二、方案设计

### 2.1 API Key 配置增强

| 项目 | 说明 |
|:-----|:------|
| **前端格式校验** | 在 `SettingsPanel.tsx` 的 API Key 输入框中增加 `onChange` 校验，实时检测格式 |
| **校验规则** | 正则匹配 `/^sk-[a-zA-Z0-9]{32,}$/` |
| **未配置引导** | 在 `AIArea.tsx` 顶部增加"未配置 API Key"的提示条 + 跳转到设置的链接 |
| **配置保存** | 输入校验通过后保存到 `.env.local` 或 localStorage |

**校验逻辑**：
```
用户输入 Key → onInput 实时校验
    ├── 格式正确 → 绿色边框 + ✅ 图标
    ├── 格式错误 → 红色边框 + ⚠️ 提示文字
    └── 空值 → 默认灰色 + 引导文案 "请输入 DeepSeek API Key"
```

### 2.2 错误码友好提示

在 `AIService.ts` 中添加错误码 -> 中文提示的映射表：

| HTTP 状态码 | 含义 | 中文提示 |
|:-----------|:-----|:---------|
| 401 | API Key 无效 | "API Key 无效，请检查设置面板中的 Key 是否正确" |
| 403 | 账户权限不足 | "账户余额不足或权限受限，请检查 DeepSeek 账户" |
| 429 | 请求频率过高 | "请求过于频繁，请稍后重试" |
| 500+ | DeepSeek 服务端错误 | "AI 服务暂时不可用，请稍后重试" |
| 网络超时 | 连接失败 | "网络连接超时，请检查网络后重试" |

**实现方式**：在 `AIService.ts` 的 `generate()` 方法中，catch 块解析 error 对象的 `status` 字段，返回结构化的中文错误信息。

### 2.3 Prompt 外部化

将 Prompt 模板从 `PromptEngine.ts` 中抽取为外部 JSON 文件：

```json
{
  "prompts": {
    "default": {
      "name": "默认版",
      "system": "...",
      "user": "..."
    },
    "academic": {
      "name": "学术版",
      "system": "...",
      "user": "..."
    }
  }
}
```

**文件位置**：`MdToHtml/prompts.json`

**热加载机制**：
- `PromptEngine.ts` 在初始化时读取 `prompts.json`
- 如果文件不存在，fallback 到内嵌的硬编码 Prompt
- 每次调用 `getPrompt()` 时加载最新文件内容（文件小，每次读取无性能影响）
- 用户修改 `prompts.json` 后无需重启应用
