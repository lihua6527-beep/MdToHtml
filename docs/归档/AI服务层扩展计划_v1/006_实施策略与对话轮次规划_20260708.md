# 计划 006：实施策略与对话轮次规划

> **版本**: v1.0
> **日期**: 2026-07-08
> **状态**: ✅ 实施指导 — 开发过程中的路线图
> **关联**: 004 集成方案、Prompt A/B、DeepSeek API 参考、005 决策报告
> **依赖**: 不修改 `HomeClient.tsx`（第82-91行的左侧 DocumentList 区域）

---

## 一、核心开发原则

```
1. 不破坏现有系统
   └── 所有新增代码在独立目录 src/components/AI/ 和 src/services/ai/
   └── 唯一被修改的现有文件是 HomeClient.tsx（最后一轮合并）
   └── HomeClient.tsx 第82-91行的 <DocumentList /> 全程不动

2. 前端优先、后端次之、合并最后
   └── 先用模拟数据验证前端交互完整性
   └── 确认无误后再对接真实后端服务
   └── 最后一步才合并到现有页面

3. 每轮交付可验证的成果
   └── 每轮结束时有一个可运行、可查看的产物
   └── 不遗留"半成品"状态
```

---

## 二、三阶段开发策略

### 阶段一：独立前端开发（不碰后端，不碰现有系统）

| 目标 | 在独立页面 `/ai-input` 搭建完整的 AI 前端交互逻辑 |
|------|---------------------------------------------------|
| 范围 | 纯 UI 组件 + React 状态管理 + 模拟数据 |
| 后端 | ❌ 不调 DeepSeek API，不调任何后端 |
| 数据 | 使用硬编码的模拟数据（mock data）模拟 AI 生成结果 |
| 现有系统 | ❌ 不修改任何现有文件 |

**新增文件**（全部在独立目录，零侵入）：
```
src/app/ai-input/page.tsx          ← 独立页面，后续可废弃
src/components/AI/AIArea.tsx        ← 主容器（最后会移到 HomeClient）
src/components/AI/AIInputPanel.tsx  ← 输入面板
src/components/AI/AITempFileList.tsx ← 结果列表
src/components/AI/AISaveDialog.tsx  ← 退出弹窗
```

### 阶段二：后端服务对接（替换模拟数据为真实 API）

| 目标 | 实现完整的 AI 后端调用链路，替换阶段一的模拟数据 |
|------|---------------------------------------------------|
| 范围 | 服务层代码 + API Route |
| 前端 | 仅替换数据源（模拟数据 → 真实 API 调用），UI 不变化 |
| 现有系统 | ❌ 不修改任何现有文件 |

**新增文件**：
```
src/services/ai/PromptEngine.ts       ← Prompt 模板引擎（含 A/B 两组）
src/services/ai/AIService.ts          ← AI 服务核心
src/services/ai/TempFileManager.ts    ← 临时文件管理器
src/app/api/ai/generate/route.ts     ← AI 生成 API Route
src/types/model-interface.ts          ← AI 类型定义（叠加到现有类型文件）
.env.local                            ← DEEPSEEK_API_KEY
```

**阶段二验收标准**：
- [ ] `POST /api/ai/generate` 返回正确的 CHD Markdown
- [ ] 前端点击「AI 生成」→ 真实调用 API → 结果出现在列表
- [ ] 「换个风格」切换到 Prompt B 重新生成
- [ ] Flash/Pro 模型切换生效
- [ ] `TempFileManager` 使用 sessionStorage 管理多版本
- [ ] 「下载 HTML」→ 调用 `HtmlBundler.bundle()` + `FileService.saveExport()` → 浏览器下载
- [ ] 错误处理：API Key 缺失提示 / 网络错误重试 / Token 超限提示
- [ ] `/preview` 页面可正确渲染 AI 生成的 CHD Markdown

**阶段三验收标准**：
- [ ] 首页 `/` 右侧可切换为 AI 模式
- [ ] 左侧 `DocumentList` 完全不变（UI 和功能）

## 三、预计对话轮次

### 轮次分配总览

```
阶段一：独立前端       3轮  →  约 70% 代码量
阶段二：后端服务       2轮  →  约 25% 代码量  
阶段三：合并           1轮  →  约 5% 代码量
                         ────
                  总计  6轮

## 四、风险与预判

| 风险 | 影响轮次 | 缓解措施 |
|------|----------|----------|
| DeepSeek API 调用失败（Key 无效/网络问题） | 第5轮 | Phase 2 开始时先用手动 curl 验证 API 可用性 |
| `HtmlBundler.bundle()` 在本地环境报错 | 第5轮 | 先参考 ExportButton.tsx 的现有调用方式，确保导入路径正确 |
| `SettingsPanel` 类型扩展与现有逻辑冲突 | 第6轮 | 先读取 SettingsPanel.tsx 完整源码，理解其类型分发机制 |
| `/preview` 页面渲染 AI 生成的 CHD Markdown 异常 | 第3/5轮 | 在 AI 页面内使用 CHDRenderer 组件先本地验证 |
