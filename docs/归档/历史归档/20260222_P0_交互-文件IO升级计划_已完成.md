# P0_交互-文件IO升级计划

## 1. 背景与目标
当前文件路径配置依赖手动修改代码或配置文件，操作繁琐且不直观。为了提升用户体验并适配桌面端使用场景，需实现“默认配置+灵活交互”的文件 I/O 机制。

**核心目标**：
1.  **开箱即用**：无需配置，软件启动即自动识别安装目录下的输入/输出文件夹。
2.  **灵活交互**：支持拖拽文件引入，支持 Web 标准的浏览器下载。
3.  **可配置化**：通过外部配置文件支持路径自定义。

## 2. 需求详情

### 2.1 配置文件与默认路径 (Configuration & Defaults)
- **配置文件**: 引入 `config.json` (或 `.env` 映射)，位于程序运行根目录。
- **默认输入路径**: 默认为 `<安装目录>/input`。
- **默认输出路径**: 默认为 `<安装目录>/output`。
- **目录结构**:
  ```text
  MdToHtml/
  ├── MdToHtml.exe      # 主程序
  ├── config.json       # 配置文件 (可选)
  ├── input/            # 默认存放 Markdown 源码
  └── output/           # 默认存放生成的 HTML
  ```
- **初始化行为**: 系统启动时，后端服务应自动检查并创建这两个文件夹（如果不存在），并扫描 `input` 目录构建初始文件列表。

### 2.2 输入交互 (Input Interaction)
- **自动扫描**: 启动时自动加载默认输入路径下的所有 `.md` 文件到左侧文件列表。
- **拖拽支持**: 用户可将外部 Markdown 文件或文件夹直接拖入编辑器区域。
  - *行为*: 拖入的文件将被添加到当前会话的文件列表中（可视作临时引入），不强制移动文件到 `input` 目录，除非用户执行“另存为”操作。
- **手动选择**: 保留“打开文件夹”按钮，允许用户通过系统对话框选择其他目录。

### 2.3 输出交互 (Output Interaction)
- **本地保存 (Save)**:
  - 点击“保存”时，默认将当前编辑的 HTML 内容写入 `<安装目录>/output` 文件夹。
  - 文件名与输入文件名保持一致（或增加时间戳版本控制）。
- **浏览器下载 (Export/Download)**:
  - 点击“导出”或“下载”时，挂载到浏览器的下载队列。
  - 使用浏览器的默认下载路径（通常为 `Downloads` 文件夹）。
  - 此功能确保在纯 Web 环境或不想污染安装目录时的可用性。

## 3. 技术方案 (详细设计)

### 3.1 路径解析策略 (Path Resolution Strategy)
本系统采用 **“便携优先，配置覆盖，安全兜底”** 的三级路径解析策略，确保在不同环境下的可用性与灵活性。

1.  **Level 1: 配置文件 (最高优先级)**
    - 系统启动时，首先读取程序根目录下的 `config.json`。
    - 若文件中定义了 `inputPath` 或 `outputPath`，直接使用该路径。
    - *适用场景*: 用户自定义数据存储位置（如 NAS、特定工作盘）。

2.  **Level 2: 便携模式 (默认策略)**
    - 若无配置文件或配置项为空，默认使用程序根目录下的 `input` 和 `output` 文件夹。
    - 系统会检测当前目录的 **写权限**。
    - *适用场景*: U盘便携版、解压即用版、开发环境。

3.  **Level 3: 安全兜底 (Fallback)**
    - 若 Level 2 检测到当前目录 **不可写** (如安装在 `C:\Program Files`)，自动降级至用户文档目录。
    - 路径规则: `~/Documents/MdToHtml/input` 和 `~/Documents/MdToHtml/output`。
    - *通知机制*: 此时应在 UI 上弹出提示：“因权限限制，已切换至文档目录存储数据”。

### 3.2 配置文件规范
- **文件名**: `config.json`
- **存放位置**: 与 `.exe` 主程序同级。
- **内容示例**:
  ```json
  {
    "inputPath": "./my_markdowns",  // 支持相对路径 (相对于exe)
    "outputPath": "D:/Work/HTML_Output", // 支持绝对路径
    "autoSave": true,
    "theme": "light"
  }
  ```

### 3.3 混合文件系统交互
- **后端服务 (Electron/Node)**:
  - 负责所有 **持久化** 操作（读取配置、扫描目录、保存文件）。
  - 提供 `GET /api/config` 接口，向前端返回当前生效的路径信息。
- **前端交互 (React)**:
  - **路径展示**: 在侧边栏底部显示“当前工作目录: [路径]”，悬停显示完整路径。
  - **拖拽文件**: 通过 HTML5 Drag and Drop API 读取 `File` 对象。
    - *逻辑*: 拖入的文件仅在内存中临时加载，**不自动复制** 到 `input` 目录，除非用户手动执行“另存为”。
  - **浏览器下载**: 通过 `<a>` 标签的 `download` 属性或 `Blob` 对象 URL 触发，完全绕过后端文件系统，直接保存到用户浏览器的默认下载目录。

### 3.4 状态管理更新
- `appConfig`: 存储从后端获取的配置信息（包含实际生效的 `inputPath`/`outputPath`）。
- `fileList`: 也就是当前的工作区文件列表，来源包含“默认目录扫描”和“拖拽引入”。
- `isReadOnlyMode`: 标识当前工作目录是否只读（用于 UI 提示）。

## 5. 风险与注意
- **相对路径陷阱**: 在 Electron 打包后，`process.cwd()` 的行为可能不符合预期，必须使用 `process.execPath` (exe路径) 作为基准解析相对路径。
- **权限提示**: 兜底机制虽然保证了可用性，但可能让用户困惑（文件去哪了？）。UI 提示必须清晰明确。
