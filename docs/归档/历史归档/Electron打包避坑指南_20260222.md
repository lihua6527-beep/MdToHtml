# Electron 桌面端打包避坑指南与经验总结

> **文档目的**: 记录本项目 (Next.js + Electron Hybrid) 在 Windows 环境下打包过程中遇到的关键问题与解决方案，为后续开发与类似项目提供参考。
> **适用环境**: Windows 11, Node.js v18+, Electron v28+, electron-builder v24+

## 1. 环境与依赖配置陷阱

### 1.1 国内网络环境下的依赖安装
**问题现象**: `npm install` 或 `electron-builder` 打包时，频繁出现 `ECONNRESET` 或 `download timeout`，尤其是 Electron 二进制包和 WinCodeSign 工具。

**解决方案**:
在项目根目录创建 `.npmrc` 文件，强制指定镜像源：
```ini
registry=https://registry.npmmirror.com
electron_mirror=https://npmmirror.com/mirrors/electron/
electron_builder_binaries_mirror=https://npmmirror.com/mirrors/electron-builder-binaries/
```
*注意*: 某些版本的 `electron-builder` 可能需要通过环境变量设置镜像，若 `.npmrc` 无效，尝试在命令行前加 `cross-env ELECTRON_MIRROR=...`。

### 1.2 PowerShell 命令兼容性
**问题现象**: `package.json` 中的脚本使用 `&&` 连接命令（如 `git add . && git commit`），在 Windows PowerShell 中报错。
**解决方案**:
- **推荐**: 使用 `concurrently` 或 `npm-run-all` 管理多任务。
- **临时**: 将命令拆分为独立的 npm script，或在 PowerShell 中手动分步执行。

## 2. 核心代码适配 (Next.js + Electron)

### 2.1 混合架构路径问题 (PathManager)
**核心挑战**:
- **开发环境**: 源码在 `src/`，静态资源在 `public/`，运行在 `localhost:3000`。
- **生产环境 (Packaged)**: 源码被打包到 `resources/app.asar` (或 `resources/app`)，静态资源在 `resources/app/out`。
- **读写权限**: 安装在 `Program Files` 时，应用根目录不可写。

**最佳实践**:
实现 `PathManager` 单例模块，区分 **只读资源路径** 与 **可写数据路径**：
- **AppRoot**: `app.isPackaged ? path.dirname(process.execPath) : process.cwd()`
- **数据存储**: 优先尝试 AppRoot（便携模式），若不可写则回退到 `Documents/MdToHtml`。
- **静态资源**: 生产环境指向 `path.join(__dirname, '../out')`。

### 2.2 ESM 与 CommonJS 的混用冲突
**问题现象**: 后端服务 `server.js` (CommonJS) 引入 `get-port` (v7+ 纯 ESM) 时报错 `require() of ES Module ... not supported`。
**解决方案**:
在 CommonJS 中使用 **Dynamic Import**:
```javascript
// server.js
const startServer = async () => {
  const getPort = (await import('get-port')).default; // 动态导入
  const port = await getPort({ port: 3000 });
  // ...
};
```

### 2.3 窗口白屏与服务启动时序
**问题现象**: Electron 窗口启动后白屏，因为 Express 服务尚未就绪。
**解决方案**:
1.  **主进程等待**: `main.js` 中 `await startServer()` 成功获取端口后再 `createWindow()`。
2.  **优雅显示**: 设置 `show: false`，监听 `ready-to-show` 事件再显示窗口。
3.  **调试技巧**: 开发阶段或初期打包时，在 `ready-to-show` 中调用 `mainWindow.webContents.openDevTools()` 自动打开控制台。

## 3. 构建与打包 (electron-builder)

### 3.1 文件锁定与权限错误 (EPERM / Symlinks)
**问题现象**:
- `EPERM: operation not permitted, unlink ... app.asar`
- `Cannot create symbolic link ... Access is denied`

**根本原因**:
- Windows 文件系统锁定机制（资源管理器、杀毒软件、或之前的进程未完全退出）。
- 符号链接在非管理员权限下可能受限。

**应急与长期方案**:
1.  **彻底查杀进程**: 确保所有 `electron.exe`, `MdToHtml Pro.exe` 进程已关闭。
2.  **修改输出目录**: 若 `dist` 目录被锁死无法删除，临时修改 `package.json` 中的 `directories.output` 为 `release` 或 `release_v2`。
3.  **关闭 ASAR (调试用)**: 设置 `asar: false` 可避免打包成单文件，直接生成文件夹结构，便于排查文件缺失问题，也能规避部分打包时的文件操作错误。
    ```json
    "build": {
      "asar": false,
      "win": { "target": ["dir"] }
    }
    ```

### 3.2 静态资源丢失
**问题现象**: 打包后页面 404，控制台显示找不到 JS/CSS。
**解决方案**:
- 确保 Next.js 配置为 `output: 'export'`。
- 检查 `package.json` 的 `files` 字段，必须显式包含 `out/**/*`：
    ```json
    "files": [
      "electron/**/*",
      "out/**/*",
      "package.json"
    ]
    ```

## 4. 总结

本次桌面端打包探索验证了 **Next.js Static Export + Express (Local API) + Electron** 架构的可行性。通过合理的路径管理和构建配置，成功生成了可在 Windows 上运行的独立安装包。后续工作应集中在自动化构建流程（如 GitHub Actions）与自动更新机制的完善上。
