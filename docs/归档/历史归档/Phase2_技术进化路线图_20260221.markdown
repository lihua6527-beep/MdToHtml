# MdToHtml Phase 2：智能进化与体验升级技术路线图

## 1. 总体目标
从 **“能用”** 到 **“好用、好看、懂你”** 的跨越。
- **数据层**：建立细粒度的“输入-输出-评分”数据飞轮，为训练垂直领域小模型（Layout-LLM）做准备。
- **视觉层**：引入参数化设计系统，确保默认美观（莫兰迪色系），支持高度定制。
- **结构层**：突破基础网格限制，实现 Bento（便当盒）式、非对称式等复杂布局算法。

---

## 2. 核心模块规划

### 方向一：数据闭环与小模型训练准备 (Data Engine)
**核心诉求**：总结细分样本评分，构建高质量数据集。

*   **1.1 细粒度评分系统 (Evaluation System)**
    *   **功能描述**：在预览界面引入“评分/标注模式”。
    *   **实现方案**：
        *   **整体评分**：对单次生成的页面进行 1-5 星打分（维度：结构合理性、美观度、内容匹配度）。
        *   **组件级标注**：允许用户点击某个卡片标记“布局错误”、“颜色不谐”或“完美样本”。
        *   **自动化指标**：引入无头浏览器（Puppeteer/Playwright）计算客观指标（如：屏幕空间利用率、文字溢出率、色彩对比度合规性）。
*   **1.2 语义化数据集构建 (Semantic Dataset)**
    *   **数据结构升级**：扩展 `/api/save-session`，存储格式从 `(Input, Output)` 升级为 `(Instruction, Markdown_Input, Rendered_HTML_Structure, User_Rating, Correction_Log)`。
    *   **样本清洗管道**：编写脚本自动过滤低分样本，保留高分样本作为“黄金数据集”。
    *   **目标**：为未来训练一个“能根据一句话描述自动生成高质量 CHD Markdown”的轻量级模型积累数据。

### 方向二：美学升级与参数化设计 (Aesthetics Engine)
**核心诉求**：定义卡片样式、颜色、字体，保证画面美观。

*   **2.1 动态主题引擎 (Theme Context)**
    *   **设计令牌 (Design Tokens)**：将硬编码的 Tailwind 类提取为 CSS 变量（颜色、圆角、阴影、间距）。
    *   **预设主题库**：内置 3-5 套经过设计师调优的主题（例如：`Morandi-Default` 莫兰迪默认, `Academic-Clean` 学术极简, `Dark-Cyber` 暗黑赛博）。
    *   **实现**：使用 React Context + CSS Variables 实现一键换肤，无刷新切换。
*   **2.2 智能排版系统 (Typography System)**
    *   **字体配对**：引入 Google Fonts (Next.js Font Optimization)，定义“标题/正文”黄金配对（如 Serif 标题 + Sans-Serif 正文）。
    *   **动态流体排版**：根据容器宽度自动计算 `font-size` 和 `line-height`，避免大屏字太小、小屏字太挤。
*   **2.3 视觉微调面板**
    *   在编辑器右侧增加“外观设置”面板，允许用户调整全局参数（基础色相、圆角大小、卡片透明度），实时反馈到预览区。

### 方向三：布局多样性与算法增强 (Layout Engine)
**核心诉求**：引入更多风格，突破横/竖铺陈旧模式。

*   **3.1 智能网格算法 (Smart Grid Algorithm)**
    *   **Bento Grid (便当盒布局)**：开发自动填充算法。当用户输入 5 个卡片时，算法自动计算最优的 `col-span` 和 `row-span` 组合（例如：1个大卡片 + 4个小卡片），而不是傻瓜式的一行一个。
    *   **Masonry (瀑布流)**：针对纯文本/图片流，支持非对齐高度的瀑布流布局。
*   **3.2 布局指令集扩展 (Directive Extension)**
    *   扩展 Markdown 头部元数据 (Frontmatter) 或组件属性，支持显式指定布局模式。
    *   例如：`layout-mode: "magazine"` (杂志风), `layout-mode: "dashboard"` (仪表盘风)。
*   **3.3 复合容器组件**
    *   引入 `<Container>` 概念（对应 H2 Section），允许不同的 Section 拥有不同的内部布局策略（Section A 是两栏，Section B 是三栏异形）。

## 3. 执行路线图 (Roadmap)

我们建议按照以下顺序推进，以保证系统的稳定性：

**阶段 1：基础重构与数据埋点 (约 2-3 天)**
1.  **重构样式层**：将现有 Hardcoded Tailwind 类抽离为 CSS 变量（为美观性做底座）。
2.  **数据Schema升级**：修改后端存储逻辑，增加评分字段和元数据字段。
3.  **构建评分UI**：在预览区增加简单的“点赞/点踩”和“保存为样本”按钮。

**阶段 2：布局引擎升级 (约 3-4 天)**
1.  **算法实现**：编写 TypeScript 布局计算函数（输入卡片列表 -> 输出 Grid 坐标）。
2.  **Bento 风格实装**：实现第一种复杂布局“Bento Grid”。
3.  **验证**：使用新的布局生成页面，并使用阶段1的工具进行评分。

**阶段 3：美学打磨与主题化 (约 2-3 天)**
1.  **引入莫兰迪色盘**：配置 Tailwind Config，定义语义化颜色（Primary, Secondary, Surface）。
2.  **字体优化**：集成 `next/font`。
3.  **可视化控制台**：开发前端侧边栏，通过滑块调整视觉参数。
