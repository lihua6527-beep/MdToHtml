# 项目阶段总结与 V1 版本计划书

**日期**: 2026-02-15
**版本**: V1.0 (Release Candidate)
**状态**: 已确认

---

## 1. 阶段工作总结 (Phase Summary)

截止目前，项目已完成 V1 版本的核心开发工作，确立了以 **CHD (Card-based Hierarchical Document)** 协议为核心的文档工程规范，并实现了配套的编辑器与渲染引擎。

### 1.1 核心成就
1.  **协议定型 (CHD v1.3)**:
    -   确立了 `Document > Section > Card` 的三级刚性结构。
    -   实现了基于 Frontmatter 的元数据管理。
    -   **简单并列关系 (Simple Parallelism)**: 通过 `layout="cols-N"` 和 `col-span` 实现了基础的网格布局系统，支持多卡片并列展示。
2.  **编辑器实装**:
    -   **双模式编辑**: 左侧 CodeMirror (源码) + 右侧 CHDRenderer (实时预览)。
    -   **交互式操作**: 支持通过 UI 按钮直接修改卡片属性 (Layout, Color, Style)，并回写至 Markdown 源码。
    -   **状态流转**: 实现了 `pending` -> `modified` -> `done` 的文档状态管理闭环。
3.  **渲染引擎**:
    -   实现了对 CHD 扩展语法 (`{key="value"}`) 的解析与渲染。
    -   支持多种卡片样式 (`normal`, `stat`, `highlight`, `code`, `summary`, `orange`)。
    -   内置了基于 Tailwind CSS 的响应式网格系统。

### 1.2 局限性确认 (V1 Scope)
**V1 版本明确仅支持“简单并列关系”的展示**。
-   **支持**: 标准的 Grid 布局 (1-4 列)，卡片的跨列 (`col-span`) 与跨行 (`row-span`)。
-   **暂不支持**: 复杂的嵌套布局 (Nested Grids)、自由画布 (Free Canvas)、复杂的父子卡片关系。
-   **设计哲学**: 保持结构简单，降低 AI 生成与解析的难度，优先保证内容的结构化与可读性。

## 2. V1 数据规范 (Data Specification)

本项目严格遵循 **[CHD协议规范_v1.3](../CHD协议规范_v1.3.md)**。

### 2.1 核心结构
```markdown
---
title: "文档标题"
version: "1.3"
status: "pending | modified | done"
---

## 章节标题 {layout="cols-3"}

### 卡片标题 {card-style="normal", col-span=1}
卡片内容...

### 数据指标 {card-style="stat", col-span=1}
100+
```

### 2.2 关键约束
1.  **层级约束**: 严禁使用四级标题 (`####`)。
2.  **包裹约束**: `## Section` 下必须紧跟 `### Card`，禁止孤儿文本。
3.  **样式约束**: `stat` 卡片仅用于展示指标，严禁包含表格/代码块。
4.  **布局约束**: 推荐使用 3-4 列布局，避免单行 5+ 卡片导致排版破碎。

## 3. 后续演进计划 (Roadmap)

### Phase 1.5 (优化与固化)
-   [ ] **文档审计**: 清理过时文档，确保 `docs/` 目录整洁准确。
-   [ ] **测试覆盖**: 补充核心组件 (Parser, Renderer) 的单元测试。

### Phase 2 (智能化与扩展)
-   [ ] **AI 辅助写作**: 集成 LLM，实现基于指令的卡片生成与润色。
-   [ ] **复杂布局探索**: 在保持 CHD 简洁性的前提下，探索有限的嵌套或分组能力。

## 4. 结论

V1 版本已达到交付标准。当前系统的核心价值在于**将非结构化文档强制转化为结构清晰的卡片流**，通过“简单并列”的布局形式，显著提升了信息的阅读效率与机器可理解性。后续开发应严格遵守此边界，避免过度设计。
