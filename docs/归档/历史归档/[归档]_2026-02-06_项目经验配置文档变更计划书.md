# 项目经验配置文档 (.cursorrules) 变更计划书

## 1. 变更背景
当前 `.cursorrules` 文件存在以下问题：
- **编号混乱**：存在重复编号（如两个 # 7）、跳号（如缺失 # 14）以及格式不统一（H1 vs H2）。
- **权重模糊**：随着规则增多，后添加的规则可能被 AI 视为次要信息。需明确所有规则具有同等最高优先级。
- **日志管理缺陷**：开发日志缺乏归档机制，长期积累会导致单文件过大，影响上下文读取效率。

## 2. 变更目标
1.  **全局权重声明**：在文件头部强制声明所有条款的平等性和强制性。
2.  **结构标准化**：重置章节编号，统一使用 H1 (`#`) 标题，确保目录结构清晰。
3.  **新增日志归档规则**：实施按天归档机制，确保活跃上下文仅包含当日记录。
4.  **完整性校验**：在重构过程中，严格保留现有所有技术细节和避坑指南，仅做结构调整和增量添加。

## 3. 具体修改内容

### 3.1 头部声明 (新增)
在文件开头添加：
```markdown
# 重要提示 (IMPORTANT)
本文档所有章节与条款具有 **同等最高优先级**。
请勿因章节顺序靠后或内容详略不同而产生权重偏差。
AI 必须对每一条规则（无论是核心原则还是具体脚本避坑）给予完全相同的重视并彻底执行。
```

### 3.3 新增规则详情 (Section 6)
在 `6. 文档与运维` 中追加：
- **开发日志按天归档 (Daily Archiving)**:
  - **检测机制**: 每次写入 `/docs/开发日志/开发记录.markdown` 前，读取文件最后一条记录的日期。
  - **触发条件**: 若 `当前系统日期` != `最后记录日期`。
  - **执行动作**:
    1. **打包归档**: 将当前 `开发记录.markdown` 重命名为 `开发记录_[旧日期].markdown` 并移动至 `/docs/归档/` (或直接打包)。
    2. **初始化**: 创建新的 `开发记录.markdown`，仅包含当天的日期标题。
  - **目的**: 确保上下文窗口中仅包含当天的活跃开发记录，防止历史噪音干扰。
