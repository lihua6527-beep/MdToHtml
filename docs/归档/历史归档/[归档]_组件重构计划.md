# 组件重构计划 - 提高可读性和可维护性

## 分析两个主要组件的问题

### InteractivePost.tsx (861行)
- **问题**：
  - 代码行数过长（861行）
  - 职责过多：导航栏、评分系统、状态管理、导出功能、编辑功能等
  - 逻辑复杂度高：debounced save、frontmatter解析、键盘快捷键等
  - 渲染逻辑复杂：条件渲染、动态样式、下拉菜单等
  - 文档类型按钮问题：下拉菜单显示和文档类型更新功能需要优化

### DocumentList.tsx (730行)
- **问题**：
  - 代码行数过长（730行）
  - 职责过多：文件排序、批量选择、回收站、容量管理、上下文菜单等
  - 逻辑复杂度高：拖拽功能、批量操作、排序逻辑等
  - 渲染逻辑复杂：条件渲染、网格布局、上下文菜单等
  - 性能优化空间：可通过React.memo和useMemo减少不必要的渲染

## 重构目标

1. **提高可读性**：将大组件拆分为更小、更专注的组件
2. **提高可维护性**：每个组件只负责单一职责
3. **提高测试性**：组件粒度更小，更容易编写单元测试
4. **提高性能**：减少不必要的渲染和计算，参考缓存系统优化经验
5. **确保功能完整性**：拆分后所有原有功能保持不变，包括已修复的文档类型按钮功能
6. **确保依赖关系**：确保组件间的依赖关系正确传递，不破坏原有逻辑
7. **增强系统健壮性**：集成错误处理机制，提高系统稳定性
