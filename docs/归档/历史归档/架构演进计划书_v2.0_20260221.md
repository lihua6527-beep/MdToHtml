## 1. 核心愿景 (Core Vision)

**MdToHtml** 是一个 **Windows 本地专属** 的 Markdown 转静态 HTML 工具。

*   **核心目标**: 在 Windows 本地环境中，将 Markdown 文本高效、精准地转换为高质量的静态 HTML 网页。
*   **部署场景**: 生成的静态 HTML 文件 (`output/`) 可直接部署到任何静态网站托管服务 (GitHub Pages, Vercel, Netlify)，但 **转换过程** 严格限制在本地进行。
*   **非目标 (Out of Scope)**:
    *   ❌ **不支持云端在线转换**: 不提供 SaaS 服务，不涉及后端 API 部署。
    *   ❌ **不支持跨平台运行**: 仅针对 Windows 环境优化，不适配 Linux/macOS。
    *   ❌ **不支持并发处理**: 采用单线程/顺序处理模式，确保稳定性与简单性。

---

## 2. 架构设计 (Architecture Design)

### 2.1 总体架构
项目保持 **Next.js SSG (Static Site Generation)** 的轻量级封装结构，利用 React 组件化优势管理渲染逻辑，但剥离所有服务端动态特性。

*   **输入层**: 本地文件系统 (`./input/*.md`)。
*   **核心层**: Next.js App Router (无 API Routes 逻辑，仅用于构建时生成)。
*   **输出层**: 本地文件系统 (`./output/` + `resources/`)。

### 2.2 关键约束
1.  **单机运行**: 所有逻辑在用户本地 PC 上执行，无外部网络依赖（除安装依赖外）。
2.  **文件驱动**: 数据源仅为本地 Markdown 文件，不连接数据库。
3.  **Windows 优先**: 脚本与工具链优先使用 PowerShell/Batch，不引入 Unix 兼容层。

## 3. 演进路线图 (Evolution Roadmap)

### Phase 1: 纯净化与本地化 (Current Focus)
*   **目标**: 移除所有云端/跨平台冗余，稳固 Windows 本地体验。
*   **任务**:
    1.  [x] **依赖清理**: 移除 `shx` 等跨平台兼容库，回归 Windows 原生 `xcopy`。
    2.  [ ] **脚本固化**: 完善 `start.bat` 与 `validate_root.ps1`，确保 Windows 环境一键启动。
    3.  [ ] **文档锁定**: 明确文档中关于“仅限 Windows”的声明。

### Phase 2: 渲染引擎增强 (Future)
*   **目标**: 提升 CHD 范式的渲染表现力。
*   **任务**:
    1.  优化 Bento Grid 布局算法。
    2.  增强 CodeMirror 编辑器的本地交互体验（如本地图片粘贴支持）。
