# 渲染范式分析与组件样式报告

**版本**: 1.0  
**日期**: 2026-02-04  
**状态**: 已归档

## 1. 核心问题分析

### 问题描述
用户注意到“自研图表引擎”和“百万级数据传输”卡片在视觉上与其他卡片存在显著差异（大号字体、居中布局、无边框），并询问这种差异是由输入端控制还是渲染引擎随机生成。

### 分析结论
经代码审查（`src/components/CHD/Card.tsx` 和 `data/例子1.md`），该差异是**完全确定性**的，由输入端的 Markdown 属性控制，而非随机渲染。

- **输入端控制**: 在 Markdown 中，这两个卡片被显式指定了 `{card-style="stat"}`。
- **渲染逻辑**: 渲染引擎读取到 `stat` 样式后，会应用特定的 CSS 类（`text-4xl`, `text-center`, `border-transparent`），从而产生“大字报”风格的视觉效果。

---

## 2. 现有渲染范式 (Rendering Paradigms)

系统目前内置了 7 种标准渲染范式，每种范式对应一套特定的视觉语言：

| 样式名称 (Key) | 视觉特征 | 适用场景 |
| :--- | :--- | :--- |
| **Normal** | 白色背景，轻微阴影，左对齐 | 通用信息承载，默认样式 |
| **Highlight** | 浅灰背景，微亮边框 | 需要轻微强调的内容区块 |
| **Stat** | **居中布局，超大字体，无边框** | **核心指标、关键数据、Slogan** (用户偏好样式) |
| **Quote** | 左侧加粗边框，斜体文字 | 引用名言、设计理念 |
| **Warning** | 红色调背景，红色文字 | 风险提示、错误警告 |
| **Code** | 深色背景，等宽字体 | 代码片段、配置参数 |
| **Summary** | 全宽布局，浅色背景 | 章节综述、总结性文字 |

---

## 3. 布局逻辑 (Layout Logic)

除了卡片内部样式，系统还包含一套“马赛克流” (Mosaic Flow) 布局算法：

1. **自动宽列**: 如果卡片内容字符数 > 600，强制占满 2 列（全宽）。
2. **节奏排列**: 对于短卡片，系统会尝试构建 `1+1` 或 `2` 的交替节奏，避免单调的网格排列。
3. **人工干预**: 用户可以通过 `{col-span=2}` 或 `{col-span=3}` 强制指定卡片跨度。

---

## 4. 后续建议

- **保持一致性**: 建议继续使用 `stat` 样式来展示核心技术指标。
- **扩展性**: 如需新的样式（如“图片卡片”或“时间轴”），需在 `Card.tsx` 中注册新的 `styleVariant`。
