# 启动体验优化：开屏动画 (Splash Screen) 设计方案

## 1. 背景与目标

### 1.1 现状分析
- **性能指标**：当前系统冷启动（Cold Start）至页面完全渲染大约需要 **2秒**。
- **用户痛点**：在这2秒期间，用户可能面对白屏或未响应状态，产生“系统卡顿”的负面感知。
- **优化目标**：通过引入优雅的**开屏动画 (Splash Screen)**，掩盖数据加载的物理耗时，提升用户感知的流畅度与专业感。

## 2. 技术方案选型

为充分利用 Next.js 14 App Router 的特性，我们采用 **Streaming SSR (流式服务端渲染)** 结合 `loading.tsx` 的方案。

### 2.1 核心机制：Next.js Loading UI
- **原理**：利用 React Suspense 机制。当用户访问首页时，服务器会**立即**返回一个轻量级的 Loading 界面（HTML Shell），而无需等待后端繁重的数据读取（`getAllPosts`）完成。
- **流程**：
    1.  **0ms**: 用户发起请求。
    2.  **10ms**: 浏览器接收到 `loading.tsx` 渲染的开屏动画（立即展示，消除白屏）。
    3.  **10ms - 2000ms**: 服务端异步执行 Markdown 文件扫描与读取。
    4.  **2000ms**: 数据准备完毕，服务端将真实内容流式传输到浏览器，自动替换开屏动画。

### 2.2 方案优势
- **零白屏**：即时响应，用户体验极佳。
- **无需接口改造**：不需要将逻辑拆分为 Client Fetch，保持了 SSR 的 SEO 友好与架构简单性。
- **架构解耦**：UI 状态由框架自动管理，无需手动维护 `isLoading` 状态。

## 3. 视觉设计 (UI/UX)

遵循 **莫兰迪配色 (Morandi Colors)** 与 **极简主义** 设计原则。

### 3.1 动画元素
- **Logo 呈现**：中心化展示应用 Logo 或名称 "MdToHtml Pro"。
- **动态效果**：
    - **呼吸效果 (Breathing)**：Logo 透明度或大小的轻微周期性变化，暗示系统正在“存活”并处理中。
    - **加载指示器**：底部使用细线条进度条或极简的 Spinner，避免过度喧宾夺主。
- **背景色**：使用柔和的莫兰迪灰/米色背景 (`bg-bg-page`)，与主界面保持一致，确保过渡自然。

### 3.2 过渡策略
- **淡出 (Fade-out)**：当真实内容加载完成时，开屏动画应有一个 300ms-500ms 的淡出消失效果，避免画面突变。

## 4. 实施步骤

1.  **后端异步化改造**：
    - 将 `src/lib/posts.ts` 中的 `getAllPosts` 封装为异步版本 `getAllPostsAsync`，确保 Next.js 能够触发 Suspense 边界。
    - 修改 `src/app/page.tsx` 为 `async` 组件。
2.  **创建 Loading 组件**：
    - 新建 `src/app/loading.tsx`。
    - 实现基于 Tailwind CSS 动画的开屏 UI。
3.  **验证与调优**：
    - 模拟不同量级的文件数据，确保动画播放流畅且过渡自然。
