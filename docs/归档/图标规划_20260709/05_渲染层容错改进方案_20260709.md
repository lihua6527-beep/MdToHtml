# 阶段三：渲染层容错改进方案

> **关联阶段**: 阶段三（P1）
> **预计工时**: 1h
> **涉及文件**: Card.tsx / Section.tsx
> **前置依赖**: 阶段一（需要 iconExists 函数支持）

---

## 一、概览

渲染层是全链路容错架构的第三层（最后一道防线）。即使提示词引导不充分、后端修正引擎也未能覆盖，渲染层仍需保证布局不塌陷、视觉一致。

## 二、步骤 3.1：Card.tsx 增加图标降级占位（0.5h）

### 2.1 当前代码的问题

**文件**: `MdToHtml/src/components/CHD/Card.tsx` 第371-385行

```tsx
{/* 当前代码：图标不存在时整个条件不成立，40x40 区域消失 */}
{attributes.icon && getIconComponentSync(attributes.icon) && shape === 'rect' && (
    <div className="absolute top-4 left-4 z-20">
        <div className={clsx(
            "w-10 h-10 rounded-full flex items-center justify-center shadow-md",
            forcedCardColor !== 'default' 
                ? `bg-${forcedCardColor} text-white` 
                : "bg-primary/10 text-primary"
        )}>
            {(() => {
                const IconComponent = getIconComponentSync(attributes.icon);
                return IconComponent ? <IconComponent size={20} /> : null;
            })()}
        </div>
    </div>
)}
```

**问题分析**：
- 条件链 `attributes.icon && getIconComponentSync(attributes.icon) && shape === 'rect'`
- 当图标名无效时 `getIconComponentSync` 返回 `null`，整个 `&&` 短路，**不渲染任何内容**
- 同时标题区域的 `pl-14` 样式也不会应用，标题位置偏移

### 2.2 修改为透明占位方案

```tsx
{/* 改进后：当有 icon 属性且为矩形卡片时，始终保留 40x40 的空间 */}
{attributes.icon && shape === 'rect' && (
    <div className="absolute top-4 left-4 z-20">
        <div className={clsx(
            "w-10 h-10 rounded-full flex items-center justify-center",
            // 只有当图标存在且有效时，才显示背景色、阴影和图标颜色
            getIconComponentSync(attributes.icon) ? [
                "shadow-md",
                forcedCardColor !== 'default' 
                    ? `bg-${forcedCardColor} text-white` 
                    : "bg-primary/10 text-primary"
            ] : "bg-transparent"
        )}>
            {(() => {
                const IconComponent = getIconComponentSync(attributes.icon);
                if (IconComponent) {
                    return <IconComponent size={20} />;
                }
                // 图标不存在时：保留 20x20 的透明占位，保持布局
                return <div className="w-5 h-5" />;
            })()}
        </div>
    </div>
)}
```

### 2.3 改动要点

| 修改点 | 原代码 | 新代码 |
|--------|--------|--------|
| 外层条件 | `attributes.icon && getIconComponentSync(...) && shape === 'rect'` | `attributes.icon && shape === 'rect'` |
| 背景色 | 始终有 `shadow-md` 和颜色类 | 仅在图标有效时应用，无效时用 `bg-transparent` |
| 图标缺失时 | 整个区块消失 | 保留 `w-5 h-5` 透明占位 |
| 布局影响 | 标题 `pl-14` 不会应用，标题偏左 | 标题仍然有 `pl-14` 偏移，布局不变 |

### 2.4 不可见的效果

由于图标区块是 `absolute top-4 left-4`，它从文档流中脱离。因此：
- 当图标不存在时，**标题仍然有 `pl-14` 样式**（第390行），标题位置不受影响
- 图标区块只是不显示内容，**40x40 的 `div` 容器本身仍然在 DOM 中**
- 不影响其他卡片元素的布局

### 2.5 更极端情况下的兜底

如果 `attributes.icon` 本身不存在（完全无图标），则连这个 `<div>` 都不渲染。此时：
- 标题区域没有 `pl-14` 样式（第390行的条件 `attributes.icon && getIconComponentSync(attributes.icon) && shape === 'rect'` 不成立）
- 这是正常的"无图标卡片"布局，不是降级状态

## 三、步骤 3.2：Section.tsx 增强图标校验（0.5h）

### 3.1 当前代码的问题

**文件**: `MdToHtml/src/components/CHD/Section.tsx` 第226-232行

```tsx
const validateIconConsistency = () => {
    if (cards.length === 0) return true;
    const hasIcons = cards.map(card => !!card.props.icon).filter(Boolean).length;
    return hasIcons === 0 || hasIcons === cards.length;
};
```

**问题**：
- 只检查 `icon` 属性是否存在（`!!card.props.icon`）
- **不检查图标名是否有效** — 如果所有卡片都有 `icon="INVALID"`，校验通过但所有图标都不渲染

### 3.2 修改为双重校验

```typescript
// 在文件顶部增加 import
import { iconExists } from '../../lib/icon-manager';

// 替换 validateIconConsistency
const validateIconConsistency = (): { valid: boolean; issues: string[] } => {
    if (cards.length === 0) return { valid: true, issues: [] };
    
    const issues: string[] = [];
    
    // 1. 检查图标属性存在的一致性
    const hasIconEntries = cards.filter(card => !!card.props.icon);
    const noIconEntries = cards.filter(card => !card.props.icon);
    
    if (hasIconEntries.length > 0 && noIconEntries.length > 0) {
        issues.push('同一 section 下的卡片要么都使用图标，要么都不使用图标');
    }
    
    // 2. 检查图标名的有效性（新增）
    const invalidIcons = hasIconEntries
        .map(card => card.props.icon)
        .filter((iconName): iconName is string => !!iconName && !iconExists(iconName));
    
    if (invalidIcons.length > 0) {
        const uniqueInvalid = [...new Set(invalidIcons)];
        issues.push(`以下图标名称不存在：${uniqueInvalid.join('、')}`);
    }
    
    return { valid: issues.length === 0, issues };
};
```

### 3.3 更新使用该函数的地方

**第245行**（当前使用处）：

```tsx
const isIconConsistent = validateIconConsistency();
```

修改为：

```tsx
const { valid: isIconConsistent, issues: iconIssues } = validateIconConsistency();
```

**第345-349行**（警告渲染处）：

```tsx
{!isIconConsistent && (
    <div className="mb-4 p-3 bg-amber-50 text-amber-700 text-sm rounded-lg border border-amber-200 flex items-center gap-2">
        <span>⚠️ 同一 section 下的卡片要么都使用图标，要么都不使用图标。</span>
    </div>
)}
```

修改为：

```tsx
{!isIconConsistent && (
    <div className="mb-4 p-3 bg-amber-50 text-amber-700 text-sm rounded-lg border border-amber-200 flex items-center gap-2">
        <span>⚠️ {iconIssues.join('；')}</span>
    </div>
)}
```

### 3.4 向后兼容性

| 情况 | 旧代码行为 | 新代码行为 | 是否兼容 |
|------|-----------|-----------|---------|
| 全部无图标 | 不警告 | 不警告 | ✅ |
| 全部有图标（有效） | 不警告 | 不警告 | ✅ |
| 部分有图标、部分无 | 警告"要么都用要么都不用" | 警告"要么都用要么都不用" | ✅ 不变 |
| 全部有图标但部分无效 | **不警告**（旧缺陷） | 警告"以下图标不存在" | ✅ 修复了缺陷 |
