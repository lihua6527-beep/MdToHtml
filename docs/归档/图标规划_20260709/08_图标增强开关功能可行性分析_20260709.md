## 一、需求描述

在 AI 翻译（输入文档 → CHD 生成）时，提供一个开关选项：
- **开启「简洁图标增强表现力」**：在 Prompt 中注入图标规则和推荐列表，AI 生成的文档包含图标
- **关闭**：Prompt 中不包含图标相关内容，AI 不生成图标，保持纯文字卡片

用户可自由选择是否使用图标增强。

---

## 二、可行性分析

### 2.1 核心问题

当前架构中，图标相关的提示词内容已经**硬编码**在 `PromptEngine.ts` 的 `getPromptA()` 和 `getPromptB()` 方法中，与主提示词**不可分离**。实现开关功能需要：

1. **分离图标内容**：将图标规则 + 图标列表从主 Prompt 中提取为独立的片段
2. **构建时选择注入**：在组装系统 Prompt 时，根据开关状态决定是否拼接图标内容
3. **传递开关状态**：从前端 UI → AIService → PromptEngine

### 2.2 数据流改造

当前数据流：
```
AIArea (currentPrompt状态) → AIService.generate({config}) → PromptEngine.getSystemPrompt(variant)
                                                              ↓
                                                         返回完整 Prompt（含图标内容）
```

改造后的数据流：
```
AIArea (currentPrompt + enableIcons状态) → AIService.generate({config}) → PromptEngine.getSystemPrompt(variant, enableIcons)
                                                                           ↓
                                                                      决定是否拼接图标内容
```

### 2.3 可行性结论

**完全可行，工程量小**。原因：

| 维度 | 分析 | 评估 |
|------|------|:----:|
| 提示词架构 | PromptEngine 已经将提示词封装为 `getSystemPrompt()` 方法，修改入口简单 | ✅ |
| 状态传递链路 | AIArea → AIInputPanel → AIService → PromptEngine，链路清晰 | ✅ |
| 图标内容结构 | 图标规则和列表在 Prompt 中是一个独立的段落块，可以提取为方法 | ✅ |
| UI 改动 | AIInputPanel 已有风格切换按钮，增加一个开关/选项即可 | ✅ |
| 后端 API | `/api/ai/generate` 请求体中的 `systemPrompt` 字段本身是字符串 | ✅ |
| 向后兼容 | 不改变现有 API 接口，只增加可选参数 | ✅ |

│  ├─ AIServiceConfig: { model, promptVariant, enableIcons }     │
│  └─ generate() → PromptEngine.getSystemPrompt(variant, icons)  │
└────────────────────────────────────────────────────────────────┘
         │
         ▼

### 3.2 PromptEngine.ts 改造

将现有的 `getPromptA()` 和 `getPromptB()` 拆分为两部分：

#### 改造前

```typescript
private static getPromptA(): string {
  return `... 包含图标内容和规则的完整 Prompt ...`;
}
```

#### 改造后

```typescript
/**
 * 获取完整的 System Prompt
 */
static getSystemPrompt(variant: 'default' | 'alternative', enableIcons: boolean = true): string {
  const base = variant === 'default' ? this.getPromptABase() : this.getPromptBBase();
  if (!enableIcons) return base;
  return base + '\n\n' + this.getIconSection(variant);
}

/**
 * 基础 Prompt（不含图标内容）
 */
private static getPromptABase(): string {
  return `... 不包含图标规则的 Prompt 主体 ...`;
}

/**
 * 图标增强内容（独立片段，按需注入）
 */
private static getIconSection(variant: 'default' | 'alternative'): string {
  if (variant === 'default') {
    return `### 图标使用规则（请严格遵循）：
(1) 成套使用：同一 Section 下的所有卡片...
...

### 图标列表（按场景分类）：
技术/性能类：zap, cpu, code...
...`;
  } else {
    // 学术版图标内容
    return `...`;
  }
}
```

#### Prompt A 中的其他改动

自检清单的第 10-13 项也属于图标相关，同样按需加入：

```typescript
private static getChecklist(enableIcons: boolean): string {
  let items = [
    '1. ☐ Frontmatter 是否包含 title、subtitle、tags？',
    '...',
    '9. ☐ Section 的 columns 值是否遵循智能列数规则？',
  ];
  if (enableIcons) {
    items.push(
      '10. ☐ 图标名称是否来自推荐的图标列表？',
      '11. ☐ 图标是否遵守成套使用规则？',
      '12. ☐ 图标是否只在标准矩形卡片中使用？',
      '13. ☐ 图标名是否使用连字符命名规范？',
    );
  }
  return items.join('\n');
}
```

## 五、注意事项与边界情况

### 5.1 自检清单的一致性

当 `enableIcons=false` 时，自检清单中的图标相关项（第10-13项）不应该出现，否则会误导 AI 自检。

### 5.2 与「风格切换」的关系

- 图标增强开关与「默认风格/学术风格」切换是**正交的两个维度**
- 可以组合出 4 种模式：
  - 默认风格 + 有图标（完整体验）
  - 默认风格 + 无图标（纯文字）
  - 学术风格 + 有图标（学术+图标）
  - 学术风格 + 无图标（学术纯文字）

### 5.3 修正引擎的兼容性

当 `enableIcons=false` 时，AI 不会生成任何图标属性。此时 `IconAutoFixService` 接收到的数据中 `iconName` 全部为 `null`，走「情况1：全部无图标 → 保持」分支，不产生任何修正行为。✅ **完全兼容**。

### 5.4 卡片形状的兼容性

当图标增强关闭时，卡片不使用图标，因此 shape 属性中即使写了 `"rect"`，也不会有图标显示。Card.tsx 的渲染逻辑中 `{attributes.icon && ...}` 条件不满足，不会渲染。✅ **完全兼容**。

| 方案 | 位置 | 优点 | 缺点 |
|:----:|:----:|------|------|
| **A** | AIArea 顶部状态栏，模型选择旁边 | 视觉显眼，用户容易发现 | 顶部区域已有多项信息 |

## 七、总结

### 7.1 可行性结论

> **完全可行。** 工程改动量约 1.8h，涉及 3 个核心文件的微调，不涉及后端、渲染层、资源层的变动。核心思路是将 PromptEngine 中已硬编码的图标内容提取为独立方法，根据开关状态按需拼接。

### 7.2 关键设计决策

| 决策 | 选择 | 理由 |
|------|------|------|
| 开关默认值 | `true`（开启） | 保持当前行为不变，向后兼容 |
| 控制粒度 | 整体开关（有/无） | 不需要拆分单个规则开关，过度设计 |
| UI 位置 | AIArea 顶部状态栏 | 与模型选择/风格选择同级，逻辑一致 |
| 状态传递 | AIArea → AIService → PromptEngine | 避免直接修改 API 接口 |

### 7.3 改造后的 Prompt 结构

```
getSystemPrompt(variant, enableIcons=true)
├── getPromptABase()          ← 基础 Prompt（不含图标）
├── getIconSection()          ← 图标规则 + 图标列表（条件注入）
├── getChecklist(enableIcons) ← 自检清单（条件包含图标项）
└── getOutputRequirements()   ← 输出要求（不变）
