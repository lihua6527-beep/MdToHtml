# Plan 05: 文档全文搜索功能

> **简要说明**：在首页文档列表（`DocumentList`）中增加全文搜索能力。集成轻量级模糊搜索库 Fuse.js，搜索范围为文件名 + Frontmatter 元信息 + 内容预览摘要。利用现有 `cache-manager` 元数据作为索引，无需额外扫描磁盘，增量成本极低。

---

## 1. 现状分析

### 1.1 当前文档查找方式

首页左侧 `DocumentList` 组件目前的查找方式：

```
浏览全部文件列表 → 手动滚动查找 → 右键打开
```

没有任何搜索功能。当 `posts/` 目录下的文档数量增长到 20+ 后，用户需要手动滚动列表寻找目标文档，效率低下。

### 1.2 现有可复用的基础设施

| 资源 | 描述 | 状态 |
|------|------|------|
| `cache-manager.ts` | Top 500 缓存，维护所有文档的元数据（title, tags, brief 等） | ✅ 已有 |
| `lib/posts.ts` | `getAllPosts()` 返回所有文档元数据 | ✅ 已有 |
| `DocumentList.tsx` | 文档列表组件 | ✅ 已有 |
| `useFileManager.ts` | 文件管理 Hook（SWR 数据获取） | ✅ 已有 |

### 1.3 技术选型

| 库 | 体积（gzip） | 功能 | 选择理由 |
|------|------------|------|---------|
| **Fuse.js** | ~30KB ✅ | 模糊搜索、权重排序、高亮 | 轻量级，无依赖，完全客户端 |
| Lunr.js | ~45KB | 全文索引 | 更大更重，需要构建索引 |
| MiniSearch | ~25KB ｜ 全文搜索 | 更现代但不如 Fuse.js 成熟 |
| 手写前缀搜索 | 0KB | 只能前缀匹配 | 功能不足，不支持模糊 |

**选择 Fuse.js**，原因：
1. 体积合理（30KB gzipped）
2. 模糊搜索能容忍拼写错误（`"mint"` 可匹配 `"mint-theme"`）
3. 支持自定义权重字段
4. 内置结果排序

## 2. 设计方案（v2 - 弹窗式搜索）

### 2.1 交互流程

```
┌──────────────────────┬──────────────────────────────┐
│  DocumentList (左)   │  主内容区 (右)               │
│                      │                              │
│  [文档列表] [🔍][🗑️]│  ┌─ SearchPanel ───────────┐ │
│  ─────────────────   │  │ [🔍 搜索框]             │ │
│  📄 文档 A ← 高亮   │  │ ┌── 结果 1 ──────────┐ │ │
│  📄 文档 B           │  │ │ 文件名 + 高亮      │ │ │
│  📄 文档 C ← 高亮   │  │ │ 标题 + 高亮        │ │ │
│  📄 文档 D           │  │ │ tags + 高亮         │ │ │
│                      │  │ │ brief + 高亮        │ │ │
│  容量进度条          │  │ └────────────────────┘ │ │
│                      │  │ [✕ 关闭搜索]          │ │
└──────────────────────┴──────────────────────────────┘
```

**交互要点**：
1. 点击 `ListHeader` 中的 🔍 搜索图标 → 右侧主内容区显示 `SearchPanel`
2. 输入关键词 → 实时 Fuse.js 模糊搜索 → 左侧列表对应文档高亮标注
3. 点击搜索结果 → 跳转编辑器
4. 点击「关闭搜索」→ 恢复完整列表，左侧高亮消失

### 2.5 搜索结果高亮

```tsx
function highlightText(text: string, query: string): React.ReactNode {
  if (!query || !text) return text;
  const escaped = query.replace(/[.*+?^${}()|[\]\\]/g, '\\$&');
  const regex = new RegExp(`(${escaped})`, 'gi');
  const parts = text.split(regex);
  return parts.map((part, i) => 
    regex.test(part) 
      ? <mark key={i} className="bg-yellow-200 dark:bg-yellow-700 rounded px-0.5">{part}</mark>
      : part
  );
}
```

高亮覆盖：文件名(slug)、标题(title)、标签(tags)、内容摘要(brief/excerpt)

### 2.6 性能考虑

| 考虑 | 方案 |
|------|------|
| 文档数量 | Top 500 限制，500 篇文档的搜索索引构建 < 50ms |
| 实时搜索 | Fuse.js 本身已高性能（逐字符过滤），无额外防抖需求 |
| 索引重建 | 仅在 `documents` 数组变化时重建（`useMemo`） |
| 空搜索 | 不触发搜索，直接显示全部文档 |
