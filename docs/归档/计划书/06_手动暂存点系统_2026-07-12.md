# Plan 06: 手动暂存点系统

> **计划日期**：2026-07-12
> **计划目标**：提供一个简单的"手动打点保存"功能——用户可以在编辑过程中主动点击"暂存"按钮，为当前文档状态打上一个标记。之后可以随时回到任意暂存点。
> **前置依赖**：计划01（操作类型系统—CHECKPOINT 类型）、计划02（撤销引擎—Operation[] 序列）
> **对应总体计划**：Phase 4

---

## 一、设计动机

### 1.1 需求来源

撤销/重做（Ctrl+Z / Ctrl+Shift+Z）对细粒度的操作回退很好用。但当你：

```
- 改了一大段文字后，想"先保留这个版本，继续改"
- 试了几种不同的改法，发现第一种最好
- 明天回来看今天的进度，想看到几个关键节点
```

这时候的诉求不是"撤销上一步"，而是**"记住这个版本，以后能回来"**。

### 1.2 和撤销/重做的区别

| | 撤销/重做（Ctrl+Z） | 暂存点（Checkpoint） |
|---|---|---|
| **谁触发** | 自动记录每次操作 | 用户手动打点 |
| **粒度** | 单次操作级 | 阶段版本级 |
| **用途** | 临时回退（改错了） | 版本锚点（想保存当前状态） |
| **保留** | 刷新后持久化 | 刷新后持久化 |
| **上限** | 50 步 | 不限，但建议保留最近 20 个 |

**简单理解**：撤销是"橡皮擦"，暂存点是"书签"。

## 二、方案设计

### 2.1 核心思想

在 Operation 序列中插入 `CHECKPOINT` 操作：

```
Operation 序列（时间顺序）：
  [文本编辑] → [文本编辑] → [AI润色] → [CHECKPOINT "第一版完成"] → [文本编辑] → ...

                                                  👆 这个 CHECKPOINT 记录了
                                                    打点时刻的完整文档快照
```

### 2.2 CHECKPOINT 操作定义

```typescript
enum OperationType {
  // ...
  CHECKPOINT,  // 用户手动暂存点
}

// CHECKPOINT 的 Operation 结构：
const checkpointOp: Operation = {
  id: 'op-xxx',
  type: OperationType.CHECKPOINT,
  timestamp: Date.now(),
  position: { start: 0, end: doc.length },  // 暂存点是"全篇"快照
  payload: {
    before: '',           // CHECKPOINT 不用于撤销，不需要 before
    after: fullDocContent,  // 暂存点的文档完整内容
  },
  display: {
    icon: '📍',
    label: '暂存点: 第一版完成',  // 用户输入的描述
    detail: `共 ${fullDocContent.length} 字符`,
  },
};
```

### 2.3 CHECKPOINT 不会出现在 undo 栈顶

CHECKPOINT 是**标记型操作**，不是编辑操作。它的特殊之处：

- ✅ 插入到 Operation 序列中
- ❌ 不参与 undo/redo（Ctrl+Z 不会撤销到一个 CHECKPOINT）
- ✅ 从 CHECKPOINT 跳转回某个版本时，通过重建文档内容实现，不是通过 undo

### 2.4 用户操作流程

```
1. 用户在编辑器中编辑文档
2. 完成一个阶段后，点击界面上的"📍 暂存"按钮
3. 弹出对话框（或直接使用默认描述）：
     请输入暂存点描述（可选）：
     ┌──────────────────────────┐
     │ 第一版完成               │
     └──────────────────────────┘
     [取消]  [确认暂存]
4. 确认 → 生成 CHECKPOINT 操作 → 序列推入 → 持久化
5. 界面上的"暂存点列表"更新
```

### 2.5 暂存点列表 UI

```
┌── 暂存点 ──────────────┐
│                         │
│  📍 第一版完成         │
│     2026-07-12 11:30   │
│  📍 初始草稿           │
│     2026-07-12 10:00   │
│  📍 刚开始写           │
│     2026-07-12 09:00   │
│                         │
│  [+ 新建暂存点]         │
└─────────────────────────┘
```

每个暂存点支持：
- **点击** → 回到该版本（跳转前自动保存当前状态为一个 CHECKPOINT，防止丢失）
- **右键 → 删除** → 移除该 CHECKPOINT

## 三、回退到暂存点的逻辑

### 3.1 基本算法

```typescript
function jumpToCheckpoint(targetCheckpoint: Operation): void {
  // 1. 在跳转前，自动保存当前状态为新 CHECKPOINT
  autoSaveCurrentAsCheckpoint('跳转前的状态');

  // 2. 从目标 CHECKPOINT 获取文档内容
  const docContent = targetCheckpoint.payload.after;

  // 3. 直接替换编辑器内容 + 重置 Operation 序列
  editor.setContent(docContent);
  resetHistory(targetCheckpoint);  // 保留到目标 CHECKPOINT 为止的操作
}
```

### 3.2 跳转前后的效果

```
跳转前序列：
  [编辑1] → [编辑2] → [CHECKPOINT A] → [编辑3] → [编辑4] → [CHECKPOINT B] → [编辑5]
                                                                              ↑ 当前位置

自动保存为 CHECKPOINT C：
  [编辑1] → [编辑2] → [CHECKPOINT A] → [编辑3] → [编辑4] → [CHECKPOINT B] → [编辑5] → [CHECKPOINT C]

跳转到 CHECKPOINT A：
  [编辑1] → [编辑2] → [CHECKPOINT A]
                        ↑ 当前位置
  编辑5 的操作被"截断"了（它们仍然在持久化中可查，但不在当前撤销栈中）
```

## 四、持久化策略

### 4.1 CHECKPOINT 单独存储

CHECKPOINT 的操作记录可以单独维护一个列表，独立于常规的 undo/redo 栈：

```typescript
interface CheckpointStore {
  checkpoints: Array<{
    id: string;           // 对应 Operation.id
    label: string;        // 用户描述
    timestamp: number;    // 打点时间
    content: string;      // 完整文档快照（放在单独存储 key 中）
  }>;
}

// localStorage 存储
const CHECKPOINT_KEY = 'chd_editor_checkpoints';
```

> 为什么不把文档内容存在 Operation.payload.after 中？
> CHECKPOINT 的 payload.after 是完整文档内容，可能很大。把它单独提取出来管理，避免和 Operation 序列混在一起导致序列体积膨胀。

### 4.2 存储上限

```
- 最多保留 20 个暂存点
- 超过 20 个时，删除最旧的一个（或让用户选择删除哪个）
- 每个暂存点独立存储文档内容，不会因为序列截断而丢失
```

## 五、与现有功能的交互

### 5.1 自动保存 vs 暂存点

| | 自动保存 (useAutoSave) | 暂存点 (Checkpoint) |
|---|---|---|
| **触发** | 系统自动（定时或失焦） | 用户手动 |
| **用途** | 防止内容丢失 | 版本锚点 |
| **UI** | 无 | 可见列表 |
| **可回退** | 刷新后恢复最新 | 可跳转到任意暂存点 |

两者**互补**，不冲突。

### 5.2 暂存点 + 撤销重做

```
场景：用户跳转到某个暂存点后，发现还是之前的版本好

做法：
  1. 跳转到 CHECKPOINT B（当前状态自动保存为 CHECKPOINT C）
  2. 改了几笔 → 后悔了
  3. 点击 CHECKPOINT C（刚才自动保存的"跳转前的状态"）
  4. 回到原来的版本
```
