# 编辑体验革新与所见即所得 (WYSIWYG) 计划书

> **文档说明**: 本计划书旨在解决 Markdown 编辑与预览割裂的问题，目标是实现类似 Typora/Notion 的所见即所得编辑体验。
> **状态**: 长期规划 (Long-term)
> **优先级**: 高 (High) - 但实现难度极大

## 1. 核心痛点
- **割裂感**: 用户在左侧编写 Markdown 源码，右侧查看渲染结果，视线需频繁切换。
- **样式不一致**: 编辑区的纯文本/等宽字体与渲染区的精美排版（莫兰迪配色、卡片样式）完全不同。
- **操作繁琐**: 简单的加粗、下划线、颜色修改需要记忆 Markdown 语法或 HTML 标签，而非直观的选中操作。

## 2. 需求描述
- **所见即所得**: 在渲染出的页面上直接进行文本选择和编辑。
- **风格一致性**: 编辑状态下的文本样式（字体、颜色、大小）应与预览状态完全一致。
- **交互优化**: 选中文字后弹出悬浮菜单（Bold, Italic, Underline, Color），而非手动输入符号。
- **块级操作**: 支持对 Block（段落、标题、列表）的拖拽、转换和属性配置。

## 3. 技术方案分析

### 方案 A: CSS 深度定制 (轻量级)
- **原理**: 保持 Markdown 源码编辑，但通过 CSS Hack 将 `textarea` 或 `pre` 标签伪装成渲染结果。
- **优点**: 成本低，不需要改变底层数据流。
- **缺点**: 无法实现复杂的卡片布局和多列排版，仅适用于简单文本。
- **结论**: **不推荐**，无法满足 CHD 复杂布局需求。

### 方案 B: 块级混合编辑 (中量级)
- **原理**: 
  - 默认显示渲染后的 React 组件。
  - 点击某个 Block（如一段文字）时，该 Block 切换为 `Textarea` 或 `CodeMirror` 实例。
  - `Textarea` 的样式（字体、行高、背景）与渲染组件完全匹配。
  - 失去焦点（Blur）时，解析 Markdown 并切回渲染组件。
- **优点**: 
  - 实现相对简单，风险可控。
  - 保持了 Markdown 的源码可控性。
- **缺点**: 
  - 切换瞬间可能有“跳动”感。
  - 无法跨 Block 选择文本。

### 方案 C: 富文本引擎重构 (重量级 - 推荐)
- **原理**: 引入专业富文本引擎（Prosemirror / Slate.js / TipTap）。
- **架构**:
  1. **Import**: Markdown -> AST -> Prosemirror State。
  2. **Edit**: 用户操作直接修改 Prosemirror State (DOM 映射)。
  3. **Export**: Prosemirror State -> AST -> Markdown。
- **优点**: 
  - 真正的 WYSIWYG 体验。
  - 支持复杂的选区、拖拽、嵌套。
  - 极其强大的扩展性（插件机制）。
- **缺点**: 
  - **开发工作量巨大**: 需要重写所有渲染逻辑。
  - **数据一致性风险**: Markdown <-> State 的双向转换可能丢失细节（如自定义 HTML 属性）。

## 4. 实施路线图 (Roadmap)

### Phase 1: 调研与原型 (2周)
- [ ] 搭建 Prosemirror / TipTap 最小原型。
- [ ] 验证 CHD 特有组件（Grid, Card, Section）在富文本引擎中的实现可行性。
- [ ] 测试 Markdown 双向转换的保真度。

### Phase 2: 核心编辑器替换 (4周)
- [ ] 实现基础文本编辑（加粗、斜体、列表）。
- [ ] 实现自定义节点（Card, Section）。
- [ ] 接入现有的一键排版与主题系统。

### Phase 3: 高级交互 (2周)
- [ ] 悬浮菜单 (Floating Menu)。
- [ ] 拖拽排序 (Drag & Drop)。
- [ ] 快捷指令 (Slash Commands)。

## 5. 风险评估
- **技术风险**: 富文本引擎的学习曲线极陡峭，坑多。
- **维护风险**: 需要维护复杂的转换逻辑，一旦 Markdown 规范变更，转换器需同步升级。
- **性能风险**: 大型文档的 DOM 节点数量可能导致卡顿，需要虚拟滚动支持。

## 6. 结论
建议在 **v2.0** 版本中启动此计划。当前 v1.x 版本应优先完善基于源码编辑的体验（如辅助工具栏、即时预览优化），待系统稳定后再进行架构级重构。
