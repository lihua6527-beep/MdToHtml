# 架构治理规范 (Architecture Governance)

## 1. 技术选型原则 (Tech Stack Principles)
项目严格遵循 **“Windows 本地化、轻量化、静态化”** 的原则。

### 1.1 核心限制 (Constraints)
*   **OS**: 仅支持 **Windows 10/11**。
*   **Runtime**: Node.js (LTS Version)。
*   **禁止项**:
    *   禁止引入数据库 (SQLite/PostgreSQL 等)。
    *   禁止引入 Docker/K8s 等容器化技术。
    *   禁止引入重型后端框架 (NestJS/Django)。
    *   禁止复杂的并发/多线程处理逻辑。

## 2. 代码与工程规范 (Engineering Standards)

### 2.1 文件系统交互
*   **读写安全**: 严格限制在项目根目录的 `input/` 和 `output/` 文件夹内。
*   **路径处理**: 使用 Windows 风格路径分隔符或 Node.js `path` 模块兼容处理，但在脚本中优先使用 PowerShell/CMD 语法。

### 2.2 构建与发布
*   **静态导出**: 必须使用 `output: 'export'` (Next.js SSG)。
*   **本地脚本**: 必须提供 `.bat` 或 `.ps1` 脚本用于自动化操作，不依赖 Makefile 或 Shell Scripts。

## 3. 性能指标 (Performance Metrics)
*   **构建速度**: 单个 Markdown 文件转换时间 < 2s。
*   **产物积**: 生成的 HTML 应当经过压缩，无冗余 JS 注入。

## 4. 安全合规 (Security)
*   **本地沙箱**: 确保程序不会访问 `input`/`output` 之外的文件系统区域。
*   **无外网通信**: 核心转换功能在断网环境下必须可用。
