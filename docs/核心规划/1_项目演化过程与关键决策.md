# 项目演化过程与关键决策 (Project Evolution & Key Decisions)

> **系统本质上是在回答一个问题： 当AI能生成无限内容时，如何确保输出的品质与一致性？**
>
> 答案是： **协议化输入、自动化评分、可视化调优、多态化输出**。
>
> 这不仅是工具创新，更是 **内容生产流程的范式转移**。

## 1. 项目演进历程 (The Evolution)

本项目从一个简单的个人需求，演进为具备深度的工程系统，经历了四个关键阶段。

### 第一阶段：静态化与痛点 (Origin)
*   **背景**：需要一个低成本、零运维的个人技术博客。
*   **痛点**：现有的静态生成器（Hexo/Hugo）排版千篇一律，无法满足对“内容多样性呈现”的追求。硬编码 HTML 维护成本极高。
*   **目标**：构建一个能自动将 Markdown 转化为高品质、多风格网页的工具。

### 第二阶段：协议化与 AI 陷阱 (The AI Trap)
*   **尝试**：最初试图构建全流程 AI 系统，让大模型直接读取内容并生成 HTML/CSS 布局。
*   **失败**：发现 AI 输出极不稳定，样式难以统一，且调试成本极高（“黑箱”问题）。
*   **突破**：抛弃朴素渲染，提出“协议驱动”核心。定义了 **CHD (Card-based Hierarchical Document)** 协议雏形，作为人机协作的中间语言。

### 第三阶段：解耦化 (Decoupling)
*   **核心决策**：将“非确定性的 AI 生成”与“确定性的渲染”彻底分离。
*   **架构调整**：
    1.  **降维**：将二维布局问题简化为一维的“内容类型标签”序列。
    2.  **解耦**：AI 仅负责在离线阶段生成符合规范的 Markdown，核心渲染完全由确定性的规则引擎接管。
*   **结果**：系统内核变得 100% 稳定、可调试、高性能。

### 第四阶段：通用引擎与协同化 (Synergy & Abstraction)
*   **升维**：项目超越了"博客"的范畴，成为一个通用的"结构化内容交付引擎"。
*   **协同**：引入前端人机交互闭环。利用用户反馈生成"黄金样例"，基于小模型实现通用结构化理解。
*   **聚焦**：确定核心输出为 HTML 网页 + Markdown 双格式。❌ **放弃 PPT/PDF 导出**（已验证与 CHD 流式编辑不兼容：PDF 分页无法匹配无限流式内容，PPT 大模型可更优产出）。
*   **技术升级**：采用 Electron + Next.js 混合架构，实现桌面端应用与静态生成的完美结合。

## 2. 关键架构决策 (Key Architectural Decisions)

| 决策点 | 放弃方案 | 采纳方案 | 理由 |
| :--- | :--- | :--- | :--- |
| **核心驱动** | 端到端 AI 生成 | CHD 协议 + 规则引擎 | 保证稳定性与可控性，消除 AI 幻觉。 |
| **输入格式** | 自然语言 / 随意 MD | 强约束 CHD Markdown | 建立人机协作的唯一标准语言，降低解析复杂度。 |
| **交互模式** | 聊天式修改 | 可视化引导式调整 | 赋予用户直接控制权，聚焦于“选择”而非“描述”。 |
| **输出形态** | 单一网页 | HTML 网页 + Markdown 双格式 | ❌ PPT/PDF 已验证不兼容并放弃（2026-07-11） |
| **渲染逻辑** | AI 直接生成 HTML | AST -> 组件映射 | 确保样式一致性，便于维护和扩展主题。 |
| **状态管理** | 实时文件扫描 | 元数据缓存 (O(1)) | 解决文件量增长带来的性能瓶颈，确保状态一致性。 |

## 3. 系统模块职责演变

### 3.1 初始阶段（无模型）
*   **前端**: 独立的、表单式的“严格引导编辑器”，强制用户产出规范数据。
*   **数据**: 产出“绝对规范”的 CHD 文档。
*   **渲染引擎**: 独立服务，接收规范文档，用纯规则解析并渲染。

### 3.2 智能增强阶段（模型接入后）
*   **前端**: 升级为“智能编辑器”，支持自由文本粘贴 + 智能识别。
*   **小模型服务**: 独立 API，接收文本，进行深度加工（语义分类、关系理解、重要性标注），返回增强版 AST。
*   **渲染引擎**: 接收增强版 AST，渲染更专业的布局。

## 4. 面试/答辩叙事策略

- **核心逻辑**：痛点 -> AI 尝试失败 -> 架构重构（解耦/降维）-> 最终工程化方案。
- **重点强调**：
  - **工程思维**：展示如何通过“协议”来管理不确定性。
  - **系统闭环**：不仅有工具，还有数据反馈和模型进化的闭环设计。
  - **实际价值**：解决了内容创作者“排版难”的真实问题，且具备极高的扩展性。
