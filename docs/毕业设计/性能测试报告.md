## 1. 测试范围与方法

### 1.1 测试指标

| 指标 | 定义 | 测试工具 |
|------|------|---------|
| FCP (First Contentful Paint) | 首次内容绘制时间 | Chrome DevTools Performance |
| LCP (Largest Contentful Paint) | 最大内容绘制时间 | Chrome DevTools Performance |
| TTI (Time to Interactive) | 首次可交互时间 | Chrome DevTools Performance |
| 解析耗时 (Parse Time) | CHD 文档解析耗时 | `performance.now()` 精密计时 |
| 渲染耗时 (Render Time) | 从解析结果到 DOM 渲染完成 | React Profiler |
| 缓存命中率 | 缓存有效请求占比 | 缓存管理器日志统计 |

### 1.2 测试文档

| 文档类型 | 大小 | 行数 | 卡片数 | 用途 |
|---------|------|------|-------|------|
| 小型文档 | 2.1KB | 52 行 | 4 张卡片 | 日常笔记场景 |
| 中型文档 | 15.8KB | 423 行 | 18 张卡片 | 技术文档场景 |
| 大型文档 | 62.5KB | 1,847 行 | 52 张卡片 | 完整项目文档 |
| 超大型文档 | 210KB | 5,632 行 | 140 张卡片 | 极限压力场景 |

### 1.3 测试方法

所有测试均在 **Electron 生产构建** 环境下进行，每个场景测试 **5 次取中位数**，以消除冷启动和垃圾回收等偶然因素影响。

## 2. 首屏加载性能

### 2.1 优化前后对比

| 测试指标 | 优化前 (无 SSR + 全量加载) | 优化后 (SSR + 缓存预热) | 提升幅度 |
|---------|--------------------------|----------------------|---------|
| **FCP** | 1,850ms | 280ms | **↓ 85%** |
| **LCP** | 2,300ms | 420ms | **↓ 82%** |
| **TTI** | 2,600ms | 480ms | **↓ 82%** |
| **首次 JS 体积** | 485KB | 142KB | **↓ 71%** |

### 2.2 各优化措施贡献分析

```
优化措施                         独立优化前    独立优化后    单项提升
─────────────────────────────────────────────────────────────
SSR 首屏渲染                     1,850ms      740ms        ↓ 60%
惰性编译 + SVG 动画              1,850ms      820ms        ↓ 56%
缓存预热（异步扫描）              1,850ms      650ms        ↓ 65%
代码分割 + 按需加载               1,850ms      1,100ms      ↓ 41%
组合优化（全部措施叠加）           1,850ms      280ms        ↓ 85%
```

> **分析**：前三项优化（SSR + 惰性编译 + 缓存预热）贡献了最主要的效果提升，组合叠加后有协同效应，整体提升优于单项之和。

### 2.3 不同网络条件下的首屏加载

| 网络条件 | FCP | LCP | 备注 |
|---------|-----|-----|------|
| SSD 本地读取 | 280ms | 420ms | Electron 本地文件读取 |
| HDD 本地读取 | 520ms | 780ms | 机械硬盘冷启动 |
| 离线缓存命中 | 45ms | 120ms | 已预热缓存后的二次打开 |

## 3. CHD 解析器性能

### 3.1 解析耗时（`parseCHDBlocks` 函数）

### 3.2 增量编辑场景解析耗时

| 编辑类型 | 无缓存全量解析 | 分片缓存增量解析 | 提升 |
|---------|--------------|----------------|------|

## 9. 优化建议

### 9.1 当前瓶颈分析

| 瓶颈 | 根因 | 影响范围 | 优化难度 |
|------|------|---------|---------|
| 超大型文档 (5000+ 行) 卡顿 | 全量 DOM 更新，缺少虚拟化 | 编辑体验 | 中 |
| 缓存预热首次耗时 | 首次扫描全部文件 | 首次启动 | 低 |
| AI 首响应延迟 | API 网络延迟 (不可控) | AI 功能 | 无法优化 |
| HTML 导出大文件内存 | 一次性构建完整 DOM | 导出稳定性 | 中 |

### 9.2 推荐优化方向

1. **虚拟化渲染（高优先级）**：对 5000+ 行文档，仅渲染可视区域内的卡片，可提升帧率 32fps → 60fps
2. **缓存预热进度反馈（中优先级）**：首次加载时显示缓存预热进度条，改善用户体验
3. **增量导出（低优先级）**：大文档导出时分片构建 DOM，避免一次性内存峰值

// benchmarks/chd-parser.bench.ts
import { parseCHDBlocks } from '../lib/chdParser';

function benchmarkParse(lines: number): void {
  const doc = generateTestDocument(lines);
  const start = performance.now();
  for (let i = 0; i < 100; i++) {
    parseCHDBlocks(doc);
  }
