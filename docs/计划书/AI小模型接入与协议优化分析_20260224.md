# AI 小模型接入与协议优化分析 (2026-02-24)

## 1. 核心变更背景

本次 `CHD v1.5` 协议更新的核心动作是将卡片样式体系从原本的 7+ 种（Normal, Stat, Summary, Orange, Emphasis, Quote, Code）大幅精简为 4 种核心样式（Normal, Highlight, Quote, Code）。

这一变更不仅是为了 UI 的统一，更是为了**扫清 AI 小模型（<3B 参数量）接入的最后一道障碍**。

## 2. 对 AI 模型的深度影响分析

### 2.1 决策空间降维 (Dimensionality Reduction)

在旧版协议中，AI 模型（尤其是小模型）经常面临极其微妙的分类决策：
- *"这段数据应该用 `stat` 还是 `highlight`？"*
- *"这段总结应该用 `summary` 还是 `orange`？"*

这种模糊的语义边界导致了两个问题：
1.  **决策熵高**：模型在生成 token 时概率分布平坦（High Entropy），容易出现“犹豫”或不一致。
2.  **幻觉风险**：为了强行区分微妙差别，模型可能会编造不存在的特征。

**优化后**：
分类任务被简化为清晰互斥的类别：
- 是代码？ -> `Code`
- 是引用/评价？ -> `Quote`
- 需要强调？ -> `Highlight`
- 其他所有？ -> `Normal`

这种**硬分类（Hard Classification）**极大地降低了模型的决策难度，使得 1.5B 甚至 Bert-Tiny 级别的模型也能达到极高的分类准确率。

### 2.2 训练数据质量提升 (Data Consistency)

高质量的训练数据是小模型微调（Fine-tuning）成功的关键。在旧体系下，不同的人类标注者对 `stat` 和 `highlight` 的理解不一致，导致训练数据中充满了噪声（Label Noise）。

**优化后**：
由于类别定义清晰，人类标注的一致性（Inter-annotator Agreement）将显著提升。清洗后的数据集将更加纯净，直接提升模型的收敛速度和最终效果。

### 2.3 矩形约束的战略意义 (Rectangular Constraint)

我们在协议中明确强调了**“矩形主导”**，并暂缓了圆形、切角等异形卡片的 AI 生成支持。

**原因**：
1.  **几何理解成本**：要求 AI 理解“圆形卡片适合放头像，切角卡片适合放标签”需要模型具备空间几何的常识，这对于纯文本模型（Text-only LLMs）是巨大的挑战，往往需要消耗大量参数去记忆这些规则。
2.  **布局泛化**：矩形是所有布局系统（Grid, Flex, Masonry）的原子单位。强制输出矩形，使得 AI 生成的内容可以无缝适配任何下游布局算法（如我们的智能分栏算法），实现了**内容生成与布局渲染的解耦**。

### 2.4 编辑器与渲染器的解耦优势 (Decoupling Editor & Renderer)

虽然我们在编辑器端引入了大量复杂的交互功能（如拖拽、微调、撤销/重做），但这些**全部基于前端实现，并不污染底层的 CHD 协议**。

- **对 AI 而言**：它只需要关注最简单的 Markdown 文本生成。无论编辑器多么华丽，AI 的任务始终是将非结构化文本转化为简单的 L1/L2 结构。
- **维度缩减 (Dimensionality Reduction)**：编辑器负责处理复杂的渲染细节（如圆角大小、阴影深浅），而 AI 只需负责“内容分类”。我们将视觉维度的复杂度全部剥离给了前端渲染引擎，AI 所需处理的特征维度大幅减少。
- **结论**：编辑器越强大，反而越能通过简单的协议来承载复杂的表现力，这对 AI 训练是**极度有利**的。

## 3. 微调数据迁移计划

为了适配新协议，现有的数据集需要进行以下清洗（Data Cleaning）：

| 旧标签 (Old Label) | 新标签 (New Label) | 迁移逻辑 |
| :--- | :--- | :--- |
| `stat` | `highlight` | 数据/指标合并入高亮样式 |
| `emphasis` | `highlight` | 强调合并入高亮 |
| `orange` | `highlight` | Hero/强调合并入高亮 |
| `summary` | `normal` / `highlight` | 根据内容重要性映射，通常为 Normal |
| `data` | `highlight` | 数据合并入高亮 |

## 4. 下一步行动建议

1.  **数据清洗脚本**：开发脚本将历史存量的 Markdown 文档中的旧样式自动批量替换为新样式。
2.  **Prompt 简化**：更新 System Prompt，移除关于 `stat`, `summary` 等样式的 Few-shot 示例，减少 Context Window 占用。
3.  **小模型验证**：使用清洗后的数据微调 Qwen-1.5B 或 TinyLlama，验证其在 v1.5 协议下的生成准确率。
