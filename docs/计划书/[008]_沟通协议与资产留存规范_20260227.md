# 沟通协议与资产留存规范

## 📋 沟通协议（Communication Protocol）

### 1. 沟通目标
- **统一语言**：确保所有参与者使用相同的技术术语和概念
- **减少歧义**：明确每个交付物的具体要求和验收标准
- **提高效率**：建立标准化的沟通模板和检查清单

### 2. 沟通层级

#### 2.1 上游数据提供方
| 沟通内容 | 格式要求 | 交付标准 |
|---------|----------|----------|
| 项目数据 | JSON + HTML文件对 | 必须符合[008]规范 |
| 更新通知 | Markdown变更日志 | 包含变更详情和影响范围 |
| 问题反馈 | Issue模板 | 使用预设模板，包含复现步骤 |

#### 2.2 下游系统对接
| 沟通内容 | 格式要求 | 交付标准 |
|---------|----------|----------|
| 接口需求 | JSON Schema | 提供完整验证规则 |
| 测试报告 | Markdown表格 | 包含测试用例和结果 |
| 部署文档 | Step-by-step指南 | 包含环境要求和故障排除 |

### 3. 沟通模板

#### 3.1 数据需求模板
```markdown
## 数据需求：[项目名称]

### 必需字段
- [ ] id: [具体值]
- [ ] type: [project/paper]
- [ ] title: [完整标题]
- [ ] brief: [50-100字描述]
- [ ] date: [YYYY-MM-DD]
- [ ] tags: [标签数组]

### 可选字段
- [ ] cover: [封面图路径]
- [ ] author: [作者信息]
- [ ] keywords: [搜索关键词]

### 验收标准
- [ ] JSON格式有效
- [ ] 所有必需字段已填写
- [ ] 中文路径编码正确
```

#### 3.2 问题报告模板
```markdown
## 问题报告：[问题简述]

### 环境信息
- 系统版本：[具体版本]
- 浏览器：[浏览器及版本]
- 复现频率：[总是/偶尔/一次]

### 复现步骤
1. [第一步]
2. [第二步]
3. [第三步]

### 期望结果
[描述期望的行为]

### 实际结果
[描述实际的行为]

### 附加信息
[截图、日志等]
```

## 🗂️ 资产留存规范（Asset Retention Specification）

### 1. 留存原则
- **完整性**：每次交互的所有相关资产必须完整保存
- **可追溯性**：每个资产都有明确的时间戳和版本标识
- **可检索性**：建立统一的索引和标签系统

### 2. 资产分类

#### 2.1 代码资产
| 类型 | 存储位置 | 命名规范 | 留存期限 |
|------|----------|----------|----------|
| 源代码 | `/src` | 功能_日期.ts | 永久 |
| 配置文件 | `/config` | 环境_版本.json | 永久 |
| 脚本文件 | `/scripts` | 操作_目标.sh | 永久 |

#### 2.2 文档资产
| 类型 | 存储位置 | 命名规范 | 留存期限 |
|------|----------|----------|----------|
| 需求文档 | `/docs` | [编号]_需求_日期.md | 永久 |
| 设计文档 | `/docs` | [编号]_设计_日期.md | 永久 |
| 测试报告 | `/docs/test` | [日期]_测试报告.md | 2年 |
| 会议纪要 | `/docs/meetings` | [日期]_会议纪要.md | 1年 |

#### 2.3 数据资产
| 类型 | 存储位置 | 命名规范 | 留存期限 |
|------|----------|----------|----------|
| 项目数据 | `/public/static_pages` | 名称.json/html | 永久 |
| 备份数据 | `/backups` | 备份_日期.zip | 1年 |
| 日志文件 | `/logs` | 系统_日期.log | 6个月 |

### 3. 留存流程

#### 3.1 每次Skill交互必须留存
1. **交互记录**：保存完整的对话记录
2. **代码变更**：保存所有修改的文件版本
3. **决策记录**：记录关键决策的理由和依据
4. **测试结果**：保存测试用例和结果

#### 3.2 资产命名规范
```
[类别]_[描述]_[日期]_[版本].[扩展名]

示例：
- 需求_区块链数据格式_20260227_v1.0.md
- 代码_路由处理_20260227_v2.1.ts
- 测试_首页加载_20260227_v1.0.json
```

### 4. 索引系统

#### 4.1 主索引文件
位置：`/docs/index.md`
内容：
```markdown
# 项目资产索引

## 最新更新
- [2026-02-27] 添加区块链项目数据格式规范
- [2026-02-27] 更新中文路径处理方案

## 按类别索引
- [需求文档](需求文档/)
- [设计文档](设计文档/)
- [测试报告](测试报告/)

## 按日期索引
- [2026-02-27](2026-02-27/)
```

#### 4.2 自动化索引生成
```bash
# 每日自动生成索引
./scripts/generate-index.sh

# 输出示例：
# docs/2026-02-27/index.md
# docs/assets/2026-02-27.json
```
