# 实施计划书 (Implementation Plan) - 卡片形态与布局革新

> **版本**: 1.1.0
> **日期**: 2026-02-21
> **分支**: `feature/card-shape-layout`
> **作者**: Trae AI & User
> **来源**: 基于 `卡片.txt` 可行性分析合并

## 1. 需求概述 (Overview)
当前 CHD (Card-based Hybrid Document) 系统以“矩形 + 网格”为主，视觉表现力单调。为了实现更接近“艺术化排版”或“PPT 风格”的自由度，本计划旨在引入**卡片形态 (Shape)** 与 **自由布局 (Layout)** 两个全新的维度。

**核心理念**: 将“模块”进一步拆分为“样式”和“布局”两个正交维度，在不改变后端解析逻辑（不引入拖拽、不修改协议）的前提下，通过前端渲染引擎的增强，极大丰富视觉表达力。

## 2. 功能范围 (Scope)

### 2.1 样式家族 (Style Families) - 扩展
| 家族 | 描述 | 技术方案 | 状态 |
| :--- | :--- | :--- | :--- |
| **矩形系 (Rect)** | 基础圆角、直角。 | `border-radius` | 现有 |
| **切角系 (Matrix)** | 赛博朋克风格切角。 | `clip-path: polygon(...)` | **新增** |
| **圆形系 (Circle)** | 正圆、椭圆。 | `border-radius: 50%` | **新增** |
| **箭头系 (Arrow)** | 具有指向性的卡片。 | `clip-path` + 伪元素 | **新增** |
| **有机系 (Organic)** | 不规则流体形状。 | SVG / `border-radius` 复杂参数 | *P2 (暂缓)* |

### 2.2 布局模式 (Layout Modes) - 扩展
| 模式 | 描述 | 技术方案 | 状态 |
| :--- | :--- | :--- | :--- |
| **网格 (Grid)** | 标准 12 列网格。 | CSS Grid | 现有 |
| **环绕 (Surround)** | 文本环绕图片/核心元素。 | `float` / Flex Order | **新增** |
| **环形 (Orbital)** | 中心 + 卫星环绕。 | 绝对定位 + `sin/cos` 计算 | **新增** |
| **主次 (Primary)** | 左主右次/上主下次。 | Grid Areas | **新增** |
| **重叠 (Overlap)** | 卡片部分重叠堆堆乐。 | 负 Margin / 绝对定位 | *P2 (暂缓)* |

### 2.3 兼容性规则 (Compatibility Rules)
建立简单的配置表验证器，防止“圆形卡片”在“紧凑网格”中表现不佳。
- 示例规则: `Orbital Layout` 推荐使用 `Circle` 或 `Organic` 样式；`Grid Layout` 禁用 `Arrow` (除非作为分隔符)。

## 3. 技术方案 (Technical Approach)

### 3.1 架构升级
```text
当前: [解析] -> [IR] -> [渲染(Grid)]
升级: [解析] -> [IR] -> [样式池] + [布局池] -> [组合引擎(兼容性检查)] -> [渲染]
```

### 3.2 关键实现
1.  **样式池 (Style Pool)**: 在 `globals.css` 中定义原子类 (e.g., `.shape-matrix-sm`, `.shape-arrow-right`)。
2.  **布局组件 (Layout Components)**:
    - `HubLayout.tsx`: 接收 `cards` 数组，分离第一个卡片为 `Center`，其余为 `Satellites`，计算绝对位置。
    - `SurroundLayout.tsx`: 使用 CSS Float 或 Grid Area 实现环绕。
3.  **参数透传**: 利用 Markdown 扩展属性 `::section layout="orbital"::` 和 `::card style="matrix"::` 进行控制。

## 4. 任务分解 (Task Breakdown)

- [ ] **L-03**: 在 `Section` 组件中增加 Layout 分发逻辑 (Switch Case)。

- [ ] **I-01**: 创建 showcase 文档，展示所有组合。
- [ ] **I-02**: 移动端适配测试（复杂布局回退为 Flex Column）。

## 5. 风险评估
- **计算复杂度**: 环形布局需要 JS 介入计算坐标。 -> *对策*: 使用 `useMemo` 缓存计算结果，仅在卡片数量变化时重算。
- **内容溢出**: 切角或圆形卡片可能裁剪内容。 -> *对策*: 为特殊形状卡片强制增加 `padding`。
