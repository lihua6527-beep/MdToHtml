# 多维布局系统重构计划 (Multidimensional Layout System Refactoring Plan)

## 1. 问题诊断 (Problem Diagnosis)

### 1.1 现状分析
用户反馈系统目前的排布“全都是从上至下的排布”，严重缺失“从左到右”的横向布局能力，被描述为系统的“阉割”。

### 1.2 根因定位
经过代码审查 (`src/components/CHD/Section.tsx` 和 `CHDRenderer.tsx`)，发现核心矛盾在于**渲染意图与容器实现的断裂**：

1.  **意图层 (CHDRenderer.tsx)**: 
    *   代码内部其实包含了一套“智能尺寸计算”逻辑 (Smart Sizing Logic)，根据文本长度和卡片关系 (`parallel`, `total-part`) 自动计算 `col-span` (跨列数)。
    *   这说明系统**原本设计了**横向并排 (Span 1 + Span 1) 的能力。

2.  **实现层 (Section.tsx)**:
    *   **默认行为错误**: 容器默认采用 `flex flex-col` (垂直堆叠)。
    *   **触发条件苛刻**: 只有当显式指定 `{layout="grid"}` 时，才会启用 Grid 布局。
    *   **结果**: 上游计算好的 `col-span` 属性因为容器不是 Grid 而失效，所有卡片被迫垂直堆叠。

## 2. 解决方案 (Solution Strategy)

### 2.1 核心目标
**“默认即多维”**：无需用户额外配置，系统应默认启用智能网格布局，自动根据内容密度实现左右并排或全宽显示。

### 2.2 重构方案

#### A. 激活网格系统 (Activate Grid System)
*   **修改**: 在 `Section.tsx` 中，将默认布局从 `flex-col` (垂直列表) 更改为 `grid` (网格)。
*   **策略**: 默认启用 `md:grid-cols-2` (双列网格)。
    *   移动端 (Mobile): 保持单列堆叠。
    *   桌面端 (Desktop): 默认双列，允许卡片通过 `col-span-2` 占据整行。

#### B. 语义化布局扩展 (Semantic Layout Extensions)
支持更多直观的布局指令，映射到特定的 Grid 配置：
*   `{layout="left-right"}`: 强制左右分栏 (1:1 或 1:2)。
*   `{layout="gallery"}`: 多列画廊模式 (3列或4列)。
*   `{layout="sidebar"}`: 侧边栏模式 (1/3 侧边栏 + 2/3 主内容)。

#### C. 智能流排布 (Smart Flow)
利用 `CHDRenderer` 现有的逻辑，优化卡片尺寸计算：
*   **短卡片 (Stat/Info)**: 自动设为 `col-span-1` -> 并排显示。
*   **长卡片 (Article/List)**: 自动设为 `col-span-2` -> 独占一行。
*   **关系映射**:
    *   `relation="parallel"` (并列关系): 强制所有子卡片为 `col-span-1`。

## 3. 执行计划 (Execution Plan)

1.  **文档编写**: 生成本计划书 (Done)。
2.  **组件修复 (`Section.tsx`)**: 
    *   修改默认布局逻辑：除非显式声明 `layout="list"`，否则默认启用 Grid。
    *   引入 `col-span` 类名动态生成逻辑。
3.  **渲染器增强 (`CHDRenderer.tsx`)**:
    *   优化 `col-span` 计算算法，确保视觉平衡（避免出现单行留白）。
4.  **验证**:
    *   使用编辑器实时预览，检查“组件展示”页面的布局变化。

---

**预期效果**:
系统将不再是单调的垂直流，而是呈现出错落有致的**Bento Grid (便当盒)** 式布局，自动适应内容，无需用户手动微调。
