# 卡片样式兼容性分析与实施方案

## 1. 背景与目标

本系统当前支持基于 `Grid` 的标准化卡片布局，样式较为单一（矩形为主）。根据 `card_shape_prototype_v1.html` 原型，我们需要引入更丰富的视觉形态（异形卡片）。

本报告旨在分析原型功能与现有系统的兼容性，并制定平滑升级方案。

## 2. 现有系统架构分析

### 2.1 核心组件
*   **Card.tsx**: 
    *   目前仅支持基础样式 (`normal`, `stat`, `quote` 等) 和颜色 (`chart-1`~`5`)。
    *   **局限性**: 缺乏对 `clip-path` (形状) 的支持。
*   **Themes.ts**:
    *   仅定义色彩变量，缺乏对形状圆角、阴影深度等 "UI Kit" 级别的定义。

## 3. 原型特性与兼容性差距分析

### 3.1 异形卡片 (Shape Utilities)
| 原型特性 | 现有支持 | 兼容性评估 | 解决方案 |
| :--- | :--- | :--- | :--- |
| **赛博切角 (Cyber Cut)** | 无 | 不兼容 | 需在 `Card` 组件新增 `shape` 属性，映射到 Tailwind `clip-path` 类。 |
| **箭头卡片 (Arrow)** | 无 | 不兼容 | 同上，需处理箭头拼接时的间距问题。 |
| **圆形/胶囊 (Circle/Pill)** | 无 | 部分兼容 (通过 CSS) | 新增 `shape="circle"` 属性，强制宽高比为 1:1。 |

### 3.2 组合样式 (Composition Styles)
| 原型特性 | 现有支持 | 兼容性评估 | 解决方案 |
| :--- | :--- | :--- | :--- |
| **破格悬浮 (Floating Badge)** | 无 | 困难 | 现有 Card `overflow-hidden` 会截断悬浮元素。需修改 Card 内部结构，允许子元素绝对定位溢出。 |

## 4. 升级实施方案

### 4.1 协议扩展 (CHD Protocol Extension)
不破坏现有 Markdown 结构，通过 **属性 (Attributes)** 扩展：

```markdown
<!-- 扩展 Card 属性 -->
:: card { shape="cut" badge="HOT!" }
```

### 4.2 核心代码重构计划

#### 阶段一：原子形状支持 (Shape Primitives)
1.  **CSS 注入**: 将原型中的 `.shape-cut`, `.clip-arrow-card` 等类移植到 `globals.css` 或 Tailwind 配置中。
2.  **Card 组件升级**:
    *   新增 `shape` prop。
    *   重构 DOM 结构以支持 `clip-path` (注意：clip-path 会裁剪阴影，需使用 `filter: drop-shadow` 替代 `box-shadow`)。

### 4.3 风险控制
*   **编辑器预览**: 异形卡片的拖拽可能存在点击区域判定问题（clip-path 区域外是否响应点击）。
*   **PDF/图片导出**: `clip-path` 在某些导出引擎中可能表现不一致，需验证 `html2canvas` 或打印样式的兼容性。

## 5. 下一步行动建议
1.  **优先实现**: 阶段一（Card Shape），因为改动小、收益大（视觉提升明显）。
2.  **技术验证**: 验证 `clip-path` 下的阴影渲染和点击事件响应。
