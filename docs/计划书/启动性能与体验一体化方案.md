# 启动性能与体验一体化方案

> 本文整合了《启动性能优化方案》《启动性能优化修正计划书》《启动体验优化_开屏动画方案》，并结合**Top 20 缓存策略**，形成关于“启动性能 + 启动体验”的完整方案。

---

## 1. 背景与问题回顾

### 1.1 现状
- 当前系统冷启动到页面完全渲染约需 **2 秒**。
- 启动时会遍历所有 Markdown 文件并全量解析，导致性能随文件数线性下降。

### 1.2 核心优化方向
- **物理层**: 放弃全量扫描，改为**仅读取最近访问的 20 个文档缓存**，实现 O(1) 启动。
- **感知层**: 引入 Loading UI (Splash Screen)，消除白屏，平滑过渡。

---

## 2. 启动性能优化方案（物理层）

### 2.1 Top 20 极速启动策略 (Top 20 Instant Start)
- **原理**: 无论磁盘上有多少文件（100 或 10000），启动时仅加载 `.metadata_cache.json` 中记录的 **Top 20 最近访问列表**。
- **流程**:
    1.  **读取缓存**: 启动时读取 `metadata_cache.json`。
    2.  **轻量校验**: 仅对缓存中的 20 个文件路径执行 `fs.stat`，验证文件是否存在及是否被修改。
    3.  **渲染**: 直接使用缓存数据渲染首页列表。
- **性能预期**:
    -   启动 I/O 耗时恒定 < 50ms。
    -   解析开销几乎为零（仅当缓存失效时才触发局部读取）。

### 2.2 智能局部读取 (Smart Partial Read) - 仅用于缓存失效或新增文件
- **场景**: 当用户打开新文件或缓存中的文件被外部修改时触发。
- **机制**:
    -   只读取文件头部 **4KB**。
    -   尝试解析 Frontmatter，成功则更新缓存，失败则回退全量读取。

## 3. 启动体验优化方案（感知层：Splash Screen）

### 3.1 设计目标
- 在极速启动（<500ms）的基础上，提供一个极简的过渡动画，掩盖 Electron 窗口初始化的短暂白屏。
- 即使数据加载瞬间完成，也保证动画平滑淡出，避免闪烁。

### 3.2 技术选型：Next.js Streaming SSR
- **Loading UI**: 使用 `loading.tsx` 渲染静态的 Logo 与呼吸动画。
- **数据流**:
    -   服务端并行执行 `loadTop20Cache()`。
    -   数据准备就绪后，流式替换 Loading UI 为真实文档列表。

## 4. 综合执行计划

### 4.1 阶段一：缓存层改造
- 实现 `LRUCacheManager`，限制缓存容量为 20。
- 改造 `getAllPosts` 接口，默认只返回缓存中的 Top 20 数据。

### 4.2 阶段二：启动流程对接
- 修改首页组件，仅展示缓存数据。
- 增加“加载更多/全部文档”的入口（对接《大数据量文档列表扩展方案》）。

### 4.3 阶段三：体验打磨
- 实现 Splash Screen 动画。
- 调试动画与真实列表的衔接，确保无视觉突兀。

---

## 5. 验收标准

### 5.1 性能指标
- **冷启动耗时**: 点击图标到列表展示 < 500ms（含 Electron 初始化）。
- **I/O 开销**: 启动期间文件读取次数 <= 20 次。

### 5.2 体验指标
- **零白屏**: 全程无纯白窗口。
- **内容一致性**: 列表状态（标题、标签、完成状态）与最后一次退出时完全一致。
