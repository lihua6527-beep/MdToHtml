# 拖拽交互与性能优化计划 (Drag & Drop Interaction & Performance Plan)

## 1. 核心目标
将卡片排序从传统的"方向键点击"升级为符合直觉的 **"长按拖拽 (Long Press & Drag)"** 交互。同时，针对拖拽过程中可能引发的频繁重渲染问题，实施 **"渲染暂停 (Render Pause)"** 策略，确保极致流畅的 60fps 体验。

## 2. 交互设计 (Interaction Design)

### 2.1 触发机制
*   **动作**: 长按卡片区域（非文本输入区）。
*   **时长**: **500ms - 800ms** (避免误触，且比用户建议的 3秒 更跟手)。
*   **反馈**:
    *   **视觉**: 卡片轻微浮起 (Scale 1.05)，阴影加深 (Shadow-lg)，原位置显示虚线占位符。
    *   **触觉**: 震动反馈 (如设备支持)。

### 2.2 拖拽过程
*   **跟随**: 浮动卡片跟随手指/鼠标移动。
*   **占位**: 占位符 (Placeholder) 根据当前鼠标位置，实时计算并挤占目标网格位置。
*   **动画**: 使用 FLIP (First, Last, Invert, Play) 动画技术，使周围卡片平滑让位。

## 3. 性能优化策略 (Performance Optimization)

**核心原则**: **拖拽期间，严禁触发 Markdown 全文解析与 React 树重绘。**

### 3.1 渲染暂停机制 (Render Pause Strategy)
1.  **Drag Start**:
    *   触发 `onDragStart` 事件。
    *   **锁定 Renderer**: 设置全局状态 `isDragging = true`。通知 `CHDRenderer` 暂停对 `markdown` prop 变化的响应（即使外部文件发生变更）。
    *   **快照 DOM**: 将被拖拽卡片的 DOM 克隆一份作为浮动层 (Overlay)，原 DOM 隐藏或变更为占位符。

2.  **Drag Move**:
    *   **纯 CSS 变换**: 仅修改浮动层的 `transform: translate(x, y)` 属性。
    *   **本地计算**: 仅在 React 内部计算占位符的索引变化 (`sourceIndex` -> `targetIndex`)。
    *   **零 IO**: 此时 **绝对不** 修改 Markdown 文本，**不** 触发文件写入，**不** 触发自动保存。

3.  **Drag End (Drop)**:
    *   **计算最终位移**: 获取最终的 `targetIndex`。
    *   **解锁 Renderer**: 设置 `isDragging = false`。
    *   **原子更新**:
        1.  根据 `targetIndex` 生成 Markdown AST 的 `moveBlock` 操作。
        2.  一次性写入新的 Markdown 内容。
        3.  `CHDRenderer` 接收新文本，进行一次全量 Diff 渲染。

### 3.2 架构风险与应对
*   **风险**: 拖拽过程中，若后台有自动保存 (Auto-Save) 或其他并发修改，可能导致版本冲突。
*   **应对**: 引入 **"交互锁" (Interaction Lock)**。
    *   当 `isDragging === true` 时，阻断所有来自后端的 Markdown 更新推送。
    *   Drop 完成后，强制以当前拖拽结果为准，覆盖中间可能产生的外部变更。

## 4. 实现技术栈
*   **库选型**: `dnd-kit` (推荐，现代、轻量、无障碍友好) 或 `react-beautiful-dnd`。
*   **算法**: 需要实现 `Visual Grid Index` (2D 视觉坐标) 到 `Markdown Block Index` (1D 文本顺序) 的双向映射算法。
