# 前端交互与工作流 (Frontend Workflow)

> 整合自 `前端工作.txt` 与 `前端输入的工作.txt`

## 1. 核心矛盾与解决方案
当前设计的核心矛盾：**不应该让渲染器去处理不规范文本，但用户又无法天然写出完美CHD文档。**
解决这个矛盾的方案，不是在渲染前“适配”，而是在用户写作过程中“引导与辅助”。

## 2. 三级渐进式引导系统
理想的方案是构建一个边写边教的智能编辑器，让“约束”变得无形且友好。

### 2.1 第一层：实时语法提示（写作时）
*   **功能**: 像拼写检查器一样，对不符合CHD语法的部分（如误用四级标题、缺少必需元数据）进行下划线提示。
*   **目标**: 即时纠错，培养用户习惯。
*   **工作量**: 低 (正则/规则)。

### 2.2 第二层：结构化写作辅助（输入时）
*   **功能**:
    *   **智能补全**: 输入 `/亮点` 自动展开 YAML 结构。
    *   **片段库**: 一键插入“三点式布局”、“数据对比”等标准卡片片段。
    *   **向导模式**: 侧边栏问答，自动生成文档框架。
*   **目标**: 让用户“填空”而非“创造”结构。
*   **工作量**: 中 (模板引擎)。

### 2.3 第三层：提交时智能转换与修正（提交时）
*   **功能**: 提交时启动蒸馏后的小模型进行处理。
    *   **结构纠正**: 自动拆分长文本。
    *   **内容归类**: 自动打标签（概念/示例/数据）。
    *   **格式标准化**: 确保 AST 符合 CHD 协议。
*   **目标**: 最后的安全网，处理模糊问题。
*   **工作量**: 高 (模型训练)。

## 3. 演进路线图
1.  **初始阶段 (表单式)**: 强制用户使用表单输入，产出绝对规范的“干净”数据，用于后续模型训练。
2.  **数据驱动阶段**: 积累数据，训练“任务特化”小模型。
3.  **智能增强阶段**: 小模型接入编辑器，实现从“填表”到“智能辅助创作”的进化。
