# 编辑器智能导引优化方案 (Editor Intelligent Guidance Optimization Proposal)

## 1. 背景与目标
当前 CHD 编辑器已实现基础的“输入->渲染”功能，但缺乏对用户输入内容的结构化校验与引导。用户在编写 Markdown 时，容易出现层级错误（如 L1 直接包含文本而无卡片）、属性拼写错误（如 `card-style` 误写）或语法结构混乱。
本方案旨在将编辑器从“文本录入工具”升级为“智能辅助 IDE”，引入类似编译器的实时诊断、错误提示与自动修复建议功能。

## 2. 核心功能设计

### 2.1 实时语法分析器 (Live Syntax Analyzer)
**目标**: 在用户输入时实时解析 CHD 协议结构，建立 AST (抽象语法树) 映射。
*   **实现机制**:
    *   **Tokenizer**: 扩展 Markdown 解析器，识别 CHD 特有的 `#` (L1), `##` (L2), `###` (L3) 层级结构。
    *   **Schema Validator**: 定义 CHD 结构规范：
        *   `Root` 必须包含 `H1 (#)`。
        *   `H1` 下必须包含 `H2 (##)`。
        *   `H2` (Section) 下必须包含 `H3 (###)` (Card)。
        *   `H3` 下才允许包含具体文本内容。
*   **状态**: 实时监控，防抖(Debounce) 300ms 触发分析。

### 2.2 错误诊断系统 (Diagnostic System)
**目标**: 像 VS Code 一样在编辑器左侧行号处显示错误/警告图标，并在下方显示波浪线。
*   **错误类型**:
    *   **[Critical] 结构错误**: "L2 Section 中直接包含文本内容，未包裹在 L3 Card 中。"
    *   **[Error] 属性错误**: "`card-sytle` 属性拼写错误，建议修改为 `card-style`。"
    *   **[Warning] 最佳实践**: "卡片内容超过 800 字，建议拆分以保持原子性。"
*   **UI 表现**:
    *   编辑器内红色/黄色波浪线。
    *   鼠标悬停显示具体错误信息。
    *   底部状态栏显示 "3 Errors, 1 Warning"。

### 2.3 智能修复建议 (Quick Fix)
**目标**: 提供一键修复功能，降低用户修正成本。
*   **场景示例**:
    *   **场景**: 用户在 L2 下直接写了文本。
    *   **建议**: "Wrap in Card" (自动包裹 `### New Card`)。
    *   **场景**: 检测到未闭合的代码块。
    *   **建议**: "Close Code Block" (自动追加 ` ``` `)。

### 2.4 属性自动补全 (IntelliSense)
**目标**: 输入 `{` 时触发属性补全。
*   **实现**:
    *   输入 `card-` 自动提示 `style`, `col-span`, `row-span`。
    *   输入 `style="` 自动列举 `stat`, `highlight`, `quote`, `code` 等合法枚举值。

## 3. 技术实现路径

### Phase 1: 基础校验 (Linting)
*   引入轻量级 Markdown AST 解析库 (如 `remark` 或 `unified`)。
*   编写自定义 CHD Lint 插件。
*   集成到 Monaco Editor (或当前 Textarea 的替代品) 中。

### Phase 2: 交互升级
*   将当前的 `textarea` 替换为 `Monaco Editor` (VS Code 内核) 或 `CodeMirror`。
*   利用 Editor 提供的 `Markers` API 实现波浪线和 Hover 提示。

### Phase 3: 语言服务器 (LSP)
*   (远期规划) 封装 CHD Language Server，不仅服务于 Web 编辑器，未来可发布 VS Code 插件。

## 4. 预期收益
*   **错误率降低**: 结构性错误减少 90% 以上。
*   **学习成本降低**: 用户无需死记 CHD 协议细节，编辑器实时引导。
*   **文档质量提升**: 强制的原子性检查确保生成文档的高可读性。
