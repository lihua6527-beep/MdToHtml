## 2. 可行性评估与技术债务 (Feasibility & Tech Debt)

### 2.1 现有架构瓶颈
1.  **编辑器体验受限**: `MarkdownEditor.tsx` 依赖原生 `<textarea>`。
    *   *后果*: 无法实现语法高亮、自动补全、多光标编辑，且大文件性能差。
2.  **解析器脆弱性**: `chdParser.ts` 采用手动行遍历。
    *   *后果*: 维护成本高，难以扩展新语法（如 L3+ 嵌套或自定义指令），且容易产生解析 Bug。
3.  **样式硬编码**: `Card.tsx` 中大量使用内联的 Tailwind 类组合（如莫兰迪色值）。
    *   *后果*: 无法通过配置文件统一调整主题，设计变更成本高。

### 2.2 性能指标
*   **渲染性能**: 当前每次按键触发全量解析与 React 协调 (Reconciliation)。对于 <1000 行的文档尚可，但在大文档下会出现卡顿。
*   **同步延迟**: 当前同步机制基于 DOM 滚动事件，性能良好，但在复杂 DOM 结构下可能存在抖动。

### 验收标准 (Acceptance Criteria)
1.  **功能**: 编辑器支持 Markdown 语法高亮，且不丢失原有的双向同步功能。
2.  **性能**: 1万行文档输入延迟 < 50ms。
3.  **兼容性**: 构建产物可在无 Node.js 环境下通过双击 `index.html` (或简单 HTTP Server) 运行。
4.  **可维护性**: 新增 UI 组件必须使用 shadcn/ui 标准；解析逻辑必须有单元测试覆盖。
