## 一、设计变更摘要 (Change Summary)

### 1.1 与 v1.0 的关键差异

| 维度 | v1.0 (原计划) | v2.0 (细化确认版) |
|------|---------------|-------------------|
| **AI 配置** | 多参数可调（temperature/maxTokens/stream等） | **极致简化**：仅 DeepSeek API Key，通过 `.env.local` 环境变量注入 |
| **模型策略** | 多提供商（OpenAI/Ollama/DeepSeek）+ 参数可配置 | **纯云端 & 专用**：仅 DeepSeek V4，Flash/Pro 双模型下拉选择 |
| **结果管理** | 直接渲染 / 编辑器注入双模式 | **临时文件 + 多版本并列展示**：先存临时 Markdown，可多次生成并列对比 |
| **HTML 导出** | 调用 HtmlBundler.bundle() | **浏览器下载队列**：点击渲染按钮生成 HTML 后通过浏览器原生下载 |
| **退出逻辑** | 无特殊处理 | **退出确认弹窗**：询问是否保存临时文件为 `{源文件名}标准化.md` |
| **用户视角** | 复杂的 AI 配置页面 | **与现有编辑器体验一致**：仅增加一个「自由输入文档」的入口 |
| **多版本** | 重新生成覆盖前一次结果 | **多版本并列**：相同源文件名 + 序号区分，可自由选择渲染查看 |

### 1.2 设计原则

1. **最小侵入**：不改动现有编辑-渲染管线的核心逻辑
2. **体验统一**：AI 页面的操作流与现有编辑器尽量一致（预览、渲染、下载）
3. **配置极简**：仅 DeepSeek API Key 一个配置项 + 模型下拉选择（Flash/Pro）
4. **增量迭代**：先最简可用，后续再考虑扩展

### 2.2 核心数据流

```
用户操作                                                    AI 页面内部状态
─────────                                                ────────────────

① 输入文本 / 拖拽文件 / 导入URL
    │
    ▼
② 点击「AI 生成」
    │
    ▼
③ AIService.generate()
    │  ├── 读取 .env.local 获取 DEEPSEEK_API_KEY
    │  ├── 使用默认 Prompt + 用户文本 → 调用云端 API
    │  └── 返回 CHD Markdown
    │
    ▼
④ TempFileManager.createTemp()
    │  ├── 文件名: {源文件名}_标准化.md (首次)
    │  ├── 文件名: {源文件名}_标准化_2.md (第二次)
    │  ├── 文件名: {源文件名}_标准化_3.md (第三次)
    │  └── 存储位置: 内存/会话缓存 (页面关闭即丢弃)
    │
    ▼
⑤ 临时文件列表更新（多版本并列展示）
    │
    ├── 用户点击某版本的「渲染」按钮
    │   └── 该版本 → CHDRenderer 实时预览
    │
    ├── 用户点击某版本的「下载 HTML」按钮
    │   └── CHDRenderer 渲染 → HtmlBundler 打包
    │       → 生成 HTML 字符串 → Blob → URL.createObjectURL
    │       → 触发 `<a download>` 浏览器原生下载
    │
    ├── 用户点击「换个风格」
    │   └── AIService.regenerate() 切换备选 Prompt → 新版本
    │
    └── 用户关闭页面 / 离开
        └── 弹出确认框：「有 X 个未保存的临时文档，是否保存？」
            ├── 是 → TempFileManager.confirmSave() → 写入 posts/
            ├── 否 → 丢弃所有临时文件
            └── 取消 → 留在当前页面
```

### 3.2 新服务：TempFileManager

#### 文件：`src/services/ai/TempFileManager.ts`

```typescript
/**
 * 临时文件管理器
 * 
 * 职责：
 * 1. 管理 AI 生成的临时 Markdown 文件（仅内存/会话级别）
 * 2. 自动命名：{源文件名}_标准化[_序号].md
 * 3. 确认保存时写入 posts/ 目录
 * 4. 页面退出时提示是否保存
 * 
 * 与现有 FileService 的关系：
 * - TempFileManager 管理「未确认」的临时文件
 * - 确认保存后委托 FileService 写入 posts/ 目录
 * - 不修改 FileService 现有逻辑
 */

interface TempFileItem {
  id: string;                    // 唯一 ID (uuid)
  fileName: string;              // 文件名（如 "我的论文_标准化.md"）
  content: string;               // Markdown 内容
  createdAt: Date;               // 创建时间
  sourceFileName: string;        // 源文件名
  version: number;               // 版本号（1, 2, 3...）
  isDefault: boolean;            // 是否为默认版本（第一版）
}

class TempFileManager {
  // 存储：会话级别 Map（页面刷新后丢失）
  private static files: Map<string, TempFileItem> = new Map();
  private static versionCounter: Map<string, number> = new Map();

  /**
   * 创建新的临时文件
   * @param sourceFileName 源文件名（如"我的论文"）
   * @param content Markdown 内容
   * @param isDefault 是否为默认版本
   */
  static createTemp(
    sourceFileName: string, 
    content: string, 
    isDefault: boolean = false
  ): TempFileItem;

  /**
   * 获取所有临时文件（按创建时间排序）
   */
  static listTemps(): TempFileItem[];

  /**
   * 获取指定临时文件
   */
  static getTemp(id: string): TempFileItem | undefined;

  /**
   * 删除指定临时文件
   */
  static deleteTemp(id: string): void;

  /**
   * 清空所有临时文件
   */
  static clearAll(): void;

  /**
   * 确认保存：将临时文件写入 posts/ 目录
   * 委托 FileService.saveFile() 实现
   */
  static async confirmSave(id: string): Promise<boolean>;

  /**
   * 批量确认保存所有临时文件
   */
  static async confirmSaveAll(): Promise<number>;

  /**
   * 获取未保存的临时文件数量
   */
  static getUnsavedCount(): number;

  /**
   * 自动生成文件名
   * 规则：
   *   - 首次: {源文件名}_标准化.md
   *   - 后续: {源文件名}_标准化_{version}.md
   */
  private static generateFileName(sourceFileName: string): string;
}

// 生成文件名示例
// sourceFileName = "软件工程论文"
// 第一次 → "软件工程论文_标准化.md"
// 第二次 → "软件工程论文_标准化_2.md"
// 第三次 → "软件工程论文_标准化_3.md"
```

### 3.3 服务：AIService (精简版)

#### 文件：`src/services/ai/AIService.ts`

```typescript
/**
 * AI 服务 - DeepSeek V4 API 调用
 * 
 * 设计原则：
 * - 极简：仅支持 DeepSeek V4 云端 API
 * - 模型选择：前端下拉菜单（Flash / Pro），通过 API 参数传递
 * - API Key：仅通过环境变量注入，不硬编码
 */

interface AIServiceConfig {
  apiKey: string;              // 从环境变量 DEEPSEEK_API_KEY 读取
  model: 'deepseek-chat' | 'deepseek-reasoner';  // Flash → deepseek-chat, Pro → deepseek-reasoner
}

class AIService {
  // 从环境变量读取配置
  static getConfig(): AIServiceConfig {
    return {
      apiKey: process.env.DEEPSEEK_API_KEY || '',
      model: 'deepseek-chat',  // 默认 Flash 模型
    };
  }

  /**
   * 使用指定模型生成 CHD Markdown
   * @param text 用户原始文本
   * @param model 'deepseek-chat'(Flash) 或 'deepseek-reasoner'(Pro)
   * @param signal 取消信号
   */
  static async generate(
    text: string, 
    model: 'deepseek-chat' | 'deepseek-reasoner' = 'deepseek-chat',
    signal?: AbortSignal
  ): Promise<string>;

  /**
   * 使用备选 Prompt 重新生成（"换个风格"）
   * @param originalText 原始用户输入
   * @param previousResult 上次生成结果
   * @param promptVariant Prompt 变体
   * @param model 模型选择
   * @param signal 取消信号
   */
  static async regenerate(
    originalText: string,
    previousResult: string,
    promptVariant: 'default' | 'alternative',
    model: 'deepseek-chat' | 'deepseek-reasoner' = 'deepseek-chat',
    signal?: AbortSignal
  ): Promise<string>;
}
```

**环境变量配置**（仅需要以下一项）：
```bash
# .env.local
DEEPSEEK_API_KEY=sk-your-deepseek-api-key-here
```

> **安全说明**：`.env.local` 已被加入 `.gitignore`，不会提交到版本控制。API Key 仅在服务端 API Route 中使用，不会泄露到客户端。Endpoint 固定为 `https://api.deepseek.com/v1`。

## 五、HTML 下载流程详解

### 5.1 浏览器原生下载流程

这是与 v1.0 方案最大的差异点之一——不再通过后端导出，而是利用浏览器原生下载能力。

```
用户在 AITempFileList 中点击「下载 HTML」
    │
    ▼
① 获取选中临时文件的 Markdown 内容
    │
    ▼
② CHDRenderer 解析 + 渲染该 Markdown
    │
    ▼
③ HtmlBundler.bundle() 打包为完整 HTML 字符串
    │
    ▼
④ 前端生成 Blob：
    const blob = new Blob([htmlString], { type: 'text/html;charset=utf-8' });
    const url = URL.createObjectURL(blob);
    │
    ▼
⑤ 触发浏览器下载：
    const a = document.createElement('a');
    a.href = url;
    a.download = '我的论文_标准化.html';  // 文件名自动匹配
    a.click();
    │
    ▼
⑥ 释放内存：
    URL.revokeObjectURL(url);
    │
    ▼
⑦ 下载出现在浏览器下载队列中，用户可正常保存到本地
```

**优势**：
- 无需后端导出 API
- 下载进度由浏览器原生管理
- 用户可查看下载历史、重命名、选择保存位置
- 与现有 HtmlBundler 完全兼容

### 5.2 「渲染预览」按钮 vs 「下载 HTML」按钮

| 按钮 | 行为 | 区别 |
|------|------|------|
| **渲染预览** | 选择该文件 → 在下方预览区域用 CHDRenderer 渲染 | 仅页面内预览，不产生文件 |
| **下载 HTML** | 生成完整 HTML → 触发浏览器下载 | 产生可保存的独立 HTML 文件 |

> **提示**：用户先点击「渲染预览」查看效果，满意后再点击「下载 HTML」保存。

## 六、退出流程详解

### 6.1 流程状态机

```
[用户正在编辑 AI 页面]
    │
    ├── 无临时文件 → 直接离开（无弹窗）
    │
    └── 有临时文件
        │
        ├── 所有文件已保存 → 直接离开（无弹窗）
        │
        └── 存在未保存的临时文件
            │
            ▼
        ┌────────────────────────────┐
        │  AISaveDialog 弹窗          │
        │                            │
        │  [保存] → FileService 写入  │
        │  [不保存] → 全部丢弃         │
        │  [取消] → 关闭弹窗，留在页面  │
        └────────────────────────────┘
```

### 6.2 实现方式

```typescript
// 在 AI 页面组件中使用 useEffect + beforeunload 事件
useEffect(() => {
  const handleBeforeUnload = (e: BeforeUnloadEvent) => {
    const unsavedCount = TempFileManager.getUnsavedCount();
    if (unsavedCount > 0) {
      // 标准浏览器离开确认
      e.preventDefault();
      e.returnValue = '';
    }
  };

  window.addEventListener('beforeunload', handleBeforeUnload);
  return () => window.removeEventListener('beforeunload', handleBeforeUnload);
}, []);

// 同时捕获路由离开（Next.js App Router）
// 使用 useRouter + 自定义确认逻辑
```

## 七、AI 配置方案 — 极致简化

### 7.1 配置项一览

| 配置项 | 方式 | 必需 | 说明 |
|--------|------|------|------|
| `DEEPSEEK_API_KEY` | `.env.local` | **是** | DeepSeek API 密钥，非硬编码 |
| 模型选择 | 前端下拉菜单 | **是** | Flash (`deepseek-chat`) / Pro (`deepseek-reasoner`) |

> **不需要**：temperature、maxTokens、streamOutput、defaultMode 等参数全部去掉。
> **不需要**：提供商切换、API Endpoint 配置（固定为 DeepSeek）。
> **不需要**：本地 Ollama 或其他本地方案。

### 7.2 安全机制

```bash
# .env.local 示例（已加入 .gitignore）
DEEPSEEK_API_KEY=sk-xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx
```

**读取方式**：
```typescript
// 仅服务端可读取（API Route 中）
const apiKey = process.env.DEEPSEEK_API_KEY;

// 客户端不接触 API Key
// 所有 AI 请求通过 Next.js API Route 代理
// 客户端仅发送用户文本 + 模型选择（flash/pro）到 /api/ai/generate
```

**防止泄露**：
1. `.env.local` 加入 `.gitignore`
2. API Key 仅在服务端 API Route 中使用

## 八、用户交互流程总览

### 8.1 典型使用场景

```
场景：用户有一篇论文需要转换为 CHD 风格 HTML

① 打开 /ai-input 页面
    │
② 输入论文标题和正文（或拖拽 .md 文件）
    │
③ 点击「AI 生成」
    │  显示加载状态
    │  API 调用完成
    ↓
④ 生成结果 → "我的论文_标准化.md" 出现在文件列表
    │  自动选中并预览渲染效果
    │
⑤ 用户觉得风格不太满意
    │
⑥ 点击「换个风格」
    │  生成 "我的论文_标准化_2.md"
    │  列表中出现第二个版本
    ↓
⑦ 两个版本并列展示，用户点击切换查看
    │  发现 v2 更喜欢
    │
⑧ 点击 v2 的「下载 HTML」
    │  浏览器下载 "我的论文_标准化_2.html"
    │
⑨ 用户继续调整输入，再次生成...
    │  生成 "我的论文_标准化_3.md"
    │
⑩ 用户关闭页面
    │  弹窗提示：有 2 个未保存的临时文件
    │  用户点击「不保存」
    ↓
⑪ 所有临时文件丢弃，页面关闭
```

### 8.2 用户视角的体验变化

**与现有编辑器的对比**：

| 操作 | 现有编辑器 | AI 页面 (新增) |
|------|-----------|----------------|
| 输入方式 | 手动编写 Markdown | 自由输入文本/文件/URL |
| 文档管理 | 从 posts/ 加载 | AI 生成 → 临时文件列表 |
| 预览 | 右侧实时渲染 | 下方实时渲染 |
| 下载 HTML | 导出按钮 → 后端处理 | 下载按钮 → 浏览器原生下载 |

| 多版本 | 覆盖保存 | 多版本并列展示 |

**用户的理解**：
> "这个新功能和原来的编辑器差不多，就是多了个可以随便输入文档的地方，AI 帮我转成需要的格式，然后我预览、下载，和原来一样方便。"
