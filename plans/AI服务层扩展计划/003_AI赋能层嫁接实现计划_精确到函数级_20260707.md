### 🔴 关键阻断项 —— 已解决

**HtmlBundler.bundle() 在浏览器端不可用。** 原因是它依赖 `react-dom/server` 的 `renderToStaticMarkup()`，这是 Node.js 服务端 API。

**决策：采用方案 A（后端导出）**。
- 新增 `src/app/api/ai/export/route.ts`
- POST 接收 `{ markdown, title, theme }` → 在服务端调用 `HtmlBundler.bundle()` → 返回 `text/html` Blob
- 前端通过 `fetch POST → Blob → browser download` 触发下载队列

**Prompt A（默认，效果最稳定）— 完整文本模板：**

将基于 `MdToHtml/CHD协议.md` 内容构建，关键要素：
- 角色定义（信息架构师 + UI 设计师）
- CHD 三级刚性结构规则（L0 YAML Frontmatter → L1 `## Section {layout="grid" columns=N}` → L2 `### Card {card-style="..." icon="..."}`）
- 卡片样式约束（仅 `normal/highlight/quote` 三种）
- 智能列数规则（1-4 张 → N 列，5+ 张 → 3 列）
- 富文本规范（LaTeX `$...$`、GFM 表格、代码块）
- Frontmatter 必填字段（title、subtitle、tags）
- 负面示例（禁止 `####` 四级标题、禁止 HTML table、禁止越级）

**Prompt B（备选，换个风格）：**

与 Prompt A 相同结构，但调整以下参数：
- 更侧重"学术风格"输出
- 更倾向于使用 `highlight` + `quote` 卡片
- 列数偏好 2 列布局

> **注意**：完整的 Prompt 文本将直接硬编码在 `PromptEngine.ts` 中（约 150-200 行），不拆分为独立文件。

5. 返回 `{ markdown: "...", usage: {...} }`

## 三、🔴 HtmlBundler 浏览器端不可用 — 解决方案

### 问题根因

`HtmlBundler.bundle()` 方法第 21 行调用 `renderToStaticMarkup()`，该函数来自 `react-dom/server`，**仅在 Node.js 环境中可用**。因此用户点击「下载 HTML」时不能在前端直接调用此方法。

### 推荐方案：新增 `/api/ai/export` 端点

在 `src/app/api/ai/export/route.ts` 中创建：

```typescript
// POST /api/ai/export
export async function POST(request: NextRequest): Promise<NextResponse> {
  const { markdown, title, theme } = await request.json();
  
  // 在服务端调用 HtmlBundler.bundle()（这里可以正常使用 renderToStaticMarkup）
  const blob = await HtmlBundler.bundle(markdown, title || '文档', theme || 'ocean');
  const buffer = await blob.arrayBuffer();
  
  return new NextResponse(buffer, {
    headers: {
      'Content-Type': 'text/html;charset=utf-8',
      'Content-Disposition': `attachment; filename="${encodeURIComponent(title || '文档')}.html"`,
    },
  });
}
```

**前端下载调整为：**
```typescript
function handleDownload(fileId: string): void {
  const file = TempFileManager.getTemp(fileId);
  if (!file) return;

  // 方案 1：直接导航到下载端点（浏览器自动下载）
  const url = `/api/ai/export?markdown=${encodeURIComponent(file.content)}&title=${encodeURIComponent(file.fileName)}`;
  window.open(url, '_blank');

  // 方案 2（推荐，更安全）：POST + Blob 下载
  // fetch POST → 获取 Blob → triggerBrowserDownload()
}
```

**但这又回到了后端下载模式。** 回顾用户需求：用户明确想要浏览器原生下载队列。

**最终方案：HTML 字符串纯前端构建**

不调用 `HtmlBundler.bundle()`，而是在前端直接构建 HTML 字符串：

```typescript
function buildHtmlString(markdown: string, title: string): string {
  // 在页面中已有一个隐藏的 <div id="chd-render-target"> 使用 CHDRenderer 渲染
  // 渲染完成后，获取其 innerHTML 作为内容
  const renderedElement = document.getElementById('chd-render-target');
  const contentHtml = renderedElement?.innerHTML || '';

  // 获取当前页面 CSS（与 CssExtractor 相同逻辑）
  const styles = Array.from(document.styleSheets)
    .map(sheet => {
      try {
        return Array.from(sheet.cssRules).map(r => r.cssText).join('\n');
      } catch { return ''; }
    })
    .join('\n');

  return `<!DOCTYPE html>
<html lang="zh-CN" data-theme="ocean">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
  <title>${title}</title>
  <style>${styles}</style>
</head>
<body>
  ${contentHtml}
</body>
</html>`;
}
```

**此方案的优点**：完全在浏览器端完成，用户下载的是和页面上看到一样的渲染结果。
**缺点**：CSS 提取可能不完整，需要测试验证。
