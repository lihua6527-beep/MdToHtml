# Plan 00: CI/CD 流水线总体计划书

> **计划日期**：2026-07-12  
> **计划目标**：为 MdToHtml Pro 建立完整的 CI/CD 流水线，实现自动化测试 → 代码质量检查 → 构建验证 → 打包发布的流水线闭环。  
> **核心原则**：**先搭骨架，再填血肉，最后自动化**。

---

## 一、为什么需要 CI/CD 流水线？

### 1.1 当前痛点

```
当前开发流程（纯手动）:

  [写代码] → [手动 npm run build] → [手动 npm test] → [手动打包]
      ↑                                                    │
      └────────────────── 发现问题回到起点 ──────────────────┘

问题：
  ❌ 无自动化测试 — 改代码不知道会不会破坏已有功能
  ❌ 无代码质量门禁 — TypeScript 错误、lint 问题靠肉眼
  ❌ 无构建验证 — 构建失败要到提交后才发现
  ❌ 无部署流水线 — 打包分发全靠手动操作
  ❌ 面试无亮点 — "你没有用过 CI？"
```

### 1.2 目标流水线

```
目标开发流程（自动 CI/CD）:

  [git push]
      │
      ▼
  ┌─────────────────────────────────────────────────────┐
  │  GitHub Actions CI Pipeline                         │
  │                                                     │
  │  ① Lint : eslint --max-warnings 0                   │
  │  ② TypeCheck : tsc --noEmit                    [并行]│
  │  ③ Unit Test : jest --coverage                      │
  │                                                     │
  │  ④ Build : next build                               │
  │                                                     │
  │  ⑤ E2E Test : playwright test                       │
  │                                                     │
  │  ⑥ 生成报告：Coverage + Performance + Bundle        │
  └──────────────────────┬──────────────────────────────┘
                         │ 全部通过
                         ▼
  ┌─────────────────────────────────────────────────────┐
  │  Release Pipeline (手动触发)                         │
  │                                                     │
  │  ① 版本号自动升级 (npm version patch)               │
  │  ② Electron 自动打包 (electron-builder)             │
  │  ③ GitHub Release 创建 + Release Notes              │
  │  ④ 安装包上传至 Release Assets                      │
  └─────────────────────────────────────────────────────┘
```

### 1.3 收益

| 收益 | 量化指标 |
|------|---------|
| 回归测试自动化 | 从 15 分钟手动测试 → 2 分钟自动运行 |
| 代码质量门禁 | 从"看心情检查" → "强制通过" |
| 构建失败发现 | 从"合并后" → "PR 阶段" |
| 打包发布 | 从 20 分钟手动操作 → 1 键自动完成 |
| 面试价值 | "我有完整的 CI/CD 实战经验" |

## 二、整体架构设计

### 2.1 流水线层级

```
PR 级（自动触发）
┌──────────────────────────────────────────────────┐
│  Lint & TypeCheck & Unit Test                    │
│  → 耗时 ~30s，PR 必过门禁                        │
└──────────────────────────────────────────────────┘

Merge 级（自动触发, push to main）
┌──────────────────────────────────────────────────┐
│  Build & E2E Test                                │
│  → 耗时 ~3min，确保主分支始终绿色               │
└──────────────────────────────────────────────────┘

Release 级（手动触发, GitHub Release）
┌──────────────────────────────────────────────────┐
│  Electron Build & Publish                        │
│  → 耗时 ~10min，1 键发布                        │
└──────────────────────────────────────────────────┘
```

### 2.2 工作流文件结构

```
.github/
└── workflows/
    ├── pr-check.yml           # PR 检查（Lint + TypeCheck + Test）
    ├── ci.yml                 # 合并后 CI（Build + E2E）
    ├── release.yml            # 发布流水线（打包 + 发布）
    └── sync-labels.yml        # PR 标签同步（辅助）
```

## 三、阶段一：PR 检查流水线（第 1-2 天）

### 3.1 目标

每个 Pull Request 自动触发，确保代码质量门禁。

### 3.2 实现步骤

#### Step 1: 创建 `.github/workflows/pr-check.yml`

```yaml
name: PR Check

on:
  pull_request:
    branches: [main, develop]
    paths-ignore:
      - 'docs/**'
      - '**.md'

jobs:
  quality:
    name: Code Quality
    runs-on: ubuntu-latest
    defaults:
      run:
        working-directory: MdToHtml

    steps:
      - uses: actions/checkout@v4

      - uses: actions/setup-node@v4
        with:
          node-version: '18'
          cache: 'npm'
          cache-dependency-path: MdToHtml/package-lock.json

      - name: Install dependencies
        run: npm ci

      - name: TypeScript Type Check
        run: npx tsc --noEmit
        id: typecheck

      - name: ESLint
        run: npm run lint -- --max-warnings 0
        id: lint

      - name: Unit Tests with Coverage
        run: npm run test -- --coverage --ci
        id: unittest

      - name: Upload Coverage Report
        if: always()
        uses: actions/upload-artifact@v4
        with:
          name: coverage-report
          path: MdToHtml/coverage/

      - name: PR Comment - Test Summary
        if: always()
        uses: actions/github-script@v7
        with:
          script: |
            const { execSync } = require('child_process');
            const summary = execSync('npx jest --json --outputFile=jest-results.json 2>/dev/null || true');
            // 解析结果并评论到 PR
```

#### Step 3: 配置 Jest 输出 JSON 报告

在 `MdToHtml/jest.config.js` 中添加：

```javascript
module.exports = {
  // ... 已有配置
  reporters: [
    'default',
    ['jest-junit', { outputDirectory: 'test-results' }]
  ],
  coverageThreshold: {
    global: {
      branches: 70,
      functions: 85,
      lines: 80,
      statements: 80,
    }
  },
};
```

#### Step 4: 安装依赖

```bash
npm install --save-dev jest-junit
```

### 3.3 验收标准

- [ ] PR 创建后自动触发流水线
- [ ] TypeScript 编译错误 → ❌ 阻止合并
- [ ] ESLint 警告 > 0 → ❌ 阻止合并
- [ ] 测试覆盖率低于阈值 → ⚠️ 警告
- [ ] 测试失败 → ❌ 阻止合并
- [ ] PR 页面显示检查状态（✅ / ❌）

```yaml
  push:
    branches: [main]
    paths-ignore:
      - 'docs/**'
      - '**.md'

jobs:
  build:
    name: Build & Test
    runs-on: ubuntu-latest
    defaults:
      run:
        working-directory: MdToHtml

    steps:
      - uses: actions/checkout@v4
      
      - uses: actions/setup-node@v4
        with:
          node-version: '18'
          cache: 'npm'
          cache-dependency-path: MdToHtml/package-lock.json

      - name: Install dependencies
        run: npm ci

      - name: Type Check
        run: npx tsc --noEmit

      - name: Lint
        run: npm run lint -- --max-warnings 0

      - name: Unit Tests
        run: npm run test -- --coverage --ci

      - name: Build
        run: npm run build

      - name: Upload Build Artifact
        uses: actions/upload-artifact@v4
        with:
          name: next-build
          path: MdToHtml/.next/

  e2e:
    name: E2E Tests
    needs: build
    runs-on: ubuntu-latest
    defaults:
      run:
        working-directory: MdToHtml

    steps:
      - uses: actions/checkout@v4
      
      - uses: actions/setup-node@v4
        with:
          node-version: '18'
          cache: 'npm'
          cache-dependency-path: MdToHtml/package-lock.json

      - name: Install dependencies
        run: npm ci

      - name: Install Playwright
        run: npx playwright install --with-deps chromium

      - name: Run E2E tests
        run: npx playwright test

      - name: Upload Playwright Report
        if: always()
        uses: actions/upload-artifact@v4
        with:
          name: playwright-report
          path: MdToHtml/playwright-report/

      - name: Upload Test Screenshots
        if: failure()
        uses: actions/upload-artifact@v4
        with:
          name: e2e-failure-screenshots
          path: MdToHtml/test-results/
```

## 五、阶段三：发布流水线（第 5-6 天）

### 5.1 目标

手动触发版本发布，自动打包 Electron 并上传至 GitHub Release。

### 5.2 实现步骤

#### Step 1: 创建 Release 配置

```yaml
# .github/workflows/release.yml
name: Release Pipeline

on:
  workflow_dispatch:
    inputs:
      version_bump:
        description: '版本升级类型'
        required: true
        default: 'patch'
        type: choice
        options:
          - patch   # 1.0.0 → 1.0.1 (bug fixes)
          - minor   # 1.0.0 → 1.1.0 (new features)
          - major   # 1.0.0 → 2.0.0 (breaking changes)
      release_notes:
        description: '发布说明（可选）'
        required: false
        type: string

jobs:
  release:
    name: Build & Release
    runs-on: windows-latest  # Electron 构建需要 Windows
    defaults:
      run:
        working-directory: MdToHtml

    steps:
      - uses: actions/checkout@v4
        with:
          fetch-depth: 0  # 完整 git 历史用于 changelog

      - uses: actions/setup-node@v4
        with:
          node-version: '18'
          cache: 'npm'
          cache-dependency-path: MdToHtml/package-lock.json

      - name: Install dependencies
        run: npm ci

      - name: Run all checks
        run: |
          npx tsc --noEmit
          npm run lint -- --max-warnings 0
          npm run test -- --coverage --ci

      - name: Bump version
        run: |
          git config user.name "github-actions[bot]"
          git config user.email "github-actions[bot]@users.noreply.github.com"
          npm version ${{ github.event.inputs.version_bump }} -m "chore: bump version to %s"

      - name: Build Next.js
        run: npm run build

      - name: Build Electron
        run: npm run electron:build
        env:
          GH_TOKEN: ${{ secrets.GITHUB_TOKEN }}

      - name: Generate Release Notes
        id: release_notes
        uses: actions/github-script@v7
        with:
          script: |
            const notes = `${{ github.event.inputs.release_notes || '' }}`;
            const changelog = execSync('git log --oneline --no-decorate v$(node -p "require(\"./package.json\").version")..HEAD').toString();
            return notes ? `${notes}\n\n## Changelog\n${changelog}` : `## Changelog\n${changelog}`;

      - name: Create GitHub Release
        uses: softprops/action-gh-release@v1
        with:
          tag_name: v${{ needs.version.outputs.version }}
          name: Release v${{ needs.version.outputs.version }}
          body: ${{ steps.release_notes.outputs.result }}
          files: |
            MdToHtml/dist/*.exe
            MdToHtml/dist/*.zip
            MdToHtml/dist/*.dmg
          draft: false
          prerelease: false
```
