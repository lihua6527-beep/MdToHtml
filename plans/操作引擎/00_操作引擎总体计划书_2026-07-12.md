# Plan 00: 操作引擎总体计划书

> **计划日期**：2026-07-12（更新于 2026-07-12，第二次修订）
> **计划目标**：建立编辑器内统一的"操作类型系统（Operation Engine）"，将所有可被用户感知的变更抽象为标准化操作，形成"操作生产者 → 操作引擎 → 操作消费者"的完整链路。
> **核心原则**：**先定义规范，再实现功能**。

---

## 一、为什么需要操作引擎？

### 1.1 当前痛点

```
编辑器内存在多种"变更来源"，各自为政：

┌─────────────┐  ┌─────────────┐  ┌─────────────┐
│ 手动编辑     │  │ AI 辅助编辑  │  │ 未来新功能  │
│ (键盘输入)   │  │ (润色/扩充)  │  │ (拖拽/批注) │
│ 记录方式：   │  │ 记录方式：   │  │ 记录方式：   │
│ string[]    │  │ ❌ 无记录    │  │ ❌ 未定义    │
│ (快照，粗粒度)│  │             │  │             │
└──────┬──────┘  └──────┬──────┘  └──────┬──────┘
       │                │                │
       └────────────────┴────────────────┘
                        ▼
                 各功能互不感知
                 AI 操作不可撤销
                 扩展需重复劳动
```

### 1.2 操作引擎的定位

```
操作引擎 = 编辑器内的"指令总线"

         ┌──────────────────────────────────────────────────┐
         │                 操作引擎                          │
         │  ┌────────────────────────────────────────────┐  │
         │  │            Operation Type System            │  │
         │  │  (操作类型枚举 / 数据结构 / 序列化规范)      │  │
         │  └────────────────────────────────────────────┘  │
         │                       │                          │
         │  ┌────────────────────────────────────────────┐  │
         │  │           撤销/重做引擎 (UndoRedoEngine)     │  │
         │  │  (操作序列管理 / 逆操作生成 / 持久化)        │  │
         │  └────────────────────────────────────────────┘  │
         └──────────────────────────────────────────────────┘
                      ↕                    ↕
          ┌─────────────────┐   ┌──────────────────────┐
          │ 操作生产者        │   │ 操作消费者            │
          │ · 手动编辑钩子    │   │ · 撤销/重做 (Ctrl+Z) │
          │ · AI 辅助操作    │   │ · 手动暂存点回退     │
          │ · 未来扩展       │   │ · 持久化恢复         │
          └─────────────────┘   └──────────────────────┘
```

## 三、操作引擎核心设计

### 3.1 操作的生命周期

```
┌──────────┐    ┌──────────┐    ┌──────────┐    ┌──────────┐
│  产生    │ →  │  校验    │ →  │  执行    │ →  │  记录    │
│ (生产者)  │    │ (Operation│    │ (应用到   │    │ (推入     │
│          │    │  是否合法) │    │  编辑器)  │    │  undoStack)│
└──────────┘    └──────────┘    └──────────┘    └──────────┘
                                                      │
                                                      ▼
                                                ┌──────────┐
                                                │  持久化   │
                                                │ (local    │
                                                │  Storage) │
                                                └──────────┘
```

### 3.2 四大核心模块（精简）

| 模块 | 职责 | 关键文件 | 对应计划 |
|------|------|---------|---------|
| **类型系统** | 定义 OperationType、Operation 接口、序列化/反序列化、invert() | `src/types/operation.ts` | **01** |
| **撤销引擎** | 管理 undo/redo 双栈、逆操作生成、持久化、防抖 | `src/hooks/useHistory.ts`（重构） | **02+03** |
| **暂存点** | 用户打点保存快照，可跳转到任意暂存点 | `src/hooks/useCheckpoint.ts`（新增） | **06** |
| **AI 上下文** | AI 操作的最佳上下文传入策略和成本控制 | `services/ai/ContextBuilder.ts`（新增） | **04+05** |

### 3.3 操作生产者清单（当前 + 未来）

| 生产者 | 接入方式 | 产生操作类型 | 优先级 | 对应计划 |
|--------|---------|-------------|--------|---------|
| CodeMirror 编辑器 onChange | 监听变更事件 → 生成 INSERT/DELETE/REPLACE | `INSERT_TEXT`, `DELETE_TEXT`, `REPLACE_TEXT` | P0 | **02** |
| 卡片属性面板 | 属性修改 → 生成 CARD_STYLE_CHANGE | `CARD_STYLE_CHANGE` | P1 | **07** |
| AI 内联工具栏 | 用户确认 AI 建议 → 生成 AI_* 操作 | `AI_POLISH`, `AI_EXPAND`, `AI_TO_CARD`, `AI_SUMMARIZE` | P0 | **05** |
| 用户暂存 | 打点 → 创建 CHECKPOINT 操作 | `CHECKPOINT` | P0 | **06** |
| 拖拽排序（未来） | 卡片拖动结束 → 生成 CARD_MOVE | `CARD_MOVE` | P2 | **07** |

## 七、附录：术语表

| 术语 | 定义 |
|------|------|
| **操作（Operation）** | 编辑器内一个可被记录的变更，包含类型、位置、载荷、元信息 |
| **操作类型系统** | 定义所有允许的操作及其数据结构的规范 |
| **撤销引擎** | 管理 undo/redo 双栈，支持操作回逆的核心模块 |
| **操作生产者** | 产生操作的对象（手动编辑、AI、用户打点等） |
| **操作消费者** | 消费操作的对象（撤销引擎、暂存点跳转等） |
| **逆操作（Inverse Operation）** | 撤销时执行的反向操作，将编辑器状态恢复到操作前 |
| **暂存点（Checkpoint）** | 用户主动标记的版本快照，作为阶段回退锚点 |
| **防抖合并** | 将短时间内的连续操作合并为一条历史记录 |
| **持久化** | 将操作序列保存到 localStorage，支持页面刷新后恢复 |
