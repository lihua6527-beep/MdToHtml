> **计划日期**：2026-07-12
> **计划目标**：定义操作引擎的核心"语法"——操作类型枚举、Operation 接口、序列化/反序列化规范、逆操作生成算法。这是操作引擎的基座模块，所有其他计划依赖于此。
> **前置依赖**：无（这是操作引擎的基石）
> **对应总体计划**：Phase 1、模块"类型系统"

## 一、设计背景

整合分析报告指出：**没有统一操作规范**是当前 03（撤销系统）和 06（AI 内联编辑）两个计划最大的设计缺口。03 用纯文本快照 `string[]`，06 根本没有操作记录概念，两者无法互通。

```
没有统一操作规范
  → 03 只能整篇快照回退（粒度不够细）
  → 06 的操作无法被 03 记录
  → 用户用 AI 润色后，Ctrl+Z 无法撤销 AI 变更（UX 灾难）
  → 未来新增任何操作类型，都需要各自实现撤销逻辑（重复劳动）
```

**解决途径**：定义一个通用的 **Operation 类型系统**，作为整个操作引擎的"指令集架构"。

## 二、操作类型枚举

### 2.1 三大分类

```typescript
// src/types/operation.ts

// ====== 核心操作类型枚举 ======
enum OperationType {
  // --- ① 文本编辑（手动键盘输入） ---
  INSERT_TEXT,       // 插入文本
  DELETE_TEXT,       // 删除文本
  REPLACE_TEXT,      // 替换文本（选中后打字覆盖）

  // --- ② 卡片操作 ---
  CARD_ADD,          // 新增卡片
  CARD_DELETE,       // 删除卡片
  CARD_MOVE,         // 移动卡片位置
  CARD_STYLE_CHANGE, // 修改卡片样式（highlight/normal）

  // --- ③ AI 辅助操作（由 AI 内联编辑引入） ---
  AI_POLISH,         // AI 润色
  AI_EXPAND,         // AI 扩充
  AI_TO_CARD,        // AI 转卡片
  AI_SUMMARIZE,      // AI 总结

  // --- ④ 元操作 ---
  CHECKPOINT,        // 用户手动暂存点（记录当前完整文档快照）
  BATCH,             // 组合多个操作为原子操作（用于防抖合并）
  MARKER,            // 标记点（用于快照，不产生实际变更）
}
```

### 2.2 枚举值与操作分类说明

| 分类 | 枚举值 | 生产者 | 是否可逆 |
|------|--------|--------|---------|
| 文本编辑 | INSERT_TEXT / DELETE_TEXT / REPLACE_TEXT | 键盘输入、粘贴 | ✅ 是 |
| 卡片操作 | CARD_ADD / CARD_DELETE / CARD_MOVE / CARD_STYLE_CHANGE | 卡片属性面板、拖拽 | ✅ 是 |
| AI 辅助 | AI_POLISH / AI_EXPAND / AI_TO_CARD / AI_SUMMARIZE | AI 内联工具栏 | ✅ 是（通过 invert） |
| 元操作 | CHECKPOINT | 用户手动打点 | ⚠️ 不可逆（记录快照，非变更操作） |
| 元操作 | BATCH / MARKER | 防抖合并器、系统 | ⚠️ 条件可逆 |

## 三、Operation 接口定义

### 3.1 通用结构

```typescript
interface Operation {
  // ── 元信息 ──
  id: string;                     // 唯一标识，使用 nanoid 或递增序列
  type: OperationType;            // 操作类型
  timestamp: number;              // 发生时间（Date.now()）
  batchId?: string;               // 同一批次 ID（用于防抖合并识别）

  // ── 位置信息（文档中的范围） ──
  position: {
    start: number;                // 起始字符偏移（字符级，从 0 开始）
    end: number;                  // 结束字符偏移
    // 可选的行列表示（对人友好，用于 UI 展示）
    from?: { line: number; ch: number };
    to?: { line: number; ch: number };
  };

  // ── 操作数据 ──
  payload: {
    before: string;               // 操作前的内容（用于回退生成逆操作）
    after: string;                // 操作后的内容
    // AI 特有的额外信息（仅 AI 操作需要）
    aiContext?: {
      model: string;              // AI 模型名称
      promptType: string;         // Prompt 类型（polish/expand/to-card/summarize）
      tokensConsumed: number;     // 消耗 Token 数
    };
  };

  // ── 展示信息（用于 UI 展示历史记录） ──
  display: {
    icon: string;                 // 图标 emoji（如 ✏️、🤖、📦）
    label: string;                // 简短描述，如"润色了第 3 段"
    detail?: string;              // 详细描述（可选）
  };
}
```

### 3.2 位置编码决策

操作的位置采用 **字符偏移为主、行列号为辅** 的混合策略：

| 方案 | 优点 | 缺点 |
|------|------|------|
| **字符偏移**（start/end） | 计算简单，支持精确回退 | 如果前面内容变更，偏移会漂移 |
| **行列号**（line/ch） | 对人友好，直观 | 编辑器内部表示不一致 |
| **混合存储**（推荐） | 兼顾两者 | 存储略大，但可接受 |

> **核心保证**：回退时通过**操作序列重放**来替代"跳转到固定偏移"的做法，以消除偏移漂移问题。

## 四、逆操作生成

### 4.1 invert() 算法

每个 Operation 都应能生成一个逆操作（Inverse Operation），用于撤销。

```typescript
class OperationFactory {
  // 生成逆操作
  static invert(op: Operation): Operation {
    // 元操作（BATCH）的逆操作是各子操作的逆操作组合
    if (op.type === OperationType.BATCH) {
      // BATCH 的 payload 隐含子操作列表，需递归 invert
      throw new Error('BATCH invert must be handled by UndoRedoEngine');
    }

    // MARKER 的逆操作是自己（无实际变更）
    if (op.type === OperationType.MARKER) {
      return { ...op };
    }

    // 通用逆操作：before 和 after 互换
    return {
      ...op,
      payload: {
        before: op.payload.after,
        after: op.payload.before,
        // AI context 保持（仅用于展示，不影响回退逻辑）
        aiContext: op.payload.aiContext,
      },
      // 更新展示信息
      display: {
        icon: '↩️',
        label: `撤销: ${op.display.label}`,
        detail: op.display.detail,
      },
    };
  }
}
```

### 4.2 各类型操作的逆操作示例

| 原操作 | 逆操作 |
|--------|--------|
| `{ type: INSERT_TEXT, payload: { before: "", after: "Hello" } }` | `{ type: INSERT_TEXT, payload: { before: "Hello", after: "" } }`（效果相当于 DELETE） |
| `{ type: DELETE_TEXT, payload: { before: "World", after: "" } }` | `{ type: DELETE_TEXT, payload: { before: "", after: "World" } }`（效果相当于 INSERT） |
| `{ type: REPLACE_TEXT, payload: { before: "old", after: "new" } }` | `{ type: REPLACE_TEXT, payload: { before: "new", after: "old" } }` |
| `{ type: AI_POLISH, payload: { before: "原文", after: "润色后" } }` | `{ type: AI_POLISH, payload: { before: "润色后", after: "原文" } }` |
| `{ type: CARD_ADD, payload: { before: "", after: "### Card {...}" } }` | `{ type: CARD_DELETE, payload: { before: "### Card {...}", after: "" } }` |
| `{ type: CARD_DELETE, ... }` | → CARD_ADD（恢复被删除的卡片内容） |

> **注意**：某些操作的类型可能在逆操作时发生变化（如 CARD_DELETE 的逆操作是 CARD_ADD），这需要在 `invert()` 中根据 `type` 做特化处理。

## 五、序列化 / 反序列化

### 5.1 序列化（Operation → JSON string）

```typescript
class OperationSerializer {
  static serialize(op: Operation): string {
    return JSON.stringify(op);
  }

  static serializeArray(ops: Operation[]): string {
    return JSON.stringify(ops);
  }
}
```

### 5.2 反序列化（JSON string → Operation）

```typescript
class OperationDeserializer {
  static deserialize(json: string): Operation {
    const parsed = JSON.parse(json);
    // 进行类型验证
    if (!parsed.id || !parsed.type || !parsed.position || !parsed.payload) {
      throw new Error('Invalid Operation format');
    }
    return parsed as Operation;
  }

  static deserializeArray(json: string): Operation[] {
    const parsed = JSON.parse(json);
    if (!Array.isArray(parsed)) {
      throw new Error('Expected an array of Operations');
    }
    return parsed.map(op => OperationDeserializer.deserialize(op));
  }
}
```

## 六、辅助工具函数

### 6.1 操作工厂

```typescript
class OperationBuilder {
  private static counter = 0;

  static nextId(): string {
    return `op-${Date.now()}-${++this.counter}`;
  }

  static textInsert(
    position: number,
    text: string,
    lineInfo?: { from: { line: number; ch: number }; to: { line: number; ch: number } }
  ): Operation {
    return {
      id: this.nextId(),
      type: OperationType.INSERT_TEXT,
      timestamp: Date.now(),
      position: {
        start: position,
        end: position,
        ...(lineInfo ? { from: lineInfo.from, to: lineInfo.to } : {}),
      },
      payload: { before: '', after: text },
      display: { icon: '✏️', label: '插入文本', detail: `"${text.slice(0, 30)}..."` },
    };
  }

  static aiOperation(
    subType: OperationType.AI_POLISH | OperationType.AI_EXPAND | OperationType.AI_TO_CARD | OperationType.AI_SUMMARIZE,
    start: number,
    end: number,
    before: string,
    after: string,
    aiContext: { model: string; promptType: string; tokensConsumed: number }
  ): Operation {
    const labelMap: Record<string, string> = {
      [OperationType.AI_POLISH]: '润色',
      [OperationType.AI_EXPAND]: '扩充',
      [OperationType.AI_TO_CARD]: '转卡片',
      [OperationType.AI_SUMMARIZE]: '总结',
    };
    return {
      id: this.nextId(),
      type: subType,
      timestamp: Date.now(),
      position: { start, end },
      payload: { before, after, aiContext },
      display: {
        icon: '🤖',
        label: `AI ${labelMap[subType]}`,
        detail: `消耗 ${aiContext.tokensConsumed} tokens`,
      },
    };
  }
}
```

### 6.2 操作验证

```typescript
function validateOperation(op: Operation): { valid: boolean; errors: string[] } {
  const errors: string[] = [];

  if (!op.id) errors.push('缺少 id');
  if (op.type === undefined || op.type === null) errors.push('缺少 type');
  if (op.position?.start === undefined) errors.push('缺少 position.start');
  if (op.position?.end === undefined) errors.push('缺少 position.end');
  if (op.payload?.before === undefined) errors.push('缺少 payload.before');
  if (op.payload?.after === undefined) errors.push('缺少 payload.after');

  // AI 操作必须携带 aiContext
  if ([OperationType.AI_POLISH, OperationType.AI_EXPAND,
       OperationType.AI_TO_CARD, OperationType.AI_SUMMARIZE].includes(op.type)) {
    if (!op.payload.aiContext) errors.push('AI 操作缺少 aiContext');
  }

  return { valid: errors.length === 0, errors };
}
```
