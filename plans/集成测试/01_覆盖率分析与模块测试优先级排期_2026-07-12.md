## 五、操作引擎的测试计划（关键）

操作引擎是你目前正在做的重构，**测试应该在实现过程中同步完成**。

### 测试结构

```

└── operation-engine.test.ts    # 15 个测试用例

### 单元测试用例（15 个）

|---|---------|--------|----------------|

| 2 | undo 回退到上一步 | P0 | ❌ 不改 |

## 六、各种测试写不写的快速判断指南

### 问自己这几个问题：

```
Q1: 这个模块是纯函数吗？（输入 → 输出，无副作用）
  → 是 → 值得写单元测试 ✅
  → 否 → 去 Q2

Q2: 这个模块是 React 组件吗？
  → 是 → 不值得写单元测试（用 E2E 替代）❌
  → 否 → 去 Q3

Q3: 这个模块会被频繁重构吗？
  → 是 → 只写 E2E（保护功能正确）✅
  → 否 → 写单元测试 ✅

Q4: 这个测试需要大量 mock 吗？
  → 是 → 不如不写（mock 在重构后 90% 失效）❌
  → 否 → 可以写 ✅
```

### 快速决策表

```
场景                         写不写    写什么
─────────────────────────────────────────────
CHD 解析器 (纯函数)           ✅      单元测试
缓存管理器 (纯函数)           ✅      单元测试
操作引擎 (纯函数+业务)        ✅      单元测试 + E2E
渲染引擎 (React 组件)         ❌      只 E2E
编辑器 (React 组件)           ❌      只 E2E
AI 服务 (有网络调用)          ⚠️      只测核心逻辑
Hooks (useXxx)               ❌      不推荐
主题切换 (CSS 变量)           ❌      不值得
```
