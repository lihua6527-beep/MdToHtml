## 1. 概述

本文档旨在总结基于 CHD (Card-based Hierarchical Document) 协议的前端渲染常见错误。这些错误通常源于 Markdown 输入不符合协议的三级刚性结构约束。本文档可作为 AI 助手在分析用户反馈的“内容未显示”或“样式错乱”问题时的诊断依据。

## 2. 常见错误类型与特征

### 2.1 孤儿文本 (Orphan Text)

**现象**：
*   用户反馈：“这一段文字没有显示出来。”
*   页面表现：某个 `## Section` 标题下方空白，或者缺少部分段落。

**根因**：
*   违反了 CHD 协议的 **L1 -> L2** 约束。
*   正文文本直接书写在 `## Section` 标题下方，而没有被包裹在 `### Card` 标题内。
*   渲染器解析逻辑：渲染器通常会忽略不属于任何 Card 的 L1 层级文本，只渲染 Card 列表。

**诊断示例**：
```markdown
<!-- 错误写法 -->
## 核心定位
本文系统综述了深度学习技术在推荐系统中的应用进展... （这段文字会丢失）

### 详细内容
...
```

**修复建议**：
*   将孤儿文本包裹在新的 Card 中，通常使用 `summary` 或 `normal` 样式。

```markdown
<!-- 正确写法 -->
## 核心定位
### 核心概览 {card-style="summary"}
本文系统综述了深度学习技术在推荐系统中的应用进展...
```

### 2.2 非标样式值 (Unsupported Card Style)

**现象**：
*   用户反馈：“我设置了样式，但卡片看起来还是默认的样子” 或者 “布局错乱”。
*   页面表现：卡片样式回退到普通白底卡片，或者特定的 CSS 类未生效。

**根因**：
*   `card-style` 属性使用了协议未定义的值（如 `orange` 在非 Hero 区使用，或 `info`, `custom` 等）。
*   组件代码中 `styleVariants` 字典无法匹配该 key，导致回退到默认样式。

**诊断示例**：
```markdown
<!-- 错误写法 -->
### 关键优势 {card-style="orange"} 
(若 orange 仅设计用于文档头部 Hero，且在此处未定义具体样式行为)
```

**修复建议**：
*   检查 `card-style` 是否为合法值集合：`normal`, `highlight`, `stat`, `quote`, `warning`, `code`, `summary`。
*   将非法值替换为语义最接近的合法值。

### 2.3 复杂内容置入 Stat 卡片 (Complex Content in Stat Card)

**现象**：
*   用户反馈：“表格样式乱了”、“代码块没有背景色”、“内容被挤压”。
*   页面表现：表格无边框、无滚动条、文字居中堆叠；代码块丢失格式。

**根因**：
*   `card-style="stat"` 旨在展示大号数字指标，其 CSS 通常包含 `text-center`, `justify-center`, `items-center` 等 Flex/Grid 属性。
*   这些属性会破坏 Table 或 CodeBlock 的默认块级布局。

**诊断示例**：
```markdown
<!-- 错误写法 -->
### 数据报表 {card-style="stat"}
| ID | Name | Value |
| -- | ---- | ----- |
| 1  | A    | 100   |
```

**修复建议**：
*   **严禁**在 `stat` 卡片中放置表格、代码块、长列表。
*   将样式修改为 `normal` 或 `highlight`。
*   若表格较宽，建议添加 `col-span=2`。

### 2.4 HTML 实体与特殊字符

**现象**：
*   页面显示源码字符（如 `&gt;`）而不是符号（`>`）。

**根因**：
*   输入端过度转义。ReactMarkdown 等渲染器通常会自动处理转义，输入端应保持原始 Markdown 字符。

## 3. AI 诊断流程建议

当用户反馈显示问题时，AI 应按照以下步骤进行自检：

1.  **读取源码**：使用 `Read` 工具读取对应的 Markdown 文件。
2.  **结构扫描**：
    *   检查是否存在 `##` 下方直接跟随正文的情况（孤儿文本）。
    *   检查 `###` 卡片的 `card-style` 属性值是否在允许列表中。
    *   检查 `card-style="stat"` 的卡片内容是否包含 `|---|` (表格) 或 ` ``` ` (代码)。
3.  **验证修复**：
    *   如果发现上述问题，直接修改 Markdown 文件进行结构调整。
    *   不要尝试通过修改 CSS 来适配错误的结构（如不要试图让 Stat 卡片支持表格），应优先修正结构。
