> **版本**: v1.0  
> **日期**: 2026-02-07  
> **状态**: 规划中  
> **目标**: 定义“一键生成”背后的模型需求、数据标准及对接接口，指导小模型开发与数据闭环建设。

## 1. 核心架构：双环飞轮与三阶段流水线

本系统旨在通过**轻量级端侧模型**实现“几秒魔法秀”。整个架构基于两个核心数据飞轮，驱动三个阶段的用户体验。

### 1.1 双环飞轮 (Two-Loop Flywheel)

1.  **协议优化飞轮 (Protocol Loop)**:
    *   **输入**: 原始/杂乱 Markdown (Raw)
    *   **输出**: 符合 CHD 协议的完美 Markdown (Perfect CHD)
    *   **模型**: 评估模型 (Scorer) + 优化模型 (Optimizer)
    *   **价值**: 确保渲染引擎获得高质量原料，解决“Garbage In”问题。

2.  **交互经验飞轮 (Interaction Loop)**:
    *   **输入**: 完美 Markdown (Perfect CHD)
    *   **输出**: 用户精调后的 Markdown (Tuned Output) + 操作日志 (Operations)
    *   **模型**: 交互经验模型 (Interaction Model)
    *   **价值**: 学习用户的审美与排版偏好，提供智能布局建议。

### 1.2 三阶段流水线 (3-Stage Pipeline)

*   **Stage 1: 评估与决策** (Raw -> Scorer -> Score/Issues)
*   **Stage 2: 协同优化** (Raw + Issues -> Optimizer -> Perfect CHD)
*   **Stage 3: 渲染与交互** (Perfect CHD + Interaction Model -> Tuned Output -> Render)

## 2. 模型需求规格说明书 (Model Specifications)

鉴于“纯本地”与“几秒完成”的要求，所有模型需针对 Web/Local 环境进行极致轻量化设计 (ONNX/TFLite)，单次推理控制在 **200ms** 以内。

### 2.1 模型 A: 结构评估打分模型 (The Scorer)
*   **定位**: 守门员
*   **任务**: 输入 Markdown 文本，输出多维度评分及具体问题列表。
*   **架构建议**: DistilBERT / TinyBERT (Sequence Classification + Token Classification)
*   **输入接口**:
    ```json
    {
      "content": "Markdown string..."
    }
    ```
*   **输出接口**:
    ```json
    {
      "total_score": 85,
      "dimensions": {
        "structure": 70, // 结构完整性 (Section/Card 层级)
        "format": 90,    // 语法规范性
        "atomicity": 80  // 内容原子性 (段落长度)
      },
      "issues": [
        {
          "type": "structure_missing_section",
          "line": 15,
          "desc": "缺少必要的二级标题划分"
        },
        {
          "type": "content_too_long",
          "line": 42,
          "desc": "段落过长（>800字），建议拆分"
        }
      ]
    }
    ```

### 2.2 模型 B: 智能优化模型 (The Optimizer)
*   **定位**: 修理工
*   **任务**: 基于问题列表，将 Raw Markdown 转换为 Perfect CHD Markdown。
*   **架构建议**: T5-small / FLAN-T5-small (Seq2Seq)
*   **输入接口**:
    ```json
    {
      "content": "Raw Markdown string...",
      "instruction": "Fix structure and split long paragraphs."
    }
    ```
*   **输出接口**:
    ```json
    {
      "optimized_content": "CHD Compliant Markdown string...",
      "changes": [ // 可选，用于前端 Diff 展示
        {"op": "split", "line": 42, "original": "...", "new": ["...", "..."]}
      ]
    }
    ```

### 2.3 模型 C: 交互经验模型 (The Assistant)
*   **定位**: 设计师助手
*   **任务**: 基于当前内容结构，预测用户可能的布局调整或样式偏好。
*   **架构建议**: 简单的统计模型 (N-gram) 或 轻量级 Transformer (Encoder-only)
*   **输入接口**:
    ```json
    {
      "current_block": {
        "type": "code",
        "lang": "python",
        "length": 50
      },
      "context": {
        "prev_block_type": "heading",
        "document_theme": "tech-blog"
      }
    }
    ```
*   **输出接口**:
    ```json
    {
      "suggestions": [
        {
          "type": "change_layout",
          "value": "split-view", // 建议代码块使用左右分栏
          "confidence": 0.85
        },
        {
          "type": "add_class",
          "value": "highlight-line",
          "confidence": 0.70
        }
      ]
    }
    ```

## 3. 现有系统数据能力分析 (Gap Analysis)

### 3.1 现状
*   **数据录制**: 已实现 `/api/save-session`，可录制 `input.md` (加载时状态), `output.md` (保存时状态), `operations.json` (操作流)。
*   **覆盖范围**: 目前主要覆盖 **交互经验飞轮 (Loop 2)**。即用户在编辑器内的精调行为。
*   **缺失环节**: **协议优化飞轮 (Loop 1)** 的数据尚未闭环。目前系统假设导入的已经是 CHD 格式，缺乏“Raw -> Perfect”的对照数据采集入口。

### 3.2 改进计划
为了支持模型 A 和 B 的训练，我们需要在系统中增加 **"导入/清洗模式"**：
1.  **新增入口**: 允许用户粘贴/上传 "Raw Markdown"。
2.  **人工/规则清洗**: 提供辅助工具帮助用户将其整理为 "Perfect CHD"。
3.  **数据归档**: 将此过程保存为 `{ raw: "...", perfect: "..." }` 数据对。

## 5. 附录：训练数据标准格式 (JSONL)

为方便训练，所有 Session 数据最终应导出为如下 JSONL 格式：

**Dataset A (Optimization):**
```json
{"prompt": "Optimize specific markdown structure: [RAW_CONTENT]", "completion": "[PERFECT_CHD_CONTENT]"}
```

**Dataset B (Interaction):**
```json
{"prompt": "Given code block after heading, suggest layout:", "context": "...", "completion": "split-view"}
```
