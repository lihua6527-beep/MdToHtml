# 模型版本管理与更新机制

## 1. 版本命名规范 (Semantic Versioning)
采用 `v{Major}.{Minor}.{Patch}` 格式：
*   **Major (主版本)**: 模型架构发生重大变更（如 BiLSTM -> Transformer）。
*   **Minor (次版本)**: 重新训练或引入新数据集，接口兼容。
*   **Patch (修订号)**: 仅权重微调或元数据更新。

示例: `micro-structure-v1.2.0.onnx`

## 2. 目录结构
```
models/
├── archive/              # 历史版本归档
│   ├── v1.0.0/
│   └── v1.1.0/
├── current/              # 线上运行版本 (Symlink)
│   ├── tokenizer.json
│   ├── structure.onnx
│   └── config.json
└── staging/              # 待发布版本 (用于 A/B Test)
```

## 3. 更新流程 (CI/CD Integrated)
1.  **Training**: 运行 `src/ml/train/train.py` 生成新权重。
2.  **Evaluation**: 自动运行 `tests/test_model_performance.py`，只有指标（Acc > 90%, Latency < 50ms）达标才允许发布。
3.  **Versioning**: 自动打标并归档到 `models/archive/`。
4.  **Deployment**: 更新 `models/current` 软链接，并触发服务热重载。

## 4. 回滚机制 (Rollback)
若线上监控发现异常（如 P99 延迟突增或错误率升高）：
1.  立即将 `models/current` 指向上一稳定版本 (Last Known Good)。
2.  记录事故报告并冻结当前版本。

## 5. 元数据管理
每个模型文件必须配套 `model_meta.json`：
```json
{
  "model_id": "micro-structure-v1.2.0",
  "created_at": "2026-02-04T12:00:00Z",
  "dataset_hash": "a1b2c3d4...",
  "metrics": {
    "accuracy": 0.98,
    "latency_ms": 2.5
  },
  "compatible_tokenizer": "v1.0"
}
```
